# 运行中断恢复与证据校准实施计划

## Context

P1 仍未通过。feature-817 的真实 AI runtime 交互尚未闭环，feature-828 项目包虽有自动化与历史真机证据，但仍需按 D-035 逐项映射；现有正常会话回放也不能证明异常中断恢复。

本 Change 的目标是在不新建 Feature、不进入 P2 的前提下：先校准 817/828 证据，再为 808/817 落地可持久化、可对账、可追溯的 Agent 运行中断恢复。重开应用后保留消息、OptionCard、Gate 与已落盘产物；运行中执行显示“已中断”，只有用户明确确认才创建带血缘的新运行。

## 范围与归属

- **808**：运行账本、生命周期挂钩、重启对账、历史与运行关联、重试血缘。
- **817**：真实 runtime 证据补验，以及中断态和人工重试的对话展示；不新增视觉需求。
- **828**：D-035 证据矩阵、定向补验，并把新运行档排除出静态项目包。
- **830**：仅承接本次可复跑的定向 Electron 故障注入驱动；复用 `scripts/acceptance-env.cjs` 的隔离原则。
- 不新建 Feature，不改 P1/P2 阶段状态，不建设统一媒体任务中心，不自动重新提交，不接续原 Token 流。

## 编码前契约呈报

### 运行记录

每项目新增 `.agent-runs.json`，主进程为唯一写者：

```ts
type AgentRunStatus =
  | 'running'
  | 'stopping'
  | 'completed'
  | 'failed'
  | 'stopped'
  | 'interrupted'

interface AgentRunRecord {
  id: string                    // 严格等于 opencode 真实用户 messageID
  sessionId: string
  request: RuntimePromptRequest // 仅文本、agent、模型和资产引用；不含密钥
  status: AgentRunStatus
  createdAt: string
  updatedAt: string
  endedAt?: string
  error?: string
  retryOfMessageId?: string
}
```

- 运行 ID 直接复用发送给 SDK 的用户 `messageID`，不再生成另一套 runId。
- 正文、推理、工具轨迹仍由 opencode 历史保存；账本只在状态迁移时写入，不逐 delta 写盘。
- 复用 `electron/fs/atomic.ts` 与 `electron/fs/write-queue.ts`，损坏档不得静默重置。

### 新增 IPC

```ts
window.api.runtime.runs(): Promise<AgentRunRecord[]>
window.api.runtime.retryRun(messageId: string): Promise<{ accepted: true; messageId: string }>
```

对应通道为 `runtime:runs`、`runtime:run:retry`。

- 查询当前项目运行记录；首次读取某项目时完成一次重启对账，之后的项目切换不得误中断本进程活跃运行。
- 重试只接受当前项目、当前绑定会话中的 `interrupted` 记录；同会话有活跃运行或项目存在 pending Gate 时拒绝。
- 重试由主进程读取原 request，重新执行资产解析和完整发送链，生成新用户 messageID，并写入 `retryOfMessageId=旧 id`；旧记录保持 interrupted。
- 沿用现有错误码，不扩枚举：非法记录/状态使用 `INVALID_ARGUMENT`，并发活跃运行使用带明确消息的 `INTERNAL`。
- 查询账本失败不得阻断消息历史回放；在账本修复前禁止新运行，避免覆盖损坏记录。

## 实施步骤

### 1. 先修正规格与证据基线

1. 在 808/817 增补上述状态机、恢复边界、IPC 和验收项；在 828 增补运行档排除及 D-035 映射；若新增定向驱动，同步 830 契约。
2. 运行 817 既有真实 AC 对应的定向测试并做真实 Electron 补验：真实输入、OptionCard、任务详情、Gate、协议元数据及主题回归。现有输入框已区分 Shift+Enter，不虚构键盘缺陷；只有复现出既有 AC 失败才在 817 内修复。
3. 将 828 现有证据逐项映射到 D-035。只补真实缺口：非空多页/多画布、含内容或媒体资产、版本目录、敏感/运行/临时文件全矩阵；不重写已通过的重复导入、只读会话和来源续聊。
4. 新证据写入新的日期化 verification 目录，旧结果保持历史原样；服务或外部条件不可用时记为阻塞，不宣告通过。

### 2. 落地主进程运行账本

1. 新增 `electron/runtime/run-store.ts`，实现加载、原子写、状态迁移、活跃运行查询、首次加载对账和重试血缘。
2. 调整 `electron/runtime/client.ts`：由 main 在发送前生成并注入用户 messageID；保留 `buildPromptBody`、agent/model/tools 白名单及 SDK 调用方式。
3. 在 `electron/main.ts` 收敛公共发送函数：
   - 运行时就绪且项目/会话确定后，先落 `running`，再解析资产和调用 SDK；同步拒绝记 `failed`。
   - 同会话只允许一个非终态运行。
   - 停止先落 `stopping` 再 abort；后续 idle 定稿为 `stopped`。
   - 普通 `session.idle` 将 running 定稿为 `completed`；session/message error 定稿为 `failed`；HTTP accepted 本身不代表成功。
   - 非主动停止的 runtime 进程退出把活跃运行记为 `interrupted`；SIGKILL 由下次首次加载对账兜底。
4. 终态只迁移一次，迟到或乱序事件不得把 completed/failed/stopped/interrupted 改写为其他状态。

### 3. 接线 IPC、回放与人工重试

1. 修改 `electron/preload.ts`、`src/global.d.ts`、`src/lib/runtime-types.ts`、`src/dev-mock-api.ts`，同步两个新通道和 DTO。
2. `StudioApp.tsx` 同时加载消息与运行记录：消息查询失败按既有规则处理；运行查询失败保留消息现场并提示，不伪报恢复成功。
3. 扩展 `history-replay.ts` 的可选运行入参：用户消息按真实 messageID 关联运行，后续 assistant 消息继承该轮关联，直到下一条用户消息；原始历史 DTO 不变。
4. 发送被接受后，用返回的真实 messageID 替换乐观用户气泡 ID，并把当前流式轮次关联到该运行。
5. `ChatComposer.tsx` 仅对 interrupted 轮次的 pending/running 工具做“已中断”展示投影，不改历史数据。若崩溃发生在引擎留下用户消息之前，则显示独立恢复卡并注明“提交结果未知”，不伪造历史气泡。
6. OptionCard 继续由正文恢复，未提交选项不代选；pending Gate 沿用 `recoverPending` 等待人工拍板；Canvas/资产文件继续作为产物事实源，不回滚已落盘产物。
7. 提供“确认并重试”显式操作；pending Gate 存在时禁用。不得在 mount/effect 中自动调用，重试后新旧运行 ID 不同且血缘可查。

### 4. 项目包与验收驱动

1. 在 `electron/project/transfer.ts` 的静态导出排除清单加入 `.agent-runs.json`，确保运行态、重试血缘账本和临时写文件不进入副本；正式会话正文仍按原逻辑导出。
2. 扩展项目包测试夹具，验证非空多页/多画布、版本、实际资产及全部排除项；重复导入仍创建新身份，导入会话保持只读，续聊仍创建带来源的新会话。
3. 在 830 内新增定向 Electron 故障注入驱动，复用 `acceptance-env.cjs`；以隔离 HOME/ASD_USER_DATA 和 `.test-tmp` 落点运行，不接触真实项目。
4. 驱动只使用 Node 内置能力、Electron/CDP 和受控本地 mock 服务制造可延迟的 runtime 响应；受控 mock 用于故障时序，真实 Provider 的 817 验收不得以 mock 冒充。

## 验证

### 自动化

- RunStore：各状态迁移、首次加载对账、重复对账幂等、终态不可倒退、同会话并发拒绝、停止后 idle、进程退出、损坏档保护、重试血缘。
- 回放/组件：真实 messageID 关联、原始工具 DTO 不变、仅 interrupted 投影“已中断”、OptionCard 零自动选择、pending Gate 零自动裁决、重试仅触发一次且新旧 ID 不同。
- 主进程集成：同步拒绝、异步错误、正常 idle、停止、异常退出、无历史孤儿运行、Gate 阻断和资产重新校验。
- 828：新运行档及临时文件排除，非空多页/多画布、版本与资产完整往返，原项目不变。
- 执行定向 Vitest、`npm run typecheck`、完整 `npm test`、`npm run build`；分别保存真实输出，不用历史计数代替。

### 真实 Electron

1. 以真实 opencode/MCP/IPC 和受控延迟响应，在文本/工具运行中异常终止应用，重启后确认：请求数零自动增长、消息与日志保留、遗留工具显示已中断、已落盘产物不变。
2. 分别覆盖未提交 OptionCard、pending Gate、产物已落盘场景；不得自动选择、自动裁决或自动重试。
3. pending Gate 时重试被拒绝；人工处理 Gate 后点击“确认并重试”，验证新用户 messageID、新运行及 `retryOfMessageId`，旧运行仍保留。
4. 用真实配置的 Provider 完成 817 真实输入、OptionCard、任务详情和 Gate 补验；记录脱敏配置与原始结果，失败或不可用则保持开放。
5. 完成 828 定向导入导出恢复测试，核对排除项、副本身份、只读会话和来源续聊。

按实际结果回填 808/817/828/830 的任务清单、设计/契约和变更记录；新增证据索引只指向本次实际产物。Feature 索引仅在包状态确变时更新。即使本 Change 全部通过，也不据此宣称 P1 整体通过或进入 P2。
