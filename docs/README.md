## 事实源职责与冲突裁决（D-024）

事实源按职责分层，不做全仓单线排序：

1. **治理规则**：`AGENTS.md` 的项目明示特化条款与 `governance/AI-SDG-AI工具执行指令.md` 共同约束执行纪律；二者冲突时仅按 `AGENTS.md` 声明的项目层例外处理。
2. **已批准决策**：决策台账记录冲突裁断与架构变更依据。新决策取代旧口径时必须回流相关 A 类文档，不能长期以台账外置例外代替规格。
3. **业务与实施规格**：`短剧Agent平台设计.md` 管全局产品与架构；Feature 契约管本包实施细节与 diff 边界，是包内最高实施契约，但不得越权覆盖项目原则或全局架构，确需变更时先走对应 K 卡口。
4. **类型与 Agent 配置**：`shared/types.ts` 只权威约束共享字段形状（只读，修改触发 K1），不能单独裁定产品业务语义；`resources/opencode/agents/*.md` 约束对应 Agent 的行为、权限与工具声明。
5. **磁盘代码**：`electron/`、`src/` 是实现证据与现状核查依据，不是目标事实源。代码与 Spec 明确矛盾按 L1 修代码；Spec 自身歧义或遗漏按 L2 暂停裁决；现架构不可行按 L3 升级评审。
6. **导航与派生物**：两个 README 只作导航，HTML 只作 A 类文档镜像，`版本记录.md` 只作历史，`设计现状与偏差清单.md` 只登记实现差距；均不得反向覆盖上述事实源。

**D-012 边界**：其「以磁盘实况为终态」仅用于当时对话链路及设计 §5/§7.1 的反向同步，不表示全仓代码可以覆盖规格。

## 维护纪律

- **md 是事实源，html 是镜像**：改 `短剧Agent平台设计.md` 必须同步 `docs/design/短剧Agent平台设计.html`；镜像非独立事实源。
- **版本记录**：按 D-029 / D-030 与治理规则 §7.4 只登记项目级编年事件；历史条目不删改，后续变化另起新条目，不追加终局状态。单 Feature 日常实施回包内，里程碑只留短摘要与链接；主文件为总索引，当年体量过大也可将条目整体迁至同目录年度分卷。
- **决策台账**：按 D-028 / D-030 与治理规则 §7.1 维护“决策本体 + 终局状态”；旧决策本体不得删改，后续口径写入终局状态并回流现行事实源。触及台账时检查链接、Feature 路径、D 编号与必填字段；主文件为总索引，当年体量过大也可将条目整体迁至同目录年度分卷。
- **历史**：已作废内容不另建说明文件；决策审计按台账永久保留，其他历史由版本记录与 git 追溯，均不作为现行实现依据。
- **任务包**：新功能按《AI-SDG-AI工具执行指令》§2 建包于 `docs/features/feature-{三位数字}-{业务名}/`；标准档 5 文件，同时满足四项条件的小改动采用 3 文件精简档，不自创其他文件档。
- **偏差清单**：`docs/设计现状与偏差清单.md` 只登记已核实且未闭环的设计与实现不一致；闭环后删除条目，路线、验收与历史分别由 features/README、任务包和版本记录承载。
