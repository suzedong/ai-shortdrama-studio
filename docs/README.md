## 阅读顺序（按角色）

**新开发者 / 协作者（人）**：

1. [../README.md](../README.md) —— 项目是什么、怎么跑
2. [平台全景图.html](./design/平台全景图.html) —— 一张图建立整体认知
3. [短剧Agent平台设计.md](../短剧Agent平台设计.md) §0（定位 / 原则）→ §2.6（立项模型）→ §5 / §7.1（运行时与数据血缘）→ §11（路线）
4. [原型](./design/短剧Agent平台-原型.html) —— 看界面形态
5. [设计现状与偏差清单.md](./设计现状与偏差清单.md) —— 知道"哪些已落地、哪些是设计愿景"，避免把愿景当事实

**AI 编程工具（Trae / Cursor / Copilot）**：

1. [../AGENTS.md](../AGENTS.md)（先读）→ [governance/AI-SDG-AI工具执行指令.md](./governance/AI-SDG-AI工具执行指令.md)（通读全部条款）
2. 设计事实源：[短剧Agent平台设计.md](../短剧Agent平台设计.md)
3. 契约：`shared/types.ts`（字段契约以它为准）
4. 现状：本文 + [设计现状与偏差清单.md](./设计现状与偏差清单.md)
5. 决策：决策台账 → 版本记录（按时间查变更原因）

## 事实源优先级

1. `shared/types.ts` —— 字段契约唯一权威（只读，修改触发 K1 卡口）
2. `短剧Agent平台设计.md` —— 产品与架构事实源（md 是源，html 是镜像）
3. `resources/opencode/agents/*.md` —— Agent 行为 / 工具用法实况
4. 磁盘代码（`electron/` `src/`）—— 实现实况（"以磁盘实况为终态"，D-012）
5. 决策台账 / 版本记录 —— 变更依据与历史

**冲突裁决**：文档互相矛盾时，以"磁盘实况 + shared/types.ts"为终态判断基准（用户 2026-10-09 拍板"旧链路不回退、以磁盘实况为终态、所有设计要最后状态"，见决策台账 D-012）。

## 维护纪律

- **md 是事实源，html 是镜像**：改 `短剧Agent平台设计.md` 必须同步 `docs/design/短剧Agent平台设计.html`；镜像非独立事实源。
- **版本记录**：新条目追加到对应月份区块顶部；只记录事实与依据；条目被反转时不删除、加反转注记。
- **决策台账**：立项级决策永久保留，只增不改。
- **归档区冻结**：`docs/archive/` 仅保留作废说明（README），历史包文件已删除、见 git，不作为实现依据。
- **任务包**：新功能按《AI-SDG-AI工具执行指令》任务包 5 文件规范建包于 `docs/features/feature-{三位数字}-{业务名}/`。
- **偏差清单**：`docs/设计现状与偏差清单.md` 随磁盘实况变化持续更新，是"设计与实现偏差"的唯一载体。
