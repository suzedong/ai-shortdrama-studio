## 2. 消息视觉规范

| 消息 | 样式 |
|---|---|
| 用户文本 | 右对齐；紫底（`bg-violet`）白字；圆角 2xl、右下小圆角；最大宽 85% |
| Agent 文本 | 左对齐；紫色「主」头像 + 白卡细边框；圆角 2xl、左上小圆角 |
| 简报卡 | Agent 卡内嵌 2 列字段网格，label 用 `text-muted`，与原型/硬编码版一致 |
| 进度（pending） | 白底卡，左侧旋转 spinner（紫），文案 `text-sm` |
| 进度（done） | 绿色 ✓ + 文案变 `text-muted` |
| 错误 | 红描边（`#E05A52`）浅红底；失败原因 + 文字按钮「重试」（紫色） |
| gate / gate-action / archive | system 样式：居中小字，灰底胶囊（gate 待处理用紫底白字，gate-action 用灰，archive 用绿） |

## 3. 交互规范

- 发送：Enter 发送、Shift+Enter 换行（沿用 feature-001）；请求期间禁用发送按钮
- 自动滚动：消息数量或内容变化时 `scrollTop = scrollHeight`；用户手动上翻查看历史时不强制拉下（一期简化：始终滚底）
- 重试：错误消息「重试」按钮 → 重新执行诊断，不产生新用户气泡
- 输入框在确认门待处理期间仍可输入（一期不禁止输入，但主要动作走确认门）

## 4. 视觉验收

- [ ] 无硬编码消息残留
- [ ] 消息间距、气泡配色与 feature-001 视觉基线一致
- [ ] 长消息换行不撑破布局；进度/错误/系统消息在 360px 右栏内不溢出
- [ ] 刷新重建后视觉与刷新前一致（节点、门、消息无重复无丢失）
