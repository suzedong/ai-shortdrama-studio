> **版本**：v1.1（2026-10-03，v1.0 交付后缺陷修复，已实现并闭环）
>
> 对应架构文档：[短剧Agent平台设计.md](../../../短剧Agent平台设计.md) §3.4 对话区、§7 数据模型（events.log）、§10 部署
>
> 前置 Feature：feature-001-立项（已反向补录）
>
> **v1.1 修订要点**：FR-3 明确每道门否决后的重做语义；新增 FR-8 背景档案事实持久化；FR-5 增加落盘串行化保证。

## 1. 背景与问题

feature-001 跑通了立项业务链路，但对话区是"演示态"：

1. `ChatPanel` 首屏两条消息（用户气泡、Agent 创意简报卡）为**硬编码静态 JSX**
2. 用户真实输入创意后，对话区**无任何反馈**——只看到画布节点和确认门变化
3. 消息不持久化，渲染进程刷新或应用重启后全部丢失
4. 无"项目会话"概念：`project:save` 每次调用都新建 `project-{时间戳}` 目录，重复确认会产生多个目录
5. 项目无测试框架，违反 AGENTS.md 安全纪律第 6 条

**v1.0 交付后新发现并经用户确认的三个缺陷（2026-10-03）**：

6. **否决无重做路径**：`handleReject` 只关门，输入框唯一绑定首交流程，否决后输入任何文字都会重启整套立项（重复进度/诊断/简报/门），与 FR-3「否决后重做」矛盾（L1）。
7. **背景档案事实丢失**：锁定时只把字数写进消息，原始事实全文未落盘，刷新即永久丢失，违背架构 §2.6「不可篡改事实输入」。
8. **落盘并发覆盖**：消息写文件为"读整数组→改→写整文件"，连续 append（如首条用户消息与进度消息）并发时后写覆盖先写，存在丢消息风险。

## 2. 用户与场景

- **用户**：短剧创作者
- **场景 A（实时对话）**：输入创意后，用户气泡立即上屏，随后看到 Agent 的检索进度、结构化回复、失败点名；确认/否决动作也在对话流留痕
- **场景 B（刷新恢复）**：dev 调试或误刷新页面后，对话与画布状态从最近一次会话完整重建
- **场景 C（重启恢复）**：应用重新启动后，自动恢复最近会话，不重复创建项目目录

## 3. 功能需求

### FR-1 消息列表动态渲染

- `ChatPanel` 接收消息数组并按时间顺序渲染，**删除全部硬编码消息**
- 消息形态：
  - 用户消息：右对齐紫色气泡
  - Agent 文本：左对齐白色卡片（带头像）
  - **创意简报卡**：结构化字段网格（类型/集数/时长/画幅/风格）
  - **进度消息**：进行中显示 spinner + 文案（如"正在检索同赛道对标…"），完成后转为 ✓ 完成态
  - **错误消息**：红色描边卡片 + 失败原因 + 「重试」按钮
- 新消息到达时自动滚动到底部

### FR-2 立项流程产生消息

`handleIdea` 改造为消息驱动：

1. 首次提交时创建项目会话（见 FR-4）
2. 追加**用户消息**（立即上屏）
3. 追加**进度消息**"正在检索同赛道对标…"
4. 调用 `diagnose`：
   - 成功：进度消息转完成 → 追加 Agent 文本 + **选题诊断消息**（含案例数与结论）→ 画布节点更新 → 弹确认门 0-a
   - 失败：进度消息转失败 → 追加**错误消息**（可重试，重试重新走步骤 3-4）
5. 确认门弹出、确认、否决均产生对应消息（FR-3）

### FR-3 确认动作留痕

- 弹确认门：追加「待确认」消息（含门 id 与标题）
- 确认放行：追加动作消息（如"已确认 0-a 选题诊断"），继续既有节点推进逻辑（0-a→0-b→0-c 行为与 feature-001 一致）
- 否决/重做（v1.1 明确，每道门语义不同）：
  - 共同：追加动作消息（"已否决 0-x"）、关闭确认门；
  - **0-a 否决**：进入"待重做"。用户在对话输入修改意见并发送 → 意见作为 `instruction` 重新调用诊断 Agent；成功后追加新诊断、重新弹 0-a（不再走首交流程、不新建会话、不重复简报卡）。
  - **0-b 否决**：五要素为确定性派生事实，本轮不做按文字改写；否决后**直接重新打开 0-b**，用户可再次确认。
  - **0-c 否决**：进入"待重做"。用户输入意见 → 作为 `instruction` 重新生成视觉风格；成功后追加新视觉风格、重新弹 0-c。
- 0-b 确认后视觉风格请求期间同样显示进度消息；0-c 确认后的保存动作显示进度与结果

### FR-4 项目会话（Session）

- 首次提交创意时主进程创建会话目录 `Documents/ai-shortdrama-studio/project-{时间戳}/`，写入初始 `manifest.json`（状态 `initiating`）
- 主进程持有"当前会话"，并把路径持久化到应用 userData 下 `session-state.json`，应用重启后可读取
- `project:save`（0-c 确认时）改为**更新当前会话目录**内的 `manifest.json` / `brief.json`，不再新建目录
- 无会话时应用显示初始空态，不报错

### FR-5 消息持久化

- 每条消息实时追加写入会话目录的 `chat.messages.json`（JSON 数组，缩进 2）
- 写入失败时界面给出错误提示（不静默丢失）
- **v1.1：落盘串行化**——主进程对消息写（读-改-写）按调用顺序进入单写队列，保证连续 append 不发生并发覆盖、不丢消息、顺序与调用一致

### FR-6 会话恢复（刷新/重启）

- 渲染进程启动时查询当前会话：
  - 有会话 → 加载 `chat.messages.json`，**按消息重放**恢复：节点状态、确认门（含未处理的门）、诊断/五要素/视觉风格数据、档案录入区显隐、已保存状态
  - 无会话 → 初始空态
- **v1.1**：重放同时恢复"待重做"状态——0-a/0-c 被否决且尚未重做时，下一条对话消息仍按 FR-3 作为重做 instruction 路由
- dev 刷新（F5）与应用重启两种路径均需恢复成功

### FR-7 单元测试（首个落地测试的 Feature）

- 引入 Vitest 测试框架
- 纯逻辑测试：五要素推导、消息重放、消息构造辅助函数
- 组件测试：ChatPanel 消息渲染、发送、错误重试入口
- 测试不通过视为任务未完成；新增 `npm test` / `npm run test:run` 脚本

### FR-8 背景档案事实持久化（v1.1 新增）

- 用户锁定背景档案时，主进程把档案全文写入当前会话目录 `故事背景档案.md`（UTF-8）
- 写盘成功后再追加锁定消息、更新画布节点；写失败时档案录入区保持打开并给出错误提示，不标记完成、不丢事实
- 该文件是后续编剧 Agent 的只读事实来源

## 4. 非目标（明确不做，防止范围蔓延）

1. 项目库列表真实化与多项目切换 UI（会话恢复 IPC 预留，但不做切换入口）
2. 消息的编辑、删除、撤回、复制
3. Markdown 完整渲染、流式（SSE）逐字输出
4. `/` 唤起 Skill、`@` 指向资产的输入交互
5. 对话中展示工具调用参数明细（toolCall 渲染仅保留现有数据结构，不展开 UI）
6. 多会话并存、会话重命名
7. 剧本 Agent 及故事创作阶段
