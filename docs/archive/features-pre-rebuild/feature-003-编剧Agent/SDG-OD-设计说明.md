## 2. 画布分阶段布局

立项画布由单行扩展为纵向两行（自动布局，不可拖拽）：

```
STAGE 0 · 立项
[创意输入] ─ [选题诊断] ─ [立项单] ─ [故事背景档案]

STAGE 1 · 故事创作
[故事大纲] ─ [人物小传]
```

| 元素 | 规范 |
|---|---|
| 组标签 | 行左上，`text-xs text-muted`，全大写小字（STAGE 0/1） |
| 节点卡 | 沿用 w-56 白卡 + 序号/✓ 徽标；active 紫描边 ring、done 绿描边、pending 灰 |
| 阶段连线 | 组内节点 w-8 横线；组间不连线（以纵向留白 + 组标签分隔） |
| 缩放 | 按最宽行动态缩放；进入故事前故事行两节点灰态可见（体现下游全貌） |

## 3. 新增卡片视觉

| 卡片 | 样式 |
|---|---|
| 进入故事 CTA | 右栏顶部白卡：左侧「立项已完成」文案 + 紫底按钮「进入故事创作」；点击后卡片消失 |
| 故事大纲卡 | Agent 白卡内嵌：logline 加粗顶行；分小节「本季主线 / 主题 / 核心冲突·钩子 / 分集」；分集以 E01 列表（标题+梗概+集尾钩子） |
| 人物小传卡 | Agent 白卡内每位角色一个分隔块：角色名 + 身份徽标，下方两列 label/值（年龄/性格/背景/动机/弧光/关系/台词风格） |
| 阶段胶囊 | system 居中小胶囊，紫底白字「进入 STAGE 1 · 故事创作」 |
| 进度/错误/确认门 | 完全沿用 feature-002 规范（spinner/✓/✗、红边错误卡、确认门三按钮结构） |

## 4. 确认门视觉（1-a / 1-b）

- 1-a「故事大纲确认」：摘要 = logline；Harness 项：大纲含 E01、事实与背景档案一致、主题/冲突齐备。
- 1-b「人物小传确认」：摘要 = 主要角色数；Harness 项：至少 2 个主要角色、字段齐备、与大纲一致。
- 按钮：确认放行 / 否决（沿用现有 GateCard，无需新增按钮类型）。

## 5. 交互规范

- 立项完成 → CTA 常驻，直到进入故事；进入后编剧 Agent 自动推进，用户不填字段。
- 否决路径：关门后在对话输入调整意见，回车作为修改指令（用户文本气泡上屏 + 对应产物重新生成）；交互与 feature-002 v1.1 的确认门重做机制一致。
- 请求期间禁用发送按钮；其余沿用 Enter 发送 / Shift+Enter 换行 / 自动滚底。

## 6. 视觉验收

- [ ] 画布呈现 STAGE 0 / STAGE 1 两组，组标签与连线清晰；未进入时故事行灰态
- [ ] 大纲卡、小传卡在 360px 右栏内不溢出，长文本换行正常
- [ ] 进入故事 CTA 在立项完成后出现、点击后消失
- [ ] 刷新重建后两组节点、当前产物、未处理确认门与刷新前一致
- [ ] 配色/间距/卡片语言与 feature-001/002 视觉基线一致，无新增风格语言
