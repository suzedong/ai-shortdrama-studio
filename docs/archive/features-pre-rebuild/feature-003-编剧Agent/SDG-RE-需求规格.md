## 1. 背景与问题

feature-001 / 002 完成了 STAGE 0「立项」：选题诊断、五要素、视觉风格、故事背景档案；对话消息动态化、可持久化、可重放恢复。feature-002 v1.1 进一步补齐：**背景档案全文已落盘为会话目录 `故事背景档案.md`**（只读事实源）、消息落盘串行化、确认门可按意见重做。

但应用仍止步于立项——用户锁定背景档案后，**无法进入下一阶段，没有任何专职 Agent 接手**：

1. 无 STAGE 1「故事创作」阶段概念；立项完成即流程终点。
2. 无**编剧 Agent**：架构 §4.1 规定的「故事大纲、人物小传、分场、台词、分镜文字稿」尚不存在。
3. 画布只有一条 4 节点立项链（[StageCanvas.tsx](../../../src/components/StageCanvas.tsx) 硬编码 4 节点宽度与「立项阶段」提示），无法承载故事创作节点、无法体现阶段扩展。

> 背景档案事实持久化的缺口已在 feature-002 v1.1 解决（`archive:save`），本 Feature 直接消费 `故事背景档案.md`，不再重复该工作。

## 2. 用户与场景

- **用户**：短剧创作者（人是导演，只做拍板与提供事实）。
- **场景 A（进入故事创作）**：锁定背景档案后，用户点击「进入故事创作」，主控 Agent 交棒，**编剧 Agent 主动**基于立项单与背景事实构思故事大纲。
- **场景 B（大纲拍板）**：用户在对话流查看结构化大纲卡，在确认门 1-a 确认（写入剧本资产）或否决（用对话反馈，编剧重新构思）。
- **场景 C（人物小传拍板）**：大纲确认后，编剧 Agent 自动撰写主要人物小传，用户在确认门 1-b 确认或否决。
- **场景 D（刷新/重启恢复）**：进入故事创作后的任意时点，页面刷新或应用重启，阶段、大纲/小传、未处理确认门、画布节点从会话完整重建。

## 3. 功能需求

### FR-1 阶段切换：进入故事创作

- 立项全部节点（含背景档案）完成后，右栏显示 CTA 卡片：「立项已完成 · [进入故事创作]」。
- 点击后：
  1. 主进程把 manifest 阶段标记更新为故事创作（读-改-写，保留五要素/视觉风格等既有字段，不覆盖）。
  2. 对话流追加阶段胶囊「进入 STAGE 1 · 故事创作」。
  3. CTA 消失；**编剧 Agent 立即自动开始**故事大纲生成（FR-2），无需用户再输入。

### FR-2 编剧 Agent 产出故事大纲

- 生成期间显示进度消息「编剧 Agent 正在构思故事大纲…」（spinner）。
- 主进程自行组装上下文：brief.json 的五要素/视觉风格 + `故事背景档案.md` 事实（feature-002 v1.1 已落盘）+ 可选的用户修改指令；调用火山方舟，解析为结构化 `StoryOutline`。
- 成功：进度转完成 → 追加**故事大纲卡**（logline / 本季主线 / 主题 / 核心冲突与钩子 / 分集，至少 E01）→ 画布故事行「故事大纲」节点激活 → 弹确认门 **1-a 故事大纲确认**。
- 失败：进度转失败 → 错误卡（可重试，重试重新生成大纲）。
- 大纲必须与背景档案事实一致（人物年龄/城市/季边界等不得被改写）。

### FR-3 确认门 1-a 与大纲定稿

- **确认**：追加动作消息 → 主进程把大纲定稿写入 `剧本/故事大纲.json`（结构化）与 `剧本/故事大纲.md`（人读），manifest 阶段推进 → 画布「故事大纲」完成、「人物小传」激活 → 自动开始人物小传生成（FR-4）。
- **否决**：追加动作消息、关闭确认门；大纲卡保留。用户在对话输入调整意见（如"女主改成研究生、节奏更快"），该文本作为**修改指令**触发大纲重新生成（走 FR-2，并在 prompt 中携带指令）。

### FR-4 编剧 Agent 产出人物小传

- 生成期间显示进度「编剧 Agent 正在撰写人物小传…」。
- 主进程上下文 = brief + 已定稿大纲（`剧本/故事大纲.json`）+ 背景档案 + 可选指令；产出 `CharacterProfile[]`（主要角色）。
- 成功：进度完成 → 追加**人物小传卡**（每位角色：身份/性格/背景/动机/弧光/关系/台词风格）→ 画布「人物小传」节点激活 → 弹确认门 **1-b 人物小传确认**。
- 失败：进度转失败 → 错误卡（可重试）。

### FR-5 确认门 1-b 与本 Feature 收尾

- **确认**：动作消息 → 小传定稿写入 `剧本/人物小传.json` + `.md`，manifest 阶段置为故事创作完成 → 画布「人物小传」完成 → 追加 Agent 文本：「故事大纲与人物小传已锁定，下一阶段：分场与台词」。
- **否决**：动作消息、关门；用户以对话反馈，指令触发小传重新生成（FR-4）。

### FR-6 画布分阶段

- 画布由「单行立项链」泛化为「多阶段分组」：STAGE 0 立项（既有 4 节点）+ STAGE 1 故事创作（故事大纲、人物小传 2 节点）；组标题、节点连线、状态着色沿用既有视觉语言。
- 宽度按各行动态计算并整体缩放（不再硬编码 4 节点宽度）。
- 立项未进入故事创作时，故事行节点保持灰态占位。

### FR-7 故事阶段重放恢复

- 消息中新增阶段进入标记、故事大纲、人物小传等 kind；`replayMessages` 扩展为可恢复：
  - 当前阶段（立项 / 故事）；
  - 大纲、小传数据；故事行节点状态；
  - 未处理确认门 1-a / 1-b；
  - 立项已完成但尚未进入故事创作时，重新显示「进入故事创作」CTA。
- 刷新（F5）与应用重启两种路径均恢复成功。

### FR-8 单元测试

- 纯逻辑：大纲/小传 JSON 解析（含代码块包裹、数组或对象包装）、故事确认门构造、故事阶段重放。
- 组件：大纲卡/小传卡渲染；故事阶段 App 编排集成（进入→大纲→1-a→小传→1-b，断言定稿落盘 IPC 被调用）。
- 测试不通过视为未完成。

## 4. 非目标（明确不做，防止范围蔓延）

1. **分场、台词、分镜文字稿**：编剧 Agent 的下游产物，留待后续 Feature（feature-004）。
2. E02 及以后分集的独立大纲细化（本 Feature 大纲含 E01 明细即可，其余以本季主线概括）。
3. 项目库列表真实化、多项目切换 UI。
4. 画布自由编排/拖拽连线（坚持自动布局与"看 + 确认"）。
5. 剧本的在线富文本编辑器、版本 diff UI（定稿写 JSON+MD，但不做编辑器）。
6. 大纲/小传的流式（SSE）逐字输出。
7. 多编剧 Agent 并行、Agent 间直接互调（仍经主控/消息）。
8. 新增任何运行时依赖。
