## 1. 背景与问题

feature-003 让编剧 Agent 产出了故事大纲（`剧本/故事大纲`）与人物小传（`剧本/人物小传`），STAGE 1 以收尾文本「故事大纲与人物小传已锁定，下一阶段：分场与台词」结束。但流程到此为止：

1. 无 STAGE 2「剧本分镜」阶段概念，故事定稿后无下游接手。
2. 编剧 Agent 的后半职责（架构 §4.1：**分场、台词、分镜文字稿**）尚不存在；大纲只有 E01 梗概，不是可拍摄文本。
3. 未来镜头/声音/剪辑 Agent 需要机器可读的分镜表（架构 §7 `分镜/shotlist.json`），当前没有任何生产者。

本 Feature 把编剧链路推进到「**第一集可拍摄剧本 + 可排镜的分镜表**」，为后续美术定妆 / 逐镜生成（一期单集闭环，架构 §11 第 3 条）准备输入。

## 2. 用户与场景

- **用户**：短剧创作者（人是导演，只做拍板与提供事实）。
- **场景 A（进入剧本分镜）**：1-b 人物小传锁定后，右栏出现「进入剧本分镜」CTA；点击后主控交棒，编剧 Agent **立即自动**基于大纲+小传+背景事实拆分 E01 分场。
- **场景 B（分场拍板 2-a）**：用户查看分场卡，确认（写入分场资产并自动进入台词）或否决（对话反馈，编剧重拆分场，已锁定产物不受影响）。
- **场景 C（台词拍板 2-b）**：编剧基于已定稿分场撰写对白；用户确认或否决重做。
- **场景 D（分镜拍板 2-c）**：编剧基于已定稿分场+台词拆分镜表（镜号/景别/画面/台词/时长/运镜）；确认后第一集剧本与分镜锁定。
- **场景 E（刷新/重启恢复）**：STAGE 2 任意时点刷新或重启，阶段、三个产物、未处理确认门、画布节点从会话完整重建。

## 3. 功能需求

### FR-1 阶段切换：进入剧本分镜

- 人物小传（1-b）锁定后，右栏显示 CTA：「故事已完成 · [进入剧本分镜]」。
- 点击后：
  1. 主进程把 manifest.status 读-改-写为 `script-scenes`（保留全部既有字段，不覆盖）。
  2. 对话流追加阶段胶囊「进入 STAGE 2 · 剧本分镜」。
  3. CTA 消失；编剧 Agent **立即自动**开始分场生成（FR-2），无需用户输入。

### FR-2 编剧 Agent 产出分场（E01）

- 生成期间显示进度「编剧 Agent 正在拆分第一集分场…」（spinner）。
- 主进程自组装上下文：brief 五要素/视觉风格 + `故事背景档案.md` + **已定稿**故事大纲 + 人物小传 + 可选用户修改指令；解析为结构化 `SceneBreakdown`（`Scene[]`）。
- 成功：进度完成 → 追加**分场卡**（场号、内外/日夜、地点、出场角色、节拍、情绪、预估时长）→ 画布「分场」节点激活 → 弹确认门 **2-a 分场确认**。
- 失败：进度失败 → 错误卡（可重试）。
- 分场必须与大纲 E01、背景档案事实一致（角色、季边界不得被改写）。

### FR-3 确认门 2-a 与分场定稿

- **确认**：动作消息 → 主进程写 `剧本/分场.json`（结构化）+ `剧本/分场.md`（人读），manifest.status 推进为 `script-dialogue` → 画布「分场」完成、「台词」激活 → 自动开始台词生成（FR-4）。
- **否决**：动作消息、关门；分场卡保留。用户在对话输入调整意见，文本作为**修改指令**触发分场重新生成（FR-2，prompt 携带指令）。

### FR-4 编剧 Agent 产出台词

- 生成期间显示进度「编剧 Agent 正在撰写第一集台词…」。
- 上下文 = 分场全部上下文 **+ 已定稿分场**；产出 `DialogueScript`（按场组织的 `DialogueLine[]`，含角色/对白旁白独白/情绪/动作提示）。
- 成功：进度完成 → 追加**台词卡**（按场分组：角色名 + 情绪 + 台词）→ 画布「台词」节点激活 → 弹确认门 **2-b 台词确认**。
- 失败：错误卡（可重试）。
- 说话人必须引用人物小传中的角色 id；功能性无小传角色（路人、画外音）允许带 `speakerName` 兜底。

### FR-5 确认门 2-b 与台词定稿

- **确认**：写 `剧本/台词.json/.md`，status 推进为 `script-storyboard` → 「台词」完成、「分镜表」激活 → 自动开始分镜生成（FR-6）。
- **否决**：关门、台词卡保留；对话意见作为指令触发台词重生成。

### FR-6 编剧 Agent 产出分镜文字稿（分镜表）

- 生成期间显示进度「编剧 Agent 正在编排第一集分镜…」。
- 上下文 = 前述全部 **+ 已定稿分场 + 已定稿台词**；产出 `ShotList`（`Shot[]`，字段对齐架构 §7：镜号/集/行序/景别/场景id/角色id[]/画面动作/台词/时长/运镜/参考资产）。
- 成功：进度完成 → 追加**分镜卡**（镜号/景别/画面动作/台词/时长/运镜）→ 画布「分镜表」节点激活 → 弹确认门 **2-c 分镜确认**。
- 失败：错误卡（可重试）。
- `场景id` 一期以分场场号引用；`参考资产[]` 一期恒为空数组（美术资产尚未生产，占位）。

### FR-7 确认门 2-c 与本 Feature 收尾

- **确认**：写 `分镜/shotlist.json` + `分镜/shotlist.md`（新建 `分镜/` 顶层产物目录），status 置为 `storyboard-done` → 「分镜表」完成 → 追加 Agent 文本：「第一集剧本与分镜已锁定，下一阶段：美术定妆」。
- **否决**：关门、分镜卡保留；对话意见触发分镜重生成。

### FR-8 画布分阶段

- 画布新增第三行 **STAGE 2「剧本分镜」**：分场 → 台词 → 分镜表（3 节点）；组标签、连线、状态着色、动态行宽缩放沿用 feature-003 的 groups 画布。
- 未进入 STAGE 2 时，该行节点灰态占位。
- 三行总览：STAGE 0 立项（4）/ STAGE 1 故事创作（2）/ STAGE 2 剧本分镜（3）。

### FR-9 STAGE 2 重放恢复

- 消息新增阶段进入（phase=`script`）、分场、台词、分镜等 kind；`replayMessages` 扩展恢复：
  - 当前阶段（立项 / 故事 / 剧本分镜）；
  - 三个产物数据与画布节点状态；
  - 未处理确认门 2-a / 2-b / 2-c；
  - 各产物否决后等待意见的重做状态 `scriptRedo`；
  - 故事完成但未进入剧本分镜时，重新显示「进入剧本分镜」CTA。
- 刷新（F5）与应用重启两种路径均恢复成功。

### FR-10 单元测试

- 纯逻辑：分场/台词/分镜 JSON 解析（代码块包裹、数组/对象包装、非法形态抛错）、三个新确认门构造、STAGE 2 重放。
- 组件：分场卡/台词卡/分镜卡渲染；STAGE 2 App 编排集成（进入→分场→2-a（断言落盘 IPC）→台词→2-b→分镜→2-c；否决重做）。
- 测试不通过视为未完成。

## 4. 非目标（明确不做，防止范围蔓延）

1. **E02 及以后分集**：一期单集闭环，本包只细化 E01；多集目录/命名演进留待后续。
2. **美术 / 定妆 / 场景资产真实生成**：分镜的 `参考资产[]` 仅空数组占位；美术 Agent 为后续 Feature。
3. **逐镜视频生成、ComfyUI 工作流、T2A 配音、剪辑**：均为后续 Feature。
4. **manifest 历史数据债务治理**：feature-001~003 存在 manifest 字段漂移、五要素/视觉风格双份存储等问题（见契约 §10 已知差异登记），本包**只新增、不重构**，治理另立数据治理包（届时触发 K3 由用户签字）。
5. 剧本在线富文本编辑器、版本 diff UI（只写 JSON+MD 定稿）。
6. 流式（SSE）逐字输出。
7. 多编剧 Agent 并行、Agent 间直接互调。
8. 新增任何运行时依赖。
