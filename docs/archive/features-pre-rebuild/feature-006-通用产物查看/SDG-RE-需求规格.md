# SDG-RE 需求规格 · feature-006 通用产物查看

> 版本：v1.4（2026-10-04，新增定稿文件回退，见 US-8）
> 关联：feature-005-产物解锁重做（变更传播/失效态）、feature-001~004（各产物生产）
> 触发：用户反馈「不管是立项阶段还是其他阶段，查看功能都很重要。只有查看了才能知道问题，才能采取修改」。

## 1. 背景与问题

当前画布上，「查看」不是一项完整能力，而是背景档案的特例：

1. 👁 入口仅在「故事背景档案」一个节点出现（`viewEntries={{ background: true }}` 硬编码）；
2. 六个 AI 产物节点（立项单/大纲/小传/分场/台词/分镜）只有 💬 对话修改，没有查看；
3. 「选题诊断」节点没有任何入口；
4. 查看按钮 hover 才浮现，用户难以发现。

用户在任何阶段都需要**先看到产物内容、判断问题，再决定如何修改**。查看必须成为贯穿立项/故事/剧本三阶段、覆盖全部产物节点的一等入口。

## 2. 目标

1. 全部 9 个画布节点在「已有产物」时都可查看；
2. 入口直觉、显眼：点击节点卡片本体即可查看（借鉴 MiniMax Design「点击节点 → 查看/定位」范式），无需寻找悬浮小图标；
3. 查看为**纯只读**，不改变任何节点/产物状态，在门控、加载、变更链进行中均可查看；
4. 已失效（invalidated）节点可查看其上一版旧内容；
5. 查看后可一键衔接修改（对话修改 / 重新生成）。

## 3. 用户故事与场景

| # | 角色 | 场景 | 期望 |
| :- | :-- | :-- | :-- |
| US-1 | 导演（用户） | 立项阶段，想回看选题诊断结论与对标案例 | 点「选题诊断」卡片 → 只读看到诊断全文（对标/洞察/钩子/合规/结论） |
| US-2 | 导演 | 立项阶段，想确认立项单的六要素与视觉风格 | 点「立项单」卡片 → 看到六要素 + 视觉风格 |
| US-3 | 导演 | 故事/剧本阶段，逐一查看大纲、小传、分场、台词、分镜 | 点对应节点 → 看到结构化产物（与聊天流中的富卡片一致） |
| US-3b | 导演 | 打开查看器后，想知道这份内容实际来自会话目录的哪个文件 | 标题与状态徽标之间显示「来源：xxx」；多段复合产物列出多个来源文件（逗号分隔）；该信息纯展示、不随门控/加载状态变化 |
| US-4 | 导演 | 修改了创意后，下游标红失效，想看旧版被哪里影响 | 点失效节点 → 看到上一版内容，顶部标注「已失效·旧版本」 |
| US-5 | 导演 | 查看中发现问题，想直接改 | 模态底部「去修改」→ 定稿节点进入对话修改；失效可重做节点触发重新生成 |
| US-6 | 导演 | 变更链进行中/门控弹出时，只想查看不想操作 | 卡片仍可点开查看；「去修改」按钮置灰并说明原因 |
| US-7 | 导演 | 想回看创意输入原文 / 背景档案 | 点对应节点 → 看到创意全文 / 档案全文 |
| US-8 | 导演 | 清空了对话记录（或消息文件丢失），仍想查看已定稿的立项单/大纲/小传/分场/台词/分镜 | 有独立定稿文件的节点仍显示为已定稿、可点开查看；标题来源显示对应定稿文件而非 chat.messages.json |

### US-8：清空对话后，定稿产物仍可查看

- 作为用户，我担心「立项信息都存在 chat.messages.json，清空对话后立项信息就没了」。
- 事实：立项定稿（六要素 + 视觉风格 + 诊断结论）在 0-c 确认时已独立写入 `brief.json`，下游故事/剧本生成读的就是它，**不依赖消息流**；故事/剧本各产物定稿时也各自落了独立文件。
- 期望：消息流缺失时，查看器与画布状态**回退读取这些定稿文件**，使定稿产物「文件在即可查看」；消息流存在时仍以消息流为准（避免双源歧义）。

**可回退节点（6）**：brief、outline、profiles、scenes、dialogue、storyboard（background 本就独立）。

**不可回退硬边界（2）**：

- **idea 创意原文**：无独立文件，清空后不可恢复；
- **完整选题诊断**：定稿时仅把 conclusion 文本存入 brief.json，对标案例表/用户洞察/钩子模式/合规未落文件；清空后 diagnosis 节点不可查看，立项单的「诊断结论」段只剩结论文本、无对标案例表。

> 实现方式（契约 §10）：新增只读 IPC `session:read-finalized` 一次性返回定稿快照；纯读取、零写入。该 IPC 属 K8 卡口，需用户签字。

### US-3b：查看时知晓数据来源文件

- 作为用户，我打开查看器后，希望在标题右侧看到这份内容实际来自会话目录的哪个文件，以便核对事实来源、定位磁盘文件。
- 验收：标题与状态徽标之间显示「来源：xxx」；多段复合产物列出多个来源文件（逗号分隔）；该信息纯展示、不随门控/加载状态变化。

| 节点 | 来源文件 |
| :-- | :-- |
| idea | chat.messages.json |
| diagnosis | chat.messages.json |
| brief | chat.messages.json |
| background | 故事背景档案.md |
| outline / profiles / scenes / dialogue / storyboard | chat.messages.json |

> 复合立项单（简报+视觉风格+诊断）三段数据均在 chat.messages.json 内，来源只显示一次。

## 4. 功能范围

### 4.1 可查看节点与内容来源

| 阶段 | 节点 id | 查看内容 |
| :-- | :-- | :-- |
| 立项 | idea | 创意输入全文（当前定稿 ideaText） |
| 立项 | diagnosis | 最近一次选题诊断 TopicDiagnosis + 创意简报 brief（若有） |
| 立项 | brief | ① 最近一次创意简报 Brief（类型/集数/时长/画幅/风格）<br>② 最近一次视觉风格 VisualStyle（形态/主画风/L2锚词…）<br>③ 最近一次选题诊断 TopicDiagnosis（结论 + 对标案例摘要）；复合 kind `brief-full`：上半 BriefCard 简报、中 VisualStyleView 视觉风格、下「选题诊断结论」段（可做判定 + 对标案例名称/成绩/启示） |
| 立项 | background | 故事背景档案全文（readArchive） |
| 故事 | outline | 最近定稿故事大纲 StoryOutline |
| 故事 | profiles | 最近定稿人物小传 CharacterProfile[] |
| 剧本 | scenes | 最近定稿分场 SceneBreakdown |
| 剧本 | dialogue | 最近定稿台词 DialogueScript |
| 剧本 | storyboard | 最近定稿分镜表 ShotList |

> **立项单复合内容（修订）**：画布「立项单」节点摘要取自创意简报五要素；点开查看必须包含该简报（保证与卡片摘要、选题诊断底部简报一致），并补充同属立项交付的视觉风格方案，构成完整立项单。
>
> **立项单聚合诊断结论（再修订）**：借鉴《安妮的夏天》立项单，立项单末尾聚合「选题诊断结论」段——诊断 conclusion（可做判定）+ 对标案例精简表（名称/平台成绩/一句启示），数据复用 diagnosis 消息；诊断未生成则该段不显示。完整诊断（用户洞察/钩子模式/合规）仍在「选题诊断」节点查看。

「最近」定义见契约 §3（取消息流中该 kind 的最后一条正式产物；失效时即旧世代的最后一条）。

### 4.2 入口与交互

1. **整卡可点**：节点状态为 done 或 invalidated 时，卡片本体为点击目标（cursor:pointer），点击打开只读查看模态；
2. **hover 动作区**：hover 卡片时右上角浮现 👁（查看，与整卡点击等效）+ ✎/💬（修改类动作，沿用现状）；
3. 从未产出内容（pending/active）节点不可点、不显示 👁；
4. 查看能力**不受门控/失效清空**：门控期间、变更链进行中、加载中均可打开只读查看。

### 4.3 查看模态

1. 标题：节点名称；右侧状态徽标：✓ 当前定稿（done）/ ⚠ 已失效·旧版本（invalidated）；
2. 内容：按节点复用现有结构化富卡片（见契约 §4），只读、可滚动；
3. 底部「去修改」主按钮 + 关闭；Esc / 遮罩可关闭。

### 4.4 「去修改」路由

| 节点当前状态 / 全局状态 | 「去修改」行为 |
| :-- | :-- |
| done 且当前可发起修改 | 关闭查看 → 进入该节点 💬 对话修改（挂 @ chip，沿用 startDraft） |
| invalidated 且 isRunnable | 关闭查看 → 触发该节点「重新生成」 |
| invalidated 但直接前驱未 done | 按钮置灰，提示「请先完成上游：{前驱节点名}」 |
| loading / gate / activeUnlock / activeDraft 进行中 | 按钮置灰，提示相应原因 |

idea 节点「去修改」→ 打开 IdeaEditDialog（沿用编辑）；background 节点 → 打开可编辑档案模态（沿用 commitArchive）。

## 5. 非目标（一期不做）

- 不做产物版本历史列表/多版本切换（仅看当前或上一版旧内容；聊天流历史气泡仍保留）；
- 不做查看内联编辑（编辑统一走既有对话框/对话修改）；
- 不做导出、对比、批注；
- 不改变任何产物生产逻辑与消息流结构。

## 6. 验收标准（摘要，详见任务清单 AC）

1. 9 个节点在 done/invalidated 时均可点开查看；pending/active 不可点；
2. 点击卡片本体与点击 👁 都能打开查看，内容为该节点最近产物且字段完整；
3. 失效节点查看显示旧版本内容 + 「已失效·旧版本」徽标；
4. 查看为只读，打开/关闭不改变节点状态与消息流；
5. 「去修改」按 §4.4 正确路由或置灰提示；
6. 门控/加载/变更链期间查看可用；
7. 全量单元测试通过，无回归。
