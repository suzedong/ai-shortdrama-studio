## 1. 背景与问题

视觉风格谱系是 Stage 0-c「视觉风格」的**选择域与运行时校验依据**：0-c 只能在谱系目录内选型，`assertInCatalog` 依据它拦截目录外形态/画风。但该资产目前存在两个问题：

| # | 问题 | 影响 |
| :-- | :-- | :-- |
| 1 | **谱系对用户不可见**：谱系内容仅以编译进代码的 TS 常量 [style-catalog.ts](../../../electron/style-catalog.ts) 存在（4 形态 / 5 家族 / 18 画风，每条含 visualFeatures / anchorWords / qualityRecipe / feasibility），应用内无任何查看入口 | 用户在 0-c 拍板时无从了解"有哪些画风、各自视觉特征/锚点/可行度"，只能被动接受模型推荐 |
| 2 | **0-c prompt 目录信息缺口**：[prompts.ts L47](../../../electron/prompts.ts#L47) 注入给模型的目录仅含「家族｜画风名｜主/备｜可行度」四列，但 L56 又要求模型「anchorWords 与 qualityRecipe 照抄目录」——模型实际看不到 anchorWords / visualFeatures / qualityRecipe 正文 | "未照抄目录"现象根因不全在模型、而在 prompt 未提供原文；0-c 遵从度受损（feature-011 走查已暴露） |

本 Feature 一次性解决：把谱系作为**系统资产**提供应用内只读查看，并让 0-c prompt 与查看页基于同一份数据。

---

## 2. 角色与场景

| 角色 | 场景 | 期望效果 |
| :-- | :-- | :-- |
| 创作者（唯一用户） | 立项任意阶段想了解可选画风 | 经顶栏「系统资产」打开谱系页，按家族分组浏览全部 18 画风 |
| 创作者 | 0-c 看到推荐、想核对该画风依据 | 在候选卡点「查看谱系」快捷链接，打开同一页面 |
| 创作者 | 想快速定位某类风格 | 在搜索框输入画风名 / 锚点词关键词，列表实时过滤 |
| 创作者 | 拍板 0-c | 模型因能读到目录全字段，anchorWords / qualityRecipe 逐字照抄，不再自造 |

## 3. 功能需求

### F1 · 系统资产查看页（谱系视图）`[自研新增]`

- F1-1 新增只读页面组件，以 [style-catalog.ts](../../../electron/style-catalog.ts) 的 `STYLE_CATALOG / FORMS / CATALOG_VERSION` 为**唯一数据源**（renderer 直接 import，不新增 IPC、不复制内容、不落盘）。
- F1-2 页面结构：
  - **头部**：标题「系统资产 · 视觉风格谱系」+ 谱系版本号（`CATALOG_VERSION`）+ 4 形态说明（`FORMS`）+ 关闭按钮。
  - **搜索框**：单个文本输入，按关键词实时过滤（匹配 `name` 与 `anchorWords`，大小写不敏感、去首尾空格；空串即显示全部）。
  - **分组卡片**：按 `family`（A–E 五家族）分组，每组下该家族的画风卡片。卡片字段：画风名 `name`、主/备徽标 `tier`、可行度 `feasibility`、视觉特征 `visualFeatures`、锚点词 `anchorWords`、质感配方 `qualityRecipe`（保留换行）。
- F1-3 搜索无结果时显示空态「未找到匹配的画风」，不渲染假数据。
- F1-4 页面为**只读**：不提供编辑/新增/删除画风的入口（谱系升级仍按既有"人工同步 style-catalog.ts 并递增版本"流程，不在应用内编辑）。

### F2 · 双入口（同一组件）`[自研新增]`

- F2-1 **顶栏入口**：[App.tsx header](../../../src/App.tsx#L1570) 操作区新增「系统资产」按钮，与「运行时」按钮同一样式组；点击打开 F1 页面。
- F2-2 **0-c 候选卡快捷链接**：[CandidateCards.tsx](../../../src/components/messages/CandidateCards.tsx) 的视觉风格块（谱系徽标附近）新增「查看谱系」文字按钮；点击打开同一 F1 页面。
- F2-3 两入口共用同一页面组件与同一开关状态；打开为覆盖主内容区的页面（具体容器形态见契约 §2），关闭后回到原工作界面，不改变任何工作流/节点状态。

### F3 · 0-c 目录注入信息对齐 `[改编]`

- F3-1 改造 [prompts.ts](../../../electron/prompts.ts) 目录拼装：注入给模型的每条画风在原「家族｜画风名｜主/备｜可行度」基础上，补齐 `visualFeatures / anchorWords / qualityRecipe` 正文，使模型"看得到原文才照抄"。
- F3-2 维持既有选型规则文案（禁止目录外、主画风逐字、备档约束、仅六要素变更保留风格）；仅扩充目录数据，不改变输出 JSON schema。
- F3-3 同步更新受影响的既有测试断言（[revise-text.test.ts](../../../src/test/revise-text.test.ts) 对"单行四列正则"与"照抄"的断言需适配新格式；属格式适配，不放松"18 画风全量注入 / 11 主 7 备 / 禁止目录外"等实质约束）。

## 4. 不做什么（边界）

1. 不做谱系的应用内编辑/新增/删除/版本升级写入；不做谱系导入导出。
2. 不新建可扩展的"资产中心"空框架：仅以最小方式让容器可容纳未来资产，但本次只实现谱系一个，不提前实现其他资产。
3. 不新增 IPC、不新增文件读写、不复制谱系内容为 md/JSON（直接 import 常量）。
4. 不改变 0-c 输出 JSON schema、不改 `validateVisualStyle / assertInCatalog` 校验规则、不动八步流程与门禁语义。（该边界中「不改校验规则」由 feature-014 经用户签字解除，2026-10-07）
5. **不修改 `shared/types.ts`**（本 Feature 无 K1）。
6. 不新增运行时 npm 依赖（K9）。
7. 不处理参考图缩略图灰块等既有外部鉴权问题（与本 Feature 无关）。

## 5. 验收标准（AC，任务清单 AC 表为准）

- AC-1 顶栏可见「系统资产」按钮，点击打开谱系页；页面展示版本号、4 形态、按 A–E 家族分组的 18 画风卡片。
- AC-2 每张卡片含画风名、主/备、可行度、视觉特征、锚点词、质感配方（换行正确）。
- AC-3 搜索框输入画风名或锚点词关键词可实时过滤；无结果显示空态；清空恢复全部。
- AC-4 0-c 候选卡处有「查看谱系」链接，点击打开与顶栏同一页面。
- AC-5 页面只读、无编辑入口；关闭页面后工作流/节点状态无任何变化。
- AC-6 0-c prompt 每条画风含 visualFeatures / anchorWords / qualityRecipe 正文；选型规则与输出 schema 不变。
- AC-7 谱系页内容随 `style-catalog.ts` 数据渲染（单一事实源，无重复维护）。
- AC-8 typecheck、build、既有测试全通过且测试只增不减（含新增谱系页/搜索测试与 prompt 注入断言）。
