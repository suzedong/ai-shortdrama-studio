# SDG-OD 设计说明 · feature-016 架构重建总纲

> 状态：**v1.0 待审批**
> 日期：2026-10-07
> 本文件只锁定**界面结构与交互形态（设计方向）**，非高保真视觉稿；视觉规范在各切片 Feature 中细化。

---

## 1. 总体布局（三栏 + 画布）

对标 MiniMax Design：左导航 / 中画布 / 右 Agent 对话任务区。

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 · 当前步骤 · 运行时状态 · 设置（ComfyUI 实例入口）      │
├───────────┬──────────────────────────────────┬────────────────────┤
│ 左栏       │ 中栏：CanvasView（主工作区）       │ 右栏：Agent 对话     │
│ 项目导航    │  八步节点泳道 + 自动连线           │ ChatStream          │
│ 资产中心    │  节点卡片=产物摘要/状态            │ （唯一驱动入口）     │
│ Skill(预留)│  点击节点→ProductViewer           │ GateCard（门内联）    │
│ 风格谱系    │                                  │ 输入框（可附文件）    │
└───────────┴──────────────────────────────────┴────────────────────┘
```

交互原则：**右栏对话是唯一流程驱动入口**；中栏画布是状态的只读渲染（节点自动连线）；左栏是导航与资产。前端不做任何"下一步/推进/重生成"的编排按钮（除用户在对话与门中自然表达）。

## 2. 中栏 · CanvasView（对应 Design CANVAS FLOW）

1. 按八步（0-7）布水平/泳道节点；节点状态：pending（灰）/ active（进行/高亮）/ done（完成/实心）/ invalidated（被推翻/描边警示）。
2. **边自动生成**：新产物节点出现时，按依赖（如 brief→outline→scenes→storyboard）自动连线，用户不手动画流程线。
3. 节点卡片显示：产物类型图标 + 标题 + 更新时间 + 摘要一行；大产物不内联。
4. 点击节点 → 打开 ProductViewer（复用现有通用查看器形态）读 `ref.path` 渲染 JSON/MD。
5. 有 pending 门时，相关节点高亮脉冲，引导用户看右栏 GateCard。
6. 媒体节点（图/视频/音乐）以缩略图/波形占位呈现，点击进资产详情。

## 3. 右栏 · ChatStream + GateCard（对应 AGENT MODE / OUTPUT SYNC）

1. 流式渲染 Agent 文本（text / reasoning 分轨，沿用 runtime 事件）；工具调用以折叠的"执行记录"展示（如 `file.write 故事大纲.md`），不把工具当聊天主体。
2. 产物以**引用卡片**出现（标题 + 类型 + 打开按钮），不内联大段内容、不复制两份正文。
3. **GateCard 内联对话流**：Agent 在关键节点主动发问；展示问题 + 选项按钮（批准/重做/修改方向…）+ 备注输入；用户裁决后卡片转为结果态，对话继续。
4. 输入框：文本 + 附件（策划文档/参考资料）；支持中途追加要求（对齐 Design"随时补充"）。
5. 版本回滚用对话式 checkpoint（"回到上一节点重生成"）替代现有散在的候选/修订/解锁前端机制。

## 4. 左栏 · 导航 / 资产 / 谱系

1. 项目导航：项目列表与当前项目；新建/切换。
2. 资产中心：图片/视频/音乐/工作流分类，来源本地/局域网产物；一键定位文件（对应 LOCAL INDEX）。
3. 视觉风格谱系：保留现有 StyleCatalog 入口。
4. Skill 广场 / 插件：本期仅占位预留（feature-026），不实现。

## 5. 设置 · ComfyUI 实例（自研补 Design 缺口）

1. 设置中可新增/编辑/删除/探活 ComfyUI 实例：名称 + baseUrl（本地/局域网）+ 启用开关，支持多实例。
2. 这是相对 Design 的关键差异点：**地址、端口可配，可连局域网**。
3. 显示实例健康与在途作业；不在前端直连，操作经主进程。

## 6. 关键交互流程（立项切片示例）

```
用户输入想法/丢文档
   → ChatStream 显示 Agent 理解 + 拆解
   → Agent file.read 上下文、自身推理诊断
   → gate.request(0-a) → GateCard 弹在对话流
   → 用户裁决 → Agent 继续 → brief 节点 done，下一节点 active，自动连线
   → （0-b/0-c/0-d 逐门）进入第 1 步
全程：前端无"请生成故事大纲"之类隐藏指令；所有推进是 Agent 自主 + 用户门裁决。
```

## 7. 视觉验收标准（方向）

1. 三栏信息层级清晰，画布为主、对话为驱动；不堆卡片、不暴露内部信封/错误结构。
2. 节点状态与连线变化可感知、有过渡；门的出现有明确引导。
3. 错误以可展示文案呈现（沿用错误码归一化），不出现凭证/端口口令。
4. 视觉语言与 MiniMax Design 同源克制（中性底色 + 状态色强调），媒体产物以内容为主角。
5. 具体配色/字号/组件规范在各切片 Feature 的 OD 中定稿。
