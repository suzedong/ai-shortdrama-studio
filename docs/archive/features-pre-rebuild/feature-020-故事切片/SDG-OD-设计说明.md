# SDG-OD 设计说明 · feature-020 垂直切片·故事（第 1 步）

> 状态：**v1.1 已闭环**（设计落地事实见变更记录；设计条款未变）
> 日期：2026-10-07
> 本切片无新建 B 类可视化稿；UI 在 feature-019 Studio 工作台上演进。本文档定义视觉结构与验收标准，事实以契约为准。

---

## 1. 设计目标

让新 Studio 工作台从"只呈现第 0 步"升级为"按步骤纵向呈现第 0、1 两步"，用户能在一张画布上看到立项 → 故事的推进与衔接，门卡/聊天交互保持不变。

## 2. 画布：从单步横向条 → 多步分组

### 2.1 现状（feature-019）

- `CanvasBoard` 第 28 行写死 `step==='0'`，节点单行横向排列；第 30 行只保留步内边；标题"第 0 步 · 立项画布"硬编码。

### 2.2 目标结构（本切片）

- 节点按 `step` 分组，组在纵向上堆叠；每组一行（横向排列，沿用现有节点卡样式与步内右向箭头）。
- 组与组之间用一条**竖向衔接**表达真实跨步骤 auto 边：

```
第 0 步 · 立项
 [选题诊断] → [视觉风格] → [立项单]
              │  (auto：step-0-brief → step-1-outline)
              ▼
第 1 步 · 故事
 [故事大纲] → [人物小传]
```

- 渲染规则：
  - 分组集合由画布实际节点的 `step` 去重得到（`['0','1']`），**不写死步骤**；未来第 2 步接入自动多一组。
  - 组内：沿用现有横向节点卡 + 右向箭头（步内 auto 边）。
  - 跨组：对 `canvas.edges` 中 from/to 分属不同 step 的 auto 边，在两组之间渲染一个竖箭头占位（不新增业务数据，仅呈现既有边）。
  - 空态：当无任何节点时保留现有空态；文案改为步骤无关表述（见 §4）。

### 2.3 节点卡

- 复用现有 STATUS_META（pending/active/done/invalidated）与节点卡样式。
- KIND_LABEL 增补：`outline → 故事大纲`、`profiles → 人物小传`。
- 节点卡不新增"通过/驳回"判定按钮——裁决只在门卡进行。

## 3. 门卡与聊天

- `GateCardView` 步骤无关、字段全部取自 CanvasGate，**不改**；1-a/1-b 自动复用。
- 聊天流沿用 ChatComposer；task 委派 writer 的内部过程不作为聊天主体，showrunner 在委派前后给出简短状态与交接物。

## 4. 文案改动（去立项硬编码）

| 位置 | 现状 | 改为 |
|---|---|---|
| `StudioApp` 标题 | 短剧立项工作台 | 短剧创作工作台 |
| `CanvasBoard` 组标题 | 第 0 步 · 立项画布 | 按组动态：`第 {step} 步 · {立项/故事}`（步骤名映射表） |
| `ChatComposer` 空态 | …依次请你裁决四道确认门 | 步骤无关：showrunner 会按当前阶段依次请你裁决确认门 |

- 步骤名映射：`0→立项`、`1→故事`（集中一张映射表，后续扩展）。

## 5. 视觉验收标准

| 编号 | 标准 |
|---|---|
| V-1 | 完成立项后进入第 1 步，画布在第 0 步组下方出现第 1 步组，两组间有竖箭头衔接。 |
| V-2 | 大纲/小传节点状态随产物推进实时变化（active→done），数据驱动、无手动刷新。 |
| V-3 | 门卡在聊天区正常弹出 1-a、1-b，样式与第 0 步一致；驳回后重开仍为同一门。 |
| V-4 | 画布无写死步骤：只有第 0 步数据时不出现空的第 1 步组；有第 1 步数据时正确分组。 |
| V-5 | 整体配色/字号/卡片风格与 feature-019 保持一致，不引入新的视觉体系。 |
