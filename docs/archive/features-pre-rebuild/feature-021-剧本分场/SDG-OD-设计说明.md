# SDG-OD 设计说明 · feature-021 垂直切片·剧本分场（第 2 步）

> 状态：**v1.1 已验收**（v1.1 未改视觉设计，仅同步契约行为；2026-10-07 真机验收通过）
> 日期：2026-10-07
> 本切片无新建 B 类可视化稿；多步分组画布已在 feature-020 落地，本切片只做增量接入。本文档定义视觉结构与验收标准，事实以契约为准。

---

## 1. 设计目标

让新 Studio 工作台从"呈现第 0、1 两步"增量扩展为"按步骤纵向呈现第 0、1、2 三步"，用户能在一张画布上看到故事 → 剧本的推进与衔接，门卡/聊天交互保持不变。

## 2. 画布：多步分组的增量接入（无结构改动）

### 2.1 现状（feature-020）

- `CanvasBoard` 已按节点 `step` 去重分组、纵向堆叠，组内横向节点卡 + 右向箭头，跨组竖箭头渲染跨步骤 auto 边；分组集合完全数据驱动。

### 2.2 本切片增量

```
第 1 步 · 故事
 [故事大纲] → [人物小传]
              │  (auto：step-1-profiles → step-2-scenes)
              ▼
第 2 步 · 剧本分场
 [第一集分场] → [第一集台词]
```

- 无需改分组逻辑：画布出现 `step:'2'` 节点后自动新增一组、自动在 1/2 组间渲染竖箭头。
- KIND_LABEL（CanvasBoard.tsx 第 14-20 行）增补：`scenes → 第一集分场`、`dialogue → 第一集台词`。
- STEP_LABEL（第 23-26 行）增补：`'2' → '剧本分场'`；组标题随之自动显示「第 2 步 · 剧本分场」。

### 2.3 节点卡

- 复用现有 STATUS_META（pending/active/done/invalidated）与节点卡样式，不新增。
- 节点卡不新增"通过/驳回"判定按钮——裁决只在门卡进行。

## 3. 门卡与聊天

- `GateCardView` 步骤无关、字段全部取自 CanvasGate（question/options/payload），**不改**；2-a/2-b 自动复用。
- 聊天流沿用 ChatComposer；task 委派 writer 的内部过程不作为聊天主体，showrunner 在委派前后给出简短状态与交接物。

## 4. 文案改动（仅增量映射，无新硬编码）

| 位置 | 改动 |
|---|---|
| `CanvasBoard` KIND_LABEL | 补 `scenes` / `dialogue` 两个键 |
| `CanvasBoard` STEP_LABEL | 补 `'2' → '剧本分场'` |

- 不新增其他文案；节点标题「第一集分场 / 第一集台词」由 showrunner upsert 节点时提供。

## 5. 视觉验收标准

| 编号 | 标准 |
|---|---|
| V-1 | 故事定稿后进入第 2 步，画布在第 1 步组下方出现第 2 步组，两组间有竖箭头衔接。 |
| V-2 | 分场/台词节点状态随产物推进实时变化（active→done），数据驱动、无手动刷新。 |
| V-3 | 门卡在聊天区正常弹出 2-a、2-b，样式与第 0/1 步一致；驳回后重开仍为同一门。 |
| V-4 | 画布无写死步骤：无第 2 步数据时不出现空的第 2 步组；有数据时正确分组。 |
| V-5 | 整体配色/字号/卡片风格与 feature-019/020 保持一致，不引入新的视觉体系。 |
