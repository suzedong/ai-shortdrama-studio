## 1. 判定口径

### 1.1 来源标签

- **[Design 原有]**：参考产品已有的用户可见功能或核心交互；本项目自主实现，不复制闭源代码、商标、私有素材、账号权限或云端服务。
- **[改编]**：保留参考能力目标，但按桌面本地优先、纯 JSON、局域网 ComfyUI、固定媒体通道或八步闭环调整形态 / 数据 / 权限。
- **[自研新增]**：为局域网媒体、完整短剧生产体系、证据追溯等本项目目标新增，不冒充参考产品原有能力。

### 1.2 当前状态与最终结论

当前状态只描述 P0 可证事实：

| 状态 | 含义 |
|---|---|
| **已有基础，未 Parity 验收** | 有实现或任务包证据，但尚未按本矩阵完成形态、数据、异常和真机对账。 |
| **部分对齐** | 仅部分子能力有实现或证据；不得由局部通过推断整域完成。 |
| **待复刻** | 已纳入路线，尚无完整实现；后续必须独立建包或修订既有包。 |
| **待产品裁决** | 存在产品取舍、在线服务或边界选择，未逐项获得用户批准。 |
| **自研闭环待实施** | 本项目必须补齐的短剧产物链，不计入参考产品已有完成度。 |

P7 最终每行只能转为：**已复刻 / 改编通过 / 经决策不纳入**。最终结论必须附 Feature 任务包与测试 / 真机证据；“有 UI”“有依赖”“参考模板存在”“单次演示成功”均不等于通过。

### 1.3 通用改编边界

| 维度 | 参考形态 | 本项目现行形态 | 影响 |
|---|---|---|---|
| 数据 | 云端账号、项目及本地 SQLite 等参考实现 | 本地项目目录 + 纯 JSON，无数据库 | 不照抄 SQLite / 云 Schema；需定义 JSON 版本、恢复、引用与迁移。 |
| 文本 Agent | 云端模型及专有 Agent 编排 | 用户自定义模型服务配置；现有 Provider 仍固定火山方舟 / LM Studio 二选一；OpenCode / MCP；系统优先 | 不依赖 MiniMax 账号或云端文本服务，不新增任意 Provider；不复用专有提示词，角色、工具和权限需逐包映射。 |
| 图像 / 视频 / 音乐 | 云端多模型矩阵 | 仅 H3 Image / H3 / Music3，全部经本地 / 局域网 ComfyUI | 不开放模型选择矩阵；需显式提示能力差异和不可用项。 |

**4.0.18 架构补证与选型（2026-11-26，D-041）**：静态包确认 v2 base profile 0.4.91、1 主 + 8 专用 Agent 与 9 个 Workflow，v3 base profile 0.4.108、3 Agent 与 Composition / Resource / Version；特定 clip-studio 连接器目录实测 2 个 Skill。v2 / v3 目录并存不证明运行时同时启用，2 个也不是运行时总 Skill 数。当前选型为 v2 生产编排骨架 + v3 Resource / Version 选择性语义，保留现有 4 profile、纯 JSON、OpenCode / MCP 和局域网 ComfyUI；详见研究报告 §2.7 与根设计 §2.2，不据此标记任何运行时 Parity 通过。

**D-042 业务流程与服务边界**：以 `drama-series` 连续剧 Workflow 为首要业务主线，尽量沿用其阶段、审核与生产语义实现完整 STAGE 0—7；v2 Plan / Stage / Work Item 仍是内部通用骨架，不取代 `drama-series` 业务流程。其他 Workflow 不要求九个无差别并行复刻。文本使用用户自定义模型服务配置，但现有 Provider 仍为火山方舟 / LM Studio；媒体继续本地 / 局域网 ComfyUI。账号、登录、用户、团队、成员及角色权限管理服务不建设，社区、积分、支付等仍独立待决。已有证据足够时直接复用，只有证据缺失、版本 / 行为变化或需关闭未知项时才真机调研；`drama-series` 当前为 4.0.18 静态证据，不冒称运行时验证。

## 3. 在线服务与商业能力边界及待决清单
