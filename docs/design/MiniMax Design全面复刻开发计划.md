## 1. 计划结论

全面复刻分为 **8 个阶段交付门（P0—P7）**，采用“先校准基线、再复用扩建、先跑通短剧闭环、再补齐完整产品面、最后统一验收发布”的顺序：

| 阶段 | 交付主题 | 核心结果 |
|---|---|---|
| **P0** | 基线裁决与现有任务包收口 | 全面复刻成为正式规范方向；现有实现、文档、测试和验收状态可信 |
| **P1** | 桌面工作台复刻 | 项目、创作页、画布、对话、资产引用和任务通知形成统一工作台 |
| **P2** | 统一媒体引擎与任务中心 | 局域网 ComfyUI 同时支撑 H3 Image 与 H3 视频，统一提交、恢复、重试和追溯 |
| **P3** | 八步视觉生产链 | 完成 STAGE 2-c → 3 资产 → 4 分镜 → 5 镜头，产出逐镜验收视频 |
| **P4** | 八步后期与发布 | 完成 STAGE 6 后期与 STAGE 7 发布，跑通 0—7 真实项目闭环 |
| **P5** | Agent、Skill、插件与本地模型生态 | 从硬编码入口升级为可创建、可配置、可执行、可追溯的真实能力 |
| **P6** | 专业创作与完整产品面对齐 | 按批准范围补齐 3D、浏览器、代码/网页、外部工具及在线能力 |
| **P7** | 全量 Parity 验收与发布 | 功能、八步闭环、局域网媒体、安全、安装升级和证据链统一验收 |

本计划不是推倒重来：

- 保留 Electron + React 18 + TypeScript + Vite + Tailwind CSS 技术栈。
- 保留现有项目 JSON、版本归档、画布命令/revision、OpenCode/MCP、ComfyUI 多实例配置和 H3 Image 持久任务。
- 优先完成短剧生产闭环，再扩展 Skill、插件、本地模型、3D 等完整产品能力。
- MiniMax 的 SQLite、双渲染栈和云服务是实现参考，不是必须照抄的技术方案。

## 2. 复刻目标与不变边界

### 2.1 复刻目标

1. **能力与体验复刻**：覆盖 MiniMax Design 的用户可见功能、核心交互、Agent 工作流、产物语义、任务恢复与版本追溯。
2. **自主实现**：采用现有代码、自研或经批准的开源等价组件；不复制闭源代码、商标、私有素材、账号权限或云端服务。
3. **短剧闭环优先**：任何通用能力都必须服务于或可追溯到一个真实创作流程，禁止只复制图标、菜单、卡片和空按钮。
4. **证据化完成**：每项能力最终只能标记为“已复刻”“改编通过”或“经决策不纳入”，不得以静态界面或单次演示代替验收。

### 2.2 不得被复刻计划突破的边界

- 完整保留 **0 立项 → 1 故事 → 2 剧本分场 → 3 资产 → 4 分镜 → 5 镜头 → 6 后期 → 7 发布**，不得合并、裁剪或跳过确认门。
- 图像仅用 **MiniMax H3 Image**，视频仅用 **MiniMax H3**，音乐仅用 **MiniMax Music3**；Agent 不得自行切换生成模型。
- 图像、视频、音乐全部经可配置的本地/局域网 **ComfyUI** 权重/工作流推理（B0/B5/B8/B9）；媒体生成零公网、无媒体云端 Key、无按次云费用。
- Renderer 不直连 ComfyUI，媒体调用统一收敛于主进程/MCP 引擎工具。
- H3 官方工作流内部使用其指定文本编码器，不构成 Qwen-Image 等生成通道回退。
- 确定性操作由系统直做；AI 只承担文本生成与开放式语义理解，双通道落同一数据模型和追溯机制。
- 未经新决策，不把“全面复刻”解释为允许更换数据库、增加文本 Provider、接入在线账号服务或改变语音/音乐通道。

## 3. 现有项目基线与增量判断

### 3.1 可复用基础

| 领域 | 已有基础 | 复刻策略 |
|---|---|---|
| 桌面壳与安全隔离 | Electron 主进程、Preload、Renderer 和 IPC 基础 | 保留并扩展导航、窗口、任务和创作页能力 |
| 项目管理 | 新建、列表、打开、改名、回收站、JSON 落盘 | 补齐自动创建、历史、导入导出、恢复与重联 |
| STAGE 0—2 | 立项、故事及剧本链大部分已实施 | 先校准状态，再收口 2-c 和后续依赖，不重写上游 |
| 会话与 Agent 运行 | 会话绑定、历史回放、SSE、停止、工具轨迹；四类 profile | 复用运行链，补齐角色路由、Skill/插件引用和结果导航 |
| 画布 | 缩放、平移、小地图、连线、吸附、命令事务、revision、原子 JSON | 从阶段列内拖动扩展为持久化自由画布和多画布 |
| 资产基础 | 索引、搜索、过滤和节点绑定 | 扩展为真实缩略图、分组、版本、引用和资产管理 |
| ComfyUI 配置 | 地址配置、多实例 CRUD/测连 | 补齐第二实例真机行为、健康检查、实例选择和恢复 |
| H3 Image | 幂等提交、持久作业、断点续查、下载校验、资产登记及 LAN 出图证据 | 保持通道不变，抽象公共任务能力供视频复用 |
| 设置与主题 | 工作目录、AI 服务配置、全局双主题等已有实施 | 先完成状态收口，再纳入统一工作台体验 |
| 测试基础 | Vitest、组件测试及多个专项测试 | 增加 Electron E2E、局域网双实例和安装升级测试 |

### 3.2 主要缺口

- STAGE 3—7 的资产定妆、生产分镜、逐镜视频、真实剪辑、声音与发布链尚未完成。
- ComfyUI 引擎的生产输出和收片逻辑仍主要面向 image，H3 视频生产执行未完成。
- 缺统一任务中心 UI；取消、局部重试、跨任务进度和结果回写未形成完整产品面。
- 画布尚非完整自由画布，多创作页、多画布、坐标和完整视口恢复不足。
- Agent UI 发送角色仍有固定路径，五类参考角色尚未完整映射。
- Skill、插件、本地模型、3D 等部分入口仍是硬编码卡片、开关或骨架。
- 完整 E2E、安装包、升级、卸载和回滚能力未建立。
- 任务包索引与包内状态存在漂移；本计划编制时**未重新运行全量测试或构建，不宣称当前基线全绿**。

### 3.3 旧规格与过期描述的处理

- 根设计及项目特化规则仍写“只补 MiniMax Design 两类缺口”，与“全面复刻”新方向冲突，必须由 P0 的 K7 正式修订。
- `feature-301` 规划中的 qwen-image 属于旧描述，后续建包按 D-033 使用 H3 Image，不恢复旧通道。
- `feature-803` 中 qwen-image 历史描述不得覆盖 `feature-816` 的 H3 Image 迁移结果。
- `feature-601` 中旧豆包 T2A 描述与“语音通道待定”不一致，须在实施声音功能前重新裁决。
- 文本 Provider 的项目特化条款与 `feature-014` 的方舟/LM Studio 实施存在口径差异，P0 只负责核对并统一事实源，不由本计划擅自选定新方案。

#### 统一实施约束

1. **保留现有底座**：Electron + React、OpenCode HTTP/SSE、主进程 MCP Streamable HTTP、纯 JSON、局域网 ComfyUI 和现有 4 个 Agent profile 不变；不引入 SQLite，不并存 v2 / v3 两套运行时，不全量替换为 Composition。
2. **Plan 不是权限**：showrunner 只能提出或修订 Plan 草案；主进程确定性服务负责结构校验、DAG、依赖就绪、状态迁移、预期状态与 revision CAS、Gate、重试、版本写入、恢复和精准挂脏。Agent 工具调用只是命令请求。
3. **主 Workflow 与八步不可裁剪**：以 `drama-series` 为业务流程主线，尽量沿用其阶段、审核、分集分镜、角色一致性与生产语义；v2 的 Plan / Stage / Work Item 仅作内部骨架。MiniMax 的 Script / Art Direction / Storyboard / Shots / Assemble / Export 只作参考，必须显式映射 STAGE 0—7，保留 0 立项与 7 发布及各步业务产物。
4. **恢复不伪造**：Replan 生成新 Plan 修订并经用户确认；稳定 Work Item 做局部重试；中断运行标为 `interrupted`，人工确认后创建新 Attempt，不伪装旧 Token 流续接。
5. **授权与验收不变**：本路线不直接批准共享类型、IPC / preload / MCP、依赖或 UI 代码，不修改 P0 已完成、P1 未通过和 P2—P7 当前门状态。每个 Change 仍须回负责包记录实际测试与真机证据，规划完成不等于 Parity 或产品验收通过。

## 5. 分阶段实施计划

### P0 · 基线裁决与现有任务包收口

**目标**：让方向、规范、代码现状和验收状态一致，避免在漂移基线上扩建。

**工作范围**：

1. 通过 K7 将项目必要性从“只补缺口”正式调整为“全面复刻”，同步项目特化规则与根设计，保留八步闭环及 ComfyUI 红线。
2. 按 D-032 编制形态映射影响矩阵，逐项标识 `[Design 原有] / [改编] / [自研新增]`。
3. 裁决或明确挂起：纯 JSON 与 SQLite 参考的关系、在线服务范围、音乐工作流、语音通道。文本 Provider 已由 D-021 / D-022 固定为火山方舟 / LM Studio 二选一，不再列为待裁决项。
4. 校准 201、803、815—817 等任务包索引、包内状态、变更记录和真机证据。
5. 清理 qwen-image、豆包 T2A 等过期描述；历史内容保留编年语义，不作为现行执行依据。
6. 运行并记录 typecheck、全量测试、构建和必要的 Electron 真机基线，区分历史失败、环境限制和新增失败。

**退出条件**：

- 规范、决策台账、任务包索引与包内状态一致。
- 每项复刻能力都能映射到一个 Feature 包或明确的“不纳入”决策。
- 基线测试有原始结果，失败有归类和负责人，不以“待验收”冒充“已通过”。
- 后续包所需的 K1/K8/K9 和外部依赖已被识别，但未被本阶段自动批准。

### P1 · 桌面工作台复刻

**目标**：形成可长期使用的统一创作工作台，而不是演示式三栏壳。

**复用**：Electron 壳、项目库、会话/OpenCode、画布 revision/命令事务、设置与工作目录。

**建设范围**：

- 开始创作、项目库、技能·插件、本地模型等一级导航及统一路由。
- 新建/自动创建项目、项目历史、编辑、导入导出和异常项目恢复入口。
- 多创作页、多画布、自由节点布局、连线/吸附、小地图、自动整理。
- 节点坐标、活动画布、创作页和视口持久化；重开后完整恢复。
- 画布/聊天左右互换、独立聚焦、结果定位、Diff Review 和任务通知。
- 资产中心基础管理、真实缩略图，以及对话/画布对资产的显式引用。
- 移除演示底栏、伪造开关和无后续行为的入口；未启用能力必须明确标记不可用。

**D-035 阶段需求口径**：

1. P1 以“可信工作台闭环”为边界，不扩成 P1 相关功能的全量 Parity；参考端差异逐项记录“实测行为、本项目行为、理由、来源标签、验收证据”，不设一律照抄或一律修正规则。
2. 自动整理前保存完整节点坐标与连线快照，整理作为一个组合命令；一次撤销恢复整理前整体布局，并可重做。P1 撤销历史不跨应用重启，持久化当前画布状态而非 undo/redo 历史栈。
3. 聚焦与结果定位统一执行正确的创作页／画布／视图切换，保证目标可见、选中并高亮；聚焦时弱化非关联节点，不得只移动视口或只调暗节点。
4. 文本 Diff 支持并排／统一视图；覆盖正式产物前展示基线版本、目标版本和差异，经用户确认后写入。媒体视觉 Diff 后置。
5. 基础导入导出采用静态完整项目包：包含项目、创作页／画布、资产、版本和正式会话，排除密钥、运行中执行与临时状态；重复导入默认建副本。导入会话只读，续聊新建本地会话并记录来源，不伪装原运行时会话无缝恢复。
6. P1 通知采用轻量统一入口，覆盖真实本地事件、未读／已读和结果深链；首批事件为项目导入导出、画布／产物写入结果、Diff 待确认、资产操作和系统异常。P2 在同一入口扩展媒体排队、进度、取消、失败与重试。
7. 页历史、跨页正式引用、完整快捷键／动画、完整媒体任务中心、项目归档／模板／迁移能力后置；后置项须保留明确目标或经决策不纳入，不得永久挂起。

**D-036 恢复与后置边界**：

1. 仅恢复类纳入 P1 扩展退出门：revision 冲突阻止静默覆盖并提供 Diff 选择；异常退出恢复最后有效状态，运行中执行标为“已中断”并保留日志，人工确认后重试；Agent 恢复历史现场，重试创建关联新运行，不伪装接续原 Token 流。
2. 页历史保持后置，目标为应用内轻量前进／后退，仅持久化最后位置，不跨重启保留完整浏览栈，不替代产物版本历史。
3. 跨页正式引用保持后置，目标为“产物 ID＋版本”，源产物再版只挂脏实际引用者，不自动覆盖。
4. 项目归档、模板、迁移分别建包：归档为默认列表隐藏、完整保留、只读可恢复；模板只含结构、配置和说明并实例化新项目与新 ID；迁移基于静态完整项目包执行 schema 版本与兼容性预检，默认建副本，不静默原地升级。

**退出条件**：

- 在真实 Electron 中可建项目、建创作页/画布、对话、上传并引用资产。
- 重开应用后，项目、创作页、活动画布、节点、坐标和视口均可恢复。
- revision 冲突（D-036）禁止静默最后写入优先；保留磁盘版与待提交版并展示文本 Diff，用户可重载磁盘版、另存副本或显式覆盖，追溯记录对应最终选择。
- 原子写失败和异常退出不破坏项目 JSON；重启恢复最后有效项目、画布和已落盘产物，运行中执行标为“已中断”并保留日志，用户确认后才可重试，不自动重新提交。
- Agent 现场恢复（D-036）保留消息、OptionCard、Gate 和产物状态；未决 Gate 继续等待人工拍板，未提交选项不代选；重试创建带血缘的新运行记录，不伪装接续原 Token 流。
- 所有可见一级入口都有真实行为、明确的未开放状态或已批准的不纳入说明。
- 手动连线新增／删除、自动整理整体快照撤销／重做均有专项证据；异常整理不丢失用户布局。
- 聚焦、通知和资产结果深链均能定位到正确创作页／画布／节点或资产，目标可见且高亮。
- 文本 Diff 的并排／统一视图、基线／目标版本和写入前确认经真机验收，取消确认不覆盖正式产物。
- 静态完整项目包完成导出、重复导入建副本、排除敏感／运行状态、只读会话导入与新建会话续聊的恢复测试。
- 轻量通知的真实事件、未读／已读、跨重启保留和结果深链有证据；未实施的媒体任务状态不得伪造。

### P2 · 统一媒体引擎与任务中心

**目标**：把已有 H3 Image 单链能力升级为图像/视频共用、可恢复、可追溯的局域网媒体执行层。

**复用**：803 的 ComfyUI 引擎、816 的 H3 Image 生产迁移、多实例配置、幂等提交、持久作业、续查、下载校验和资产登记。

**建设范围**：

- 将作业输出、下载校验、收片和资产登记从 image 泛化到 image/video，保持类型和路径安全。
- 接入 H3 B5 参考生视频、B8 文生视频；复用既有 H3 Image B0/B9，不另建平行图像通道。
- 统一任务中心：参数确认、排队、进度、取消、失败详情、局部重试、断点续查和结果定位。
- 多实例选择、健康检查、占用/故障状态与恢复；实例不可用时禁止静默切换模型或云端。
- 任务结果回写画布、资产索引和对应业务产物，保留输入、seed、工作流、模型/节点版本、prompt_id、日志和输出哈希等追溯信息。
- 主进程重启后的作业恢复、重复提交防护和孤立输出处理。

**退出条件**：

- 至少两个真实局域网 ComfyUI 实例分别完成连接、图像和视频验收，多实例行为有证据。
- 主进程重启后可续查，不重复提交；单任务失败可按稳定任务 ID 局部重试。
- 图像、视频产物均通过格式、大小、路径和内容校验，并正确回写画布与资产中心。

### P3 · 八步视觉生产链（STAGE 2-c—5）

**目标**：从已定稿上游生成可用资产、生产分镜和逐镜验收视频。

**实施顺序**：`201 状态收口 → 301 角色定妆 → 302 场景与道具 → 401 生产分镜 → 501 逐镜视频`。

**建设范围**：

1. **201 收口**：完成分镜文字稿及 2-c 验收，统一其“部分落地/已实施”口径。
2. **301 角色**：角色卡、定妆、参考图、seed/提示词等一致性配方，资产选定、版本和引用。
3. **302 场景与道具**：复用主风格和一致性配方，形成可复用场景/道具资产。
4. **401 分镜**：在 201 的 shotlist 同文件演进，补齐 refs、景别、运镜、逐镜时长和台词对位。
5. **501 镜头**：Scene Keyframes、稳定 `work_items[].id`、有序 refs、最终 Prompt、依赖、锁项和 review 字段，逐镜生成与收片。

7. **失败纪律**：禁止相同实质参数循环；最多三次实质差异尝试；按稳定 work item 局部重试；拓扑变化 Replan；不得擅自换模型、放宽锁项或整阶段重跑。

**固定业务门**：`3-assets`、`4-final`、`5-all-shots`，并完整保留上游 `0-final`、`1-a/1-b`、`2-a/2-b/2-c`。

**退出条件**：

- §4.1 通用 Workflow / Plan 与 Resource / Version 底座已按负责包验收，八步 Stage、产物版本、Gate 与运行记录共用同一事实源。
- 一个真实项目能从已批准上游走到全部镜头 MP4 验收。
- 生成只读已定稿上游；分镜未定不能排镜；锁定资产/分镜不可被 Agent 静默修改。
- 每个产物有版本、上游引用、生成参数、任务记录和确认记录。
- 单镜失败不引发整阶段重跑；重试、Replan 和人工介入均有追溯。

- 任一成片可追溯到镜头、音频、字幕、剪辑参数和批准版本。

### P5 · Agent、Skill、插件与本地模型生态

**目标**：在 §4.1 既定 Workflow / Plan 底座上，将硬编码生态入口变为真实可执行能力，同时保持系统优先与媒体红线。

### P6 · 专业创作与完整产品面对齐

**目标**：在短剧闭环稳定后，按批准范围补齐 MiniMax Design 的其他专业创作域。

**退出条件**：

- 每个已启用功能都有至少一条真实端到端用例和产物证据。
- 跨工具调用有权限、失败、取消和结果回写，不只展示第三方名称或图标。

**目标**：建立完整复刻账本、质量证据和可交付桌面产品。

**建设范围**：

- 完成使用说明、已知限制、不纳入清单和验收证据索引。

**退出条件**：

- 每个复刻项均为“已复刻”“改编通过”或“经决策不纳入”，不存在无决策缺口。

- 发布候选不存在伪造完成项、未说明的历史失败或只验证成功路径的关键能力。

## 6. MiniMax 短剧工作流与八步闭环映射

MiniMax 的短剧阶段和 4.0.18 v2 通用六段链路只用于借鉴执行计划、双确认门和失败恢复机制，不替换本项目八步业务模型：

## 7. 依赖关系与并行原则

```text
P0 → P1 → P2 → P3 → P4 → P7
              │
P1 → P5 ──────┤
P2 → P5 → P6 → P7
```

阶段是**交付门**，不是所有设计工作的严格串行限制：

- 301、401、501 的规格可在 P1/P2 期间提前设计和评审。

- P6 不得阻塞 P3/P4 的短剧闭环；P7 的测试、证据和发布工程应贯穿各阶段持续积累。
