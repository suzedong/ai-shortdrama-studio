01

为什么做这个软件

不是另起炉灶，而是精准填补 MiniMax Design 的两个缺口——除此之外不做功能扩张（2026-10-04 用户拍板的项目必要性原则）。

GAP ①

无法调用本地 / 局域网 ComfyUI

Design 只能走云端模型矩阵：按次付费、限流、素材必须上公网，无法利用本地 GPU 与已有工作流资产。

→
GAP ②

不具备旧体系的完整生产闭环

从立项、故事、分场、资产、分镜、镜头到后期、发布的 8 步业务链，Design 没有完整覆盖。

→

本项目的答案

ComfyUI 做统一媒体引擎（地址可配、局域网多实例）＋ 8 步闭环一步不裁剪。形态对齐 Design，底层全部用开源同源组件（opencode / MCP / Skill）自行实现，不碰其闭源代码。

计划怎么实践

用 SDG 规格驱动治理约束"怎么写"，用绞杀者模式约束"怎么换"，用三期路线约束"走到哪"。

3.1 SDG 治理：No Spec, No Code

壹

No Spec No Code

没有任务包三件套（需求规格/契约/任务清单），不准写业务代码

贰

Spec is Truth

文档与代码冲突时错的一定是代码，以文档为准修正

叁

Reverse Sync

发现 Bug 或变更，先改文档再改代码

十个决策卡口（K1–K10）：触发即暂停、说明、等签字、留永久记录

K1 改共享层 shared/K2 技术偏离 K3 旧系统改造/退役K4 新顶层实体 K5 术语/命名K6 新业务模块/目录 K7 改 AGENTS 核心规则K8 破坏接口契约 K9 新核心依赖K10 大规模禁用规范
