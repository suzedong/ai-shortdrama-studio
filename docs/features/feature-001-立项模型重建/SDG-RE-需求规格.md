# feature-001 立项模型重建 · 需求规格

> 任务包性质：**新规格落地 + 旧模型清退**（非纯反向补录）。旧 22 包已随 D-005 作废（见 [docs/archive/README.md](../../archive/README.md)），本包按设计基线 v1.11 §2.6 / §7.1 重建 STAGE 0。
>
> 事实源：[短剧Agent平台设计.md](../../../短剧Agent平台设计.md) §2.6（L116–347）、§7.1（L546–600）；字段契约以 [shared/types.ts](../../../shared/types.ts) 为准。
>
> 解决偏差：[设计现状与偏差清单.md](../../设计现状与偏差清单.md) **B-01**（确认门模型旧残留）、**B-02**（立项产物命名）。

## 1. 背景

旧立项模型「4 节点（创意输入→选题诊断→立项单→故事背景档案）+ 4 确认门（0-a~0-d）」经《2002 相识》流程推演确认与真实生产实践不符，已随决策 **D-005 作废**；设计书 v1.11 已重写为「**1 个入口动作 + 2 个节点 + 1 道定案门**」。

磁盘实况（2026-10-13 盘点）：

- 运行时代码（GateBridge / MCP / IPC / GateCardView）对门 id **零硬编码**，门 id 全链路是动态字符串——改门编号对门机制零冲击。
- 旧门 id 仅固化在三处：`shared/types.ts` 的 `GateId` / `RevisionSource` 类型、`showrunner.md` 提示词、4 个测试文件。
- 立项版本化落盘（`立项单.vN.json`）平台侧**无实现**；旧 prompt 让 Agent 用通用 `file.write` 写 `立项/brief.json`。
- 新模型 UI 静态壳 `Stage0View.tsx` 已存在（1 入口 + 2 节点 + 定案门弹层，零 IPC）。

## 2. 谁在什么场景下要做什么

| # | 角色 | 场景 | 要做什么 | 达成效果 |
|---|---|---|---|---|
| R1 | 创作者 | 说出一句话创意（如「做我和老婆 2002 年认识的故事」） | 主控 Agent **先反问关键分叉**（商业短剧 / 个人纪念），同时把创意中可直接提取的事实先记录 | 不直接开干；从第一句话起「已捕获口径」持续累积 |
| R2 | 创作者 | 立项对话中 | 随时可改任何已捕获内容（六要素 / 故事前提 / 视觉风格），无锁、无 disabled | 对话式收敛，不是填多 tab 表单 |
| R3 | 主控 Agent | 节点①选题诊断 | 产出选题诊断卡 + **六要素口径草案**（全部预填、全部可改），区分商业 / 纪念详略 | 创作者「看草案、直接说改什么」 |
| R4 | 主控 Agent | 节点②故事前提 | 以「先编假版本引真人真事」或「先问关键事实」方式，对话收敛故事前提，沉淀背景档案 | 达到 5 项最低门槛（人物 / 时间 / 地点 / 核心事件 / 边界） |
| R5 | 主控 Agent | 视觉风格 | 按题材从《视觉风格谱系》匹配 1 个主风格（记录「风格 ID + 谱系版本」），可选 1 个辅助气氛；不自创画风 | 主风格选定是定案就绪条件之一 |
| R6 | 系统 | 就绪条件满足 | Agent 主动发**立项定案卡**（一道门 `0-final`），卡上显式列六要素、故事前提、主/辅风格、相对上一版改动 | 一键拍板 |
| R7 | 创作者 | 定案卡 | 点「发布立项 v(N+1)」**或**在对话里口头说「行，开始讲故事吧」 | 两者等价；`立项单.v(N+1).json/.md` 落盘、旧版全量留底、进入 STAGE 1 |
| R8 | 创作者 | 未就绪 | Agent 不发定案卡，明确指出还差什么（如「还差故事边界：这季讲到哪？」） | 缺料显式化，不静默定案 |
| R9 | 创作者（后续 STAGE） | 立项后要改字段 | 全字段可改 → 属 **B-03 / P1 立项后变更**，**不在本包范围** | 本包只保证 v1 定案与版本留底；影响评估面板、`影响清单.vN→vN+1.json`、脏读标记留给 P1 |

## 3. 就绪条件（定案门的客观判定，全部满足）

1. **六要素均有取值**——`genre / platforms / episodeDuration / episodeCount / tone / aspectRatio`。「待定」视为有值，但必须在六要素中以字符串 `待定` 显式表达，定案卡向用户明示待定点。
2. **故事前提达到最低门槛 5 项**——主角身份年龄（双方）、时间、地点、核心事件一句话、本季边界，五项均非空字符串。
3. **已选定 1 个主风格**——`mainStyleId` 非空（谱系 ID，如 `A7`；谱系版本 `catalogVersion` 如 `v1.46`）。

## 4. 范围

### 4.1 本包做（P0）

- 共享层类型：新门 id 模型、立项单 `ProjectBrief` v2 schema、故事前提、定案记录、就绪检查结果类型。
- 主进程新增立项 MCP 工具族：`brief.plan`（就绪校验 + 缺失项 + 相对上一版 diff）、`brief.publish`（版本化落盘，绝不覆盖）、`brief.list`（历史版本）。
- 落盘约定：项目根目录 `立项单.vN.json`（事实源）+ `立项单.vN.md`（人读镜像）；`故事背景档案.md` 独立成文。
- `canvas.update` 挂第 0 步单一产物节点 `step-0-brief`（由 publish 工具一并完成，Agent 无需手拼）。
- showrunner.md：重写第 0 步立项剧本（反问 → 诊断 → 前提 → 风格 → 唯一定案门 → 发布），第 1/2 步输入改指最新立项单。
- 渲染端术语对齐：「创意简报 / brief.json」旧措辞改为「立项单」；StudioViewer 适配新 schema。
- 旧门 id / 旧契约测试同步改写；门机制测试（gate-bridge）不动。

### 4.2 本包不做（显式排除）

- **B-03 立项后变更影响评估**（P1）：`manifest.briefVersion` 依赖图、`parentReference.fields`、影响清单、三选一面板、脏读角标。本包只在立项单内留 `approve` / `changesFromPrevious` 数据位。
- **B-04 manifest.status 7 态推进**（P1）：本包不改 manifest 结构，publish 不写 status 推进。
- **B-05 视觉风格谱系实现**（P1）：本包不重建 `style-catalog.ts`、不做「风格 ID 必须在谱系内」的平台侧强校验（Agent 提示词层负责从谱系选取）。
- Stage0View 静态壳接真 IPC（定案卡弹层 / diff 视图 / 历史回滚 UI）：P0 链路以 ChatComposer 既有 GateCardView 为裁决入口；Stage0View 接线随立项视图专项包。
- 口头拍板的 NLP 意图识别：平台不做语义识别，由 Agent 理解用户口头确认后携带 `verbal: { quote }` 调 publish 落痕。

## 5. 验收（业务层）

- AC1：新项目里对 showrunner 说一句话创意，Agent **第一轮先反问**商业/纪念，且不产生任何门与落盘。
- AC2：对话收敛过程中，未满足就绪条件时调 `brief.plan` 返回 `ready:false` 与逐项缺失原因；Agent 不报定案门。
- AC3：就绪后 Agent 只发 **一道**门 `0-final`（不再出现 0-a/0-b/0-c/0-d）；用户批准后 `立项单.v1.json` 与 `立项单.v1.md` 落项目根目录，画布出现 `step-0-brief` done 节点并带 `meta.version='v1'`。
- AC4：用户口头确认（Agent 携带原话调 publish）与点门批准落盘结果完全等价，立项单内 `approve.verbal.quote` 记录用户原话。
- AC5：再次发布生成 `立项单.v2.json/.md`，v1 文件仍在且内容不变（绝不覆盖、不进 `版本/` 归档区）；定案记录含相对 v1 的字段 diff。
- AC6：第 1/2 步 Agent 的必需输入解析到「最新版本立项单」，提示词中不再出现 `立项/brief.json`。
- AC7：仓库生产代码与提示词中不再出现旧门 id `0-a/0-b/0-c/0-d`（`2-a/2-b/2-c/1-a/1-b` 保留）。
