## 1. 背景

设计书 §2.6.2 明示选题诊断的信息来源：

- 「主控 Agent **基于已捕获口径检索同赛道公开数据**，产出选题诊断卡」；
- 诊断卡五区块：**同赛道对标案例 / 用户洞察 / 爆点钩子模式库 / 合规风险 / 结论**——其中「对标案例」「钩子模式库」本质依赖平台公开数据（各平台在榜/热播短剧），模型内置知识有时效与编造风险；
- 同节口径：商业类按五区块全量产出；**纪念类弱化**（风格参考性质，可直接判「可做」）。

代码实证（2026-10-19 盘点）：[showrunner.md](../../../resources/opencode/agents/showrunner.md) 第 0 步 step 3 现为「基于已捕获口径**自身推理**产出选题诊断卡」，无任何检索通道；`SHOWRUNNER_DECLARED_TOOLS`（[provider.ts](../../../electron/runtime/provider.ts) L45-66）20 个白名单无 web 工具；`@opencode-ai/sdk` 1.18.34 客户端类型层无 webfetch/websearch 定义——**opencode 服务端是否内置可用 web 工具未证实**，此为通道选型的关键未知项，不臆造。

**隐私边界外扩（§12）**：现平台出公网仅文本侧火山方舟；检索会把项目题材关键词带出公网。纪念类项目涉私人记忆，检索词必须脱敏、默认不检索。

**原则对齐（D-016）**：检索与诊断 = 开放式语义理解，归 AI（Agent 通道）；平台侧只做工具面放行与纪律约束，零确定性逻辑新增（无 renderer、无 IPC、零 diff 于 brief/gate/canvas 体系）。

## 2. 角色与场景

| # | 角色 | 场景 | 期望表现 |
|---|---|---|---|
| R1 | 创作者 | 商业类立项，六要素口径已捕获，进入选题诊断 | showrunner 以口径题材关键词组检索词发起检索，诊断卡「对标案例/用户洞察/钩子模式」基于真实公开数据，卡尾附「检索来源」（检索词 + 来源 URL + 日期） |
| R2 | 创作者 | 纪念类立项进入诊断 | showrunner 按设计书弱化口径直接判「可做」，**默认不发起检索**；用户明示「也帮我查查同类」才检索，且检索词仍守脱敏纪律 |
| R3 | 创作者 | 查看诊断卡 | 卡尾「检索来源」区块可逐条核对：用了哪些检索词、数据来自哪些 URL、检索日期——可证伪、可追溯 |
| R4 | Agent | 构造检索词 | 仅取口径中题材类型维度字段值（genre/platforms/tone 等）+ 泛化赛道词；**禁用** leads/coreEvent 原文、用户逐字原话、任何私密细节 |

## 3. 核心机制

### 3.1 通道选型：探测前置双方案（T0 定案）

| | 方案 A（主） | 方案 B（降级） |
|---|---|---|
| 通道 | opencode 服务端内置 web 工具（占位名 `webfetch`/`websearch`，实际 ID 以 T0 探测为准），经 `SHOWRUNNER_DECLARED_TOOLS` 白名单放行 | 自建 MCP 工具 `shortdrama_web.search` / `shortdrama_web.fetch`（主进程原生 fetch，25→27） |
| 成本 | 白名单 +N + 静态测试扩表，最低 | 新工具实现 + 搜索源选型（零 Key 优先），最高 |
| K9 | 零触发 | 零依赖优先；须引依赖则停手补登 |

T0 探测方法：① 查 opencode-ai 1.18.34 包内服务端内置工具清单（源码/文档）；② 起 opencode serve 实测工具列表；③ 试跑带白名单会话验证可调用且返回可用结果。三者结论与证据回写变更记录，定案 A 或 B；走 B 时本包契约 §2.2 补登工具契约后实施（不停手重报，D-001 已双方案预登）。

### 3.2 检索词构造纪律（契约级硬规则，落 showrunner.md）

- **只取题材类型维度**：`genre / platforms / tone / episodeDuration / episodeCount / aspectRatio` 等口径字段值 + 泛化赛道词（如「甜宠短剧 抖音 热播榜」）；
- **禁用**：`leads`（人物）与 `coreEvent`（核心事件）原文、用户逐字原话、姓名/地名/日期等私密细节；
- 纪念类：默认不检索；用户明示要求时仍守上两条。

### 3.3 诊断卡来源标注（落 showrunner.md）

诊断卡五区块结构不变（§2.6.2），卡尾增「检索来源」附录：检索词列表 + 来源 URL 列表 + 检索日期；未检索（纪念类弱化/检索失败降级）时附录显式标注「本次未联网检索」。标注随既有 `diagnosisDetail` 落盘机制入立项单（D-018，零新代码）。

## 4. 范围

### 4.1 做

1. T0 探测定案并回写变更记录（A/B 路径 + 证据）；
2. 方案 A：`electron/runtime/provider.ts` `SHOWRUNNER_DECLARED_TOOLS` 白名单 +N（实际 ID 以探测为准）+ 注释沿革；方案 B：`electron/mcp/tools.ts` +2 工具（契约 §2.2 补登后实施）；
3. 指令层：[showrunner.md](../../../resources/opencode/agents/showrunner.md) step 3 修订（自身推理 → 检索+推理；检索词脱敏纪律；来源标注纪律；纪念类默认不检索；检索失败能力诚实降级）；feature-001 变更记录按序回写（R-007）；
4. 单测：`src/test/agent-profiles.test.ts` 物理工具真键表随白名单正当扩表（工具面变更的对应更新，非断言语义变更）；方案 B 时增工具注册与形状用例；
5. 治理收尾：README 总表增 006 行、偏差清单 B-39 登记、版本记录增行。

### 4.2 不做（显式排除）

- 不改诊断卡五区块结构；不改 `electron/brief/*`（来源标注随 diagnosisDetail 既有落盘机制，零新代码）；
- 零 renderer、零 IPC、零 shared/types.ts 变更（纯 Agent 面 + 指令层）；
- 不给 writer / media-director / comfyui-operator 放行检索工具（选题诊断是主控 Agent 专属职责）；
- 不做检索结果缓存 / 历史库 / 评分排序；
- 方案 B 不接付费搜索 API、不引入 Key 管理（零 Key 优先，搜索源选型停手补登）；
- 不做「检索到的对标案例」结构化落盘（诊断卡文本承载，结构化资产属后续演进）。
