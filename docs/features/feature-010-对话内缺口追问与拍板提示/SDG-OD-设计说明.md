# feature-010 设计说明：对话内缺口追问 chip 与发卡拍板提示（qh）

> **版本**：v1.0（2026-10-23）
> **上游**：feature-010 需求规格 v1.0 / 契约 v1.0
> **本文件性质**：记录 D1-D7 关键取舍与决策卡口自查；不重复契约逐字内容

## D1 · 新增【追问选项】块，而非复用【选项】编号块

- **取舍**：为缺口追问快答新增独立块协议（纯文本行、无编号），与【选项】【风格选项】三足并行。
- **依据**：① 原型 chip 无编号、文字即取值，用户拍板「代发 chip 文字原文」——编号协议与语义相悖；② 纪律 9 已有【缺口追问】**气泡标签**，若块名复用「缺口追问」则标签/块同名混层，故块名定【追问选项】（与【选项】【风格选项】平行词族，命名空间分离）；③ parseChatOptions 三分支结构天然支持按块名分派，扩展面仅五处（契约 §2.2）。
- **备选否决**：复用【选项】+ 代发编号——否决：用户须说「1」而非自然语，quote 逐字落盘语义弱（纪律 11 要求 source:'user' 带原话）；改造【选项】兼容无编号行——否决：破坏 B-35 已验收真值表，既有测试面临回归。

## D2 · 点击代发 chip 文字原文（所见即所发）

- **取舍**：`onSend(chip原文)`，与手打同路径。
- **依据**：用户拍板项 §2-3；chip 原文即用户话语，capture.upsert source:'user' quote 逐字天然满足纪律 11；Agent 侧零适配（收到的就是正常用户消息）。
- **备选否决**：代发编号 / 代发结构化标记（如 `[chip:3]`）——否决：引入第二条发送语义路径，Agent 需额外解析，违 D-016「同一数据模型」。

## D3 · 点击路径直接复用 pickOption，零新增发送逻辑

- **取舍**：ChipRow 的 `onPick` 直接传既有 `pickOption`（其本体即 `(text) => { if (busy) return; onSend(text) }`）。
- **依据**：pickOption 参数语义本就是「代发文本」，B-35 传编号、本包传原文，行为完全一致；busy 拒点逻辑同源复用，无双通道漂移风险。
- **备选否决**：新建 pickChip 包装——否决：纯转发零增量，违最小复杂度原则。

## D4 · qh 系统直做自动追加，触发 = pendingGate.gateId === '0-final'

- **取舍**：渲染层条件挂载固定文案 GateHint，零指令新增、零 props 新增。
- **依据**：用户拍板项 §2-4；取证确认「就绪 · 发卡」在实现层 = showrunner 剧本 7 调 `gate_request({gateId:'0-final'})` → pendingGate 经 GateCardView 两挂载点渲染——触发条件完全确定性（gateId 枚举判定），合 D-016「能写成枚举规则 → 系统做」；文案固定避免 Agent 措辞漂移。
- **备选否决**：指令层约定（showrunner 输出特定标记 → 渲染层识别）——否决：多一条指令协议、多一处漂移面，且 Agent 可能漏发；qh 挂全部 gate——否决：仅 0-final 门存在「口头拍板」双前提语义（纪律 8），其他门（如资产确认门）无 verbal 路径，挂之误导。

## D5 · picked 语义文字版 [改编]

- **取舍**：chip picked 判定 = 紧随用户消息 `text.trim()` 与 chip 原文**全等**；picked 紫底白字，同组其余 consumed 禁用。
- **依据**：B-35 pickedNum 哲学的文字版平移（编号全等 → 原文全等）；原型 chip 点击后同组 opacity .4 + pointerEvents none（L2285-2288）仅演示「全置灰」，未区分 picked——本包区分 picked 与 disabled，信息更明确，标 [改编]。
- **备选否决**：原型式全置灰不区分——否决：用户无法确认自己选的是哪条；模糊匹配（包含/去标点）——否决：引入不确定判定，违可复现原则。

## D6 · qh 文案 [改编]：原型口令 → 纪律 8 真实口令

- **取舍**：正文口令「行，开始讲故事吧」→「行，就按这版发布」。
- **依据**：showrunner 剧本 8 / 纪律 8 的 verbal 拍板真实口令为后者（双前提：完整定案卡已展示 + 原话针对该版）；原型文案系 demo 示意，若照抄将引导用户说出无法触发拍板的无效口令——便利组件反而制造失败路径。
- **备选否决**：双口令并列——否决：文案膨胀，且「开始讲故事」在 0-final 门语境无对应动作。

## D7 · 测试策略：新建恰 1 文件、解析行为经渲染层断言、导出面零 diff

- **取舍**：新建 `chat-chips.test.tsx`（净增恰 1，60→61）；parseChatOptions 保持模块私有，全部解析行为经 ChatComposer 渲染层凭据断言。
- **依据**：与 chat-markdown.test.tsx 既有测法同哲学（该文件即经渲染断言解析行为）；新增导出仅为测试便利性而改动导出面，违最小 diff；渲染层断言同时覆盖「解析 + 组件接线」两段，一次断言双重保障。
- **备选否决**：导出 parseChatOptions 单测——否决：导出面 diff 无谓扩大；并入既有 chat-markdown.test.tsx——否决：该文件零 diff 是本包回归保障承诺，并入即破坏承诺基线。
