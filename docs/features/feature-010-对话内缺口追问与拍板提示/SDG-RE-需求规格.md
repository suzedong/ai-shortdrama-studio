## 1. 背景与问题

### 1.1 设计书逐字依据

《短剧Agent平台设计.md》§2.6.8（L381）：

> 每轮提取后，若 capture.json 仍有缺口（missing 非空），**Agent 主动追问**；问法按缺口主题组织（如"主角想要什么？他怕什么？"）。

原型 `docs/design/短剧Agent平台-原型.html` 同区（L1806-1823）呈现两形态：

- **缺口追问 + chip 快答**：气泡标签「缺口追问」+ 横向胶囊按钮组（`.cr .chip`：`<button class="chip">第一季只讲相识</button>` / `<button class="chip ghost">讲到确定关系</button>`），点击即代答；
- **发卡拍板提示 qh**：气泡标签「就绪 · 发卡」+ 琥珀提示条（`.qh`：标题「💡 拍板提示」+ 文案「直接说『行，开始讲故事吧』= 按钮拍板（系统记录原话与定案卡版本）」）。

### 1.2 缺口登记（B-35 遗留切片逐字引用）

`docs/设计现状与偏差清单.md` L67 末段（feature-008 变更记录 X-001 同录）：

> 遗留：…**对话内追问的快捷答复 chip、发卡卡内拍板提示（qh）两处对话层便利组件未实现**…「GateCard 折叠为条（1 步）/ 头签 chips（1 步）/ 追问快捷答复 chips（1 步）」…「发卡卡内拍板提示（qh）：渲染层便利组件（系统直做追加或指令约定皆可）」。

### 1.3 现状磁盘实况（建包前取证，全部只读验证）

- `src/studio/ChatComposer.tsx`：`parseChatOptions` 仅识别【选项】【风格选项】两类编号块（L128-197）；渲染层仅有 OptionCard 竖排卡片组件，**无横向胶囊组件**；「拍板提示 / qh / data-chat-chip / data-chat-gate-hint」全 src 零匹配（已 Grep 验证）。
- `resources/opencode/agents/showrunner.md`：纪律 9（L92）气泡标签词表已含【缺口追问】【就绪 · 发卡】；纪律 10（L93）首句已枚举「缺口追问快答」但**无对应块格式约定**——指令侧有词汇无协议。
- 0-final 门（「就绪 · 发卡」的实现形态）：showrunner 剧本 7（L125）调 `gate_request({gateId:'0-final', question:定案卡, ...})` → 前端 `pendingGate` 经 GateCardView 两挂载点渲染（ChatComposer L651-653 流式气泡内 + L668-675 独立块）——**qh 触发条件可纯系统判定，零指令负担**。
- Stage0View 卡①（published 只读态）：L475-515 五区块全展开、六要素只读——与设计书 §2.6.8 L378「可折叠/内嵌可改」差异属实，**本包仅备案，不在范围内**（用户拍板 B 优先）。

### 1.4 问题陈述

1. Agent 追问缺口时，用户只能手打整句答复——原型设计的**一键快答胶囊**缺失；
2. 定案卡（0-final 门）呈现时，新用户不知可**口头拍板**（纪律 8 verbal 双前提）——原型设计的**拍板提示条**缺失；
3. 指令侧「缺口追问快答」有词汇无协议，Agent 无法发出结构化快答。

## 3. 范围

### 3.1 做（本包交付）

1. **【追问选项】块协议**：每行一条候选答复纯文本无编号，≥2 条，必须位于消息末尾（允许尾部空白）；行首识别开/闭标签；流式未闭合 / 键入半截开标签 → pending（沿用 parseChatOptions 既有哲学）。
2. **`parseChatOptions` 扩展**（ChatComposer.tsx）：闭标签正则加 `追问选项`；开标签正则同步；tail pending 加半截判定；返回签名加 `chips?: string[]`（每非空行 trim 后即 chip 原文，不经 OPT_LINE 编号解析；<2 行整块不识别原样显示）。
3. **`ChipRow` 组件**：横向 `flex flex-wrap` 胶囊，样式对齐原型 `.cr .chip`；picked=紫底白字（紧随用户消息 `text.trim() === chip 原文`）；disabled=opacity-40（consumed 语义复用 B-35）；点击复用 `pickOption`（`onSend(chip原文)`，busy 拒点）。挂载点与 OptionCard 平行（items 渲染消费点 + 流式气泡，共两处）。
4. **`GateHint` 组件（qh）**：零 props 固定文案琥珀条；触发 = `pendingGate?.gateId === '0-final'`；挂载于 GateCardView 两挂载点之后（流式气泡内 + 独立块，共两处）。
5. **指令层**：showrunner.md 纪律 10 增补第三种子块约定（缺口追问快答 →【追问选项】胶囊块）；qh 零指令新增。
6. **demo**：demoChatItems 追加 d9（【缺口追问】标签 +【追问选项】chips 待答演示）。
7. **测试**：新建 `src/studio/chat-chips.test.tsx`（测试文件净增恰 1，60 → 61）；既有测试全零 diff。
8. **治理收尾**：偏差清单 B-45 落表翻 ✅；docs/features/README.md 0xx 段增行；变更记录 T 序列回填。

### 3.2 不做（显式排除）

- 卡①折叠 / 六要素内嵌直改（候选 C 内容，仅备案，待用户另行指示）；
- `chip.ghost` 次级样式变体（原型仅一处演示用，无语义依据）；
- 块内编号混合格式（【追问选项】= 纯文本行，编号行一律走【选项】）；
- qh 挂 0-final 以外门 / qh 文案 Agent 可控化（系统直做固定文案，避免双通道漂移）；
- K1（shared/types.ts 零改）/ K8（IPC、依赖零新增）/ K9（既有基线零回归）全不触发。

## 5. 文案定案（呈报审定）

### 5.1 qh 固定文案（系统直做，[改编] 标注）

- 原型原文：「直接说『**行，开始讲故事吧**』= 按钮拍板（系统记录原话与定案卡版本）」
- **本包定案**：「直接说『**行，就按这版发布**』= 按钮拍板（系统记录原话与定案卡版本）」
- 改编依据：showrunner 纪律 8 / 剧本 8 真实口令为「行，就按这版发布」（口头拍板 verbal 双前提：完整定案卡已展示 + 原话针对该版）；原型文案为 demo 示意，须对齐真实口令避免误导用户说出无效口令。
- 标题逐字：「💡 拍板提示」。

### 5.2 d9 demo 内容（呈报审定）

- 标签：【缺口追问】；正文（块外）：「还缺**核心冲突**——男女主之间的主要阻力是什么？」
- 块内 chips：「家族反对，门第差距」/「前任回归，旧情未了」/「身份秘密，真相将揭」（三条，取自原型短剧语境泛化）。
