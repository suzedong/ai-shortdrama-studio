## 2. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **分批落地**：批一仅 STAGE 0（校验骨架 + 0-final 联动 + B-46），批二 STAGE 1-2 门、批三起 3-7 随 P3/803 | README「可随阶段分批」；门序扩展须门有对象，避免一次性大饼；每批独立批准 |
| D2 | **校验工具化、零 LLM**：四类规则全部确定性纯函数，Agent 只调用与修复 | D-016 系统优先；规则可枚举即系统做，结果可复现、可进单测与门禁 |
| D3 | **工具与拦截同一实现**：harness.validate 与写盘前拦截共用 runHarnessValidation | 防两套口径——Agent 自查通过而拦截失败（或反之）即信任崩塌 |
| D4 | **门联动循 807 模式**：写盘前拒绝 + 零写盘 + 结构化信封码，校验前置、807 语义不变 | 复用已真机验证的防护形态与测试断言模式，不发明新拦截通道 |
| D5 | **markedAt 可选字段**（K1）：存量 dirty 无字段不提醒不报错；重复标记刷新、清脏随脏消失 | 共享层最小侵入；无法推算不臆造；漂移计时锚点 = 最近一次「仅标记脏」决策 |
| D6 | **漂移提醒系统直做，不设 harness.drift 工具**：黄条/确认卡直显，纯函数直算，零新 IPC | B-46 提醒入口即黄条与二次确认；无 Agent 消费面的 MCP 工具是死面；D-016 确定性提醒不经对话 |
| D7 | **门卡摘要走既有 gate 通道**：payload 携校验摘要 + global.d.ts 镜像，零新 IPC；通道不够则停手呈报 | K8 最小扩面；renderer 不直连主进程校验 |
| D8 | **批一规则冻结七条 checkId**，后续只增不改不删；warning 仅作通道与谱系降级 | 基础校验宜少而确定；checkId 稳定供 findings 回流与测试断言 |
| D9 | **两真机缺口分流**：web.search 环境限制登记不阻塞；capture 跨重启列 T8 必验 | 环境限制非代码缺陷不背包；持久化缺口借本包真机窗口闭环 |

## 4. 风险与边界

| 风险 | 边界与缓解 |
|---|---|
| 基础校验误伤既有立项流（老项目字段不全被 blocker 卡住） | T7 全量回归 + T8 放行路径必验；规则只查设计书既定必填键；若老数据大面积不过 → 停手呈报，不私自放宽 |
| 谱系不可装载时 styleRef 校验假阳性 | 降级 warning 并注明（契约 §1.3），不把环境问题判成内容 blocker |
| gate 通道携摘要需动 payload 形状 | 已登记 K8 范围；零新 IPC 红线，不够则呈报 |
| markedAt 时区/时钟回拨 | ISO 存储、整天数 floor、未来时间戳按 0；不引日期库 |
| 分批被误读为「全链路已闭环」 | README/偏差清单状态只标「批一」；1-a 等门未建前不得宣称确认门全链路完成 |
| 真机目验污染真实项目 | 沙箱项目构造旧 markedAt（循 810 T7 沙箱先例），目验后清理复原 |
