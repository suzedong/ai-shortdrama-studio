# feature-813 工作目录更换 · 需求规格

> 状态：**待用户卡口批准（K8）**，批准前不实现（铁律 1）。
> 用户范围裁决（2026-11-03，AskUserQuestion 三项，已确认）：
> 1. 范围 = **单一全局工作区根目录**（不做多目录并存、不做按项目目录）；
> 2. 存量 = 旧根下 `project-*` 目录**整体物理搬移**到新根，失败整体回滚、不留半搬态；
> 3. UI 入口 = **设置面板**（与 feature-014「AI 服务设置」并列），系统直做（D-016），不经 AI 对话。

## 1. 背景与问题

- 项目工作区根目录目前硬编码为 `~/Documents/ai-shortdrama-studio`，全仓共两处：
  - [electron/project/library.ts](../../../electron/project/library.ts) `workspaceRoot()`（项目列表 / 新建 / `assertProjectDir` 路径硬边界）；
  - [electron/main.ts](../../../electron/main.ts) `ensureRuntime()` 中 Agent 运行时 serve cwd。
- 用户无法把项目数据存放到期望的位置（其他分区、自选目录等），只能停留在默认目录。

## 2. 用户故事

- 作为用户，我可以在设置面板把「工作目录根」改为指定目录，已有项目目录随之整体迁移，之后所有项目数据都落在我期望的位置。
- 作为用户，更换后无需手动搬文件：项目列表、打开项目、新建项目、Agent 运行时 cwd 都自动以新根为准。
- 作为用户，更换失败（目标目录不存在、被占用、中途磁盘错误）时，系统回滚到更换前状态，我不会遇到「搬了一半」的中间态。

## 3. 效果（验收概述，AC 明细见任务清单 T7）

1. 设置面板新增「工作目录」入口：显示当前生效根目录与来源（自定义 / 默认），提供「更换目录 → 系统目录选择器 → 确认更换」完整流程。
2. 更换成功：设置落盘；项目列表在新根下看到同一组项目；当前项目的 session-state 同步重映射；新建项目落在新根；可再次更换回旧根（项目随迁回）。
3. 更换失败：零半搬态（已搬项回滚）；主进程错误码与中文 message 在面板原样上屏。
4. 浏览器开发环境（dev-mock）`window.api.settings.workspace` 三键形态可调用、不报错。

## 4. 不做（防止越界）

- 多工作区根目录并存 / 列表聚合多根；
- 跨磁盘卷（EXDEV）搬移——本阶段仅同盘 rename，跨盘给出明确错误提示；
- 导入任意外部目录——只搬平台旧根内的 `project-*` 目录，非 `project-*` 文件一律不动；
- 运行时自动重连——与 feature-014 同模式：更换后若运行时驻留，提示「需手动重连后生效」；
- 改 `project-*` 命名规则、项目内部目录结构、schema。

## 5. 系统原则（D-016 系统承载，AI 辅助）

目录更换是确定性操作（可枚举校验 + 文件搬移 + 设置落盘），一律系统直做：不经 AI 对话、不占 Agent 工具与 MCP 通道、不新增依赖。
