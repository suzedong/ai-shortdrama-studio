# feature-815 · 设计说明

## 1. 根因与最小方案

`PreviewMedia` 当前按「有视频则 return video；否则 return img」提前返回，因此资源同时存在时 PNG 永远不渲染。修复不是换媒体优先级，而是将图片与视频拆成两个独立区域。

谱系十键中的 anchorWords / textureRecipe 是人工谱系信息，不是生成作业参数。真实 PNG / MP4 已内嵌 ComfyUI API graph，主进程可做确定性只读解析，无需 AI、OCR、生成服务或新依赖。

## 2. 分层

1. **纯解析层** `metadata-parser.ts`：Buffer → 元数据文本 → API graph → 通用 prompts / params。不接触 Electron、fs、网络。
2. **资源服务层** `preview-metadata.ts`：封闭 request → 注册条目 / 文件名映射 → 安全路径 → 异步有限读取 → DTO。所有预期错误翻译为五态。
3. **IPC 层**：main 只注册一个 handler；preload 只透传封闭 request；global.d.ts 镜像 DTO。
4. **呈现层** `VisualCatalog.tsx`：保留现有深蓝弹窗、家族徽章、琥珀焦点与谱系升级工作流；详情宽度提升，宽窗双列、窄窗单列，媒体区圆角 10px、深色底、8px 栅格。

## 3. 媒体与元数据布局

- 图片卡标题「参考图片」，始终渲染自己的 `<img>` 与元数据状态。
- 视频卡标题「生成视频」，保留标准 / turbo / FastH3 三档；切换只改变当前 `<video>` 与视频元数据请求。
- 元数据在对应媒体卡内部，显示提示词原文、参数标签 / 值、复制按钮和来源说明。
- 底部保留「谱系信息」：视觉特征、锚点词示例、质感配方；与文件元数据视觉分区。
- 缺视频时图片仍占可用区域；缺图时视频与目录不失败；播放错误仅替换视频区域提示。

## 4. 解析策略

PNG 按 chunk 边界读取，MP4 按 box 层级与 keys 索引读取，避免把媒体 payload 中偶然出现的字符串当 JSON。graph 提取按节点类型和连接查找采样器、文本编码、尺寸、帧数、fps 与加载器；节点 ID 仅为 graph 内连接使用，不写死 A1 编号。

只提取确定值：连接可追到常量才采用；无法识别即省略。首帧 / 模型 basename 化，任何 graph 引用都不触发二次文件读取。解析结果只暴露白名单提示词与参数，不返回 graph。

## 5. 异步一致性

组件保存图片与视频独立 state。每次请求捕获递增序号和身份键；resolve / reject 后同时匹配当前序号与身份才提交。关闭、换风格使用新代次使旧请求失效。视频 tier 不改变图片身份，因此不重新请求图片。

## 6. 安全与降级

白名单消除 renderer 路径输入；`resolve/relative/realpath` 双重 containment 防 `..` 与符号链接逃逸；扩展名 / 常规文件校验；文件与元数据上限、长度算术检查、异步句柄 finally 关闭。错误文案固定，不泄露本机路径。

五态语义见契约 §2.2。UI 对 IPC reject 也转本地 error，不让异常越过详情边界；媒体元素与元数据互不清空对方。

## 7. 实施步骤

1. 落地规格与 DTO；2. 纯解析器；3. 安全资源服务；4. IPC / mock；5. 双媒体 UI；6. 真实 / 合成 / UI 测试；7. Electron 真机与治理回写。每步不扩大非目标。
