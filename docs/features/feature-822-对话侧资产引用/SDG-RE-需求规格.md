# feature-822 · 对话侧资产引用 · 需求规格

> 日期：2026-11-17 ｜ 阶段：P1 切片 D ｜ 溯源：[Design 原有·形态对齐 / 自研新增实现]
> 来源：[P1 调查记录](../../verification/p1-2026-11-15/P1调查记录.md) §3-⑦ / §5、[Parity 影响矩阵](../../design/MiniMax%20Design%20Parity影响矩阵.md) §2.2「`@`、`/`、附件与结果引用」及 §2.3「对话 / 画布显式引用资产」。用户已批准最小 K8；**2026-11-17 已实施并完成切片 D 验收**，证据见《SDG-RE-任务清单》，不代表 P1 整体通过。

## 1. 问题与目标

对话输入区的「资产」按钮目前没有行为，`runtime.promptAsync()` 只发送文本，历史回放也丢弃 `file` parts，资产无法作为用户本轮输入进入真实 Agent 上下文。本包完成：

**从当前项目选择资产 → 在正文中插入可删除的引用 chip → 主进程复核并构造真实文件 parts → Agent 上下文可见 → 历史重放仍显示同一引用。**

引用选择、校验和回放投影由系统确定性完成；AI 只消费实际收到的文本与资产，不把生成资产的 `sourceSession` 混同为用户输入引用。

## 2. 范围

- 复用现有 `asset.list` / `asset.thumbnail`，在输入区提供资产选择器；支持图片、视频、音乐、工作流四类及显示名/项目相对路径搜索。
- 在正文流中插入、移除引用 chip；同一资产去重，保留引用顺序。正文非空校验保持现状，引用本身不伪造成用户正文。
- 扩展现有 `runtime:prompt` 输入与 `runtime:session:messages` 回放 DTO；不新增 IPC 路由。
- renderer 只提交资产 ID；main 按发送时活动项目索引重新解析 kind、相对路径、显示名、MIME 和真实文件，构造 opencode 原生 `file` parts。
- 为稳定回放资产 ID，main 同时写入内部合成引用清单；该清单与文件 URL 不向 renderer 暴露，也不显示为用户正文。
- 当前项目切换、会话切换使选择器及旧异步结果失效；失效/缺失资产安全报错，不发送伪造引用。
- 历史回放恢复引用 chip；资产后来缺失时保留安全元数据并显示不可用状态，不改写历史正文。
- 空 `assetRefs` 的文本发送、流式回复、停止、工具轨迹和既有画布绑定保持原行为。

## 3. 非范围

不重复实现 feature-821 上传；不做拖拽/批量上传、原图查看器、资产删除或重命名；不自动绑定画布节点，不修改 MCP 工具或生成资产来源追溯；不新增资产版本快照、索引字段、共享类型、依赖、自定义协议或通用二进制 IPC；不允许 renderer 传任意路径/URL；不承诺所有模型均能语义理解图片、视频、音乐或工作流，不受支持时必须显示真实错误。

## 4. 验收标准

| 编号 | 通过判据 |
| --- | --- |
| AC-1 | 「资产」按钮打开当前项目选择器，四类资产及显示名/路径搜索可用；chip 插入、删除、去重和顺序正确，空文本规则不回归。 |
| AC-2 | renderer 仅提交资产 ID；main 在当前活动项目索引复核并只接受项目内普通文件及白名单 MIME，伪造 ID、跨项目 ID、符号链接和路径逃逸均被拒绝。 |
| AC-3 | 真实 prompt 请求包含用户正文、内部引用清单及对应原生 `file` parts；文件 URL 仅存在 main → opencode 内部链路，不进入 preload 回放 DTO。 |
| AC-4 | 发送后及会话/项目重开后均恢复同一资产 chip；缺失资产只降级对应 chip，不丢失其他正文、推理或工具段。 |
| AC-5 | 项目/会话切换后，旧选择器、列表、缩略图、发送预检及回放响应不得污染新上下文。 |
| AC-6 | 缺失、失效或 provider 不支持时不伪造接受/成功；保留可修正的输入状态，并显示不含绝对路径的安全错误。 |
| AC-7 | 空引用发送的请求体与现状一致；文本对话、SSE、停止、工具轨迹、资产上传及绑定/解绑回归通过，引用本身不写 `canvas.command`。 |
| AC-8 | K1/K9 零触发；K8 仅扩展 `runtime:prompt` 与 `runtime:session:messages` DTO，0 条新增路由，main/preload/global.d.ts/dev-mock 同步。 |
| AC-9 | typecheck、构建、专项与真实 Electron 证据入档；至少实测一张项目图片进入真实 opencode 用户消息并回放，既有全量失败基线单列。 |
| AC-10 | 只声明切片 D 实际验收结果，不宣称切片 E 或整个 P1 已通过。 |
