# SDG-RE-需求规格 · 多创作页与自由画布持久化

> 日期：2026-11-17 ｜ 阶段：P1 切片 E ｜ 来源：[Design 原有·形态对齐 / 自研新增实现]
> 溯源：[P1 调查记录](../../verification/p1-2026-11-15/P1调查记录.md) §3-③④、§5；[Parity 影响矩阵](../../design/MiniMax%20Design%20Parity影响矩阵.md) §1.4、§2.1；[已批准实施计划与卡口裁决](./SDG-AI-变更记录.md)（2026-11-17「现状调查与实施计划批准」「K1 / K8 / 删除策略用户裁决」）。
> 卡口：用户已明确批准 K1（Canvas v4 共享类型）、K8（命令与 IPC 扩展）及非空对象“确认后删结构”；K9 零触发。

## 1. 问题与目标

当前一个项目只有一份根级 `nodes/edges/gates`，没有创作页/画布集合；节点拖动与 zoom/pan 仅为 renderer 内存状态，空画布关闭前即使位于画布视图，重启也回到立项视图。Store 在提交时才读取全局活动项目，排队写与切项目竞争时存在串项目风险。

本包实现：

**多创作页 → 页内多画布 → 节点自由坐标与逐画布视口 → 活动页/活动画布/活动视图 → 完整退出并重启 Electron 后精确恢复。**

同时保留既有事务底座、项目级 Gate、项目共享会话、资产绑定和对话资产引用，不把 UI 改造建立在双份画布数据或伪造成功上。

## 2. 用户价值与核心场景

1. 创作者可在同一项目中按方案建立多个创作页，并在页内建立多个画布进行比较或组织。
2. 节点不再被限制在原 STAGE 列，可按创作关系自由布局，重开后坐标不丢失。
3. 每个画布有独立 zoom/pan，切页、切画布及完整重启后回到对应视口。
4. 页/画布结构操作是系统直做，不经过 AI；所有页继续共享项目现有会话。
5. 旧项目无需手工迁移，读取时不改档，首次成功变更后自动升级为 v4。
6. 排队写、迟到响应与项目切换不会把一个项目的画布写入或展示到另一个项目。

## 3. 范围

### 3.1 数据与主进程

- 单 `canvas.json` 升级为 schema v4；根级 pages + gates，页级 canvases，画布级 nodes/edges/viewport。
- 节点可选 `position: { x, y }`；旧节点缺省坐标继续走确定性 STAGE 布局。
- 根级 `activePageId`、`activeView: 'canvas' | 'stage0'`；页级 `activeCanvasId`。
- 页/画布新建、重命名、删除；节点移动；既有资产绑定/解绑增加完整目标。
- 新增 `canvas.viewState`：`active.set` 与 `viewport.set`，同队列原子落盘但不增 revision/receipts。
- v2/v3 懒迁移、v4 严格校验、revision 冲突、幂等重放、写前归档与原子替换。
- 项目根在调用时捕获，page/canvas 目标在入队前固定；cache 按项目隔离。
- 既有 `canvas.update` 适配活动画布，缺省 position 保留；不新增 MCP `canvas.write`。

### 3.2 Renderer

- 空态与非空态均可用的创作页 tabs、页内画布选择、新建、改名和确认删除。
- 节点跨 STAGE 自由拖动，pointer-up 只提交一次；拖动帧零 IPC。
- 逐画布 zoom/pan 恢复；滚轮防抖、平移结束、主动 fit 后保存。
- 小地图、吸附、边展示与 fit 支持自由坐标和负坐标。
- `activeView` 随立项/画布导航持久化，完整重启恢复。
- get/command/subscription/viewState 迟到响应按项目与请求序号丢弃；页切换不重置项目会话或对话附件。

## 4. 非范围

- 按页 Agent 会话、页历史、跨页正式引用、Diff Review、undo/redo、通用版本回滚。
- 自动整理、独立聚焦、左右布局快捷键、手动连线新增/删除命令。
- 新增 MCP `canvas.write`、React Flow 等依赖、新数据库或多文件跨事务。
- 修改 Gate 决策 DTO 或将 Gate 改为页级；修改会话、ComfyUI、语音或媒体通道。
- 修复 B-70、其他 P1 缺口或 P2 能力；创建 Git commit、推送或发布。

## 5. 业务规则

1. 每项目至少一页，每页至少一画布；页 id 项目内唯一，画布 id 页内唯一，节点 id 画布内唯一。
2. 标题 trim 后为 1–80 字符；默认名使用当前范围最小未占用序号；实体 id 由主进程生成。
3. 页/画布创建后切至新对象并进入画布视图；重命名不改变活动目标。
4. 画布含任一节点或边即为非空；页含多个画布或任一非空画布即为非空。
5. 非空删除必须同时经过 UI 二次确认和主进程 `confirmNonEmpty` 校验；只删结构，不删产物或资产文件。
6. 删除活动对象后，优先选择原索引下一项，否则选择上一项；页回退后使用该页自己的 activeCanvasId。
7. 结构、移动和资产命令进入 revision/receipts；活动/viewport 写入不进入，避免视口操作制造 Agent 写冲突。
8. position 为有限世界坐标且允许负值；viewport.x/y 为有限屏幕平移值，zoom 为 0.25–1.6。
9. 根级 gates 继续属于项目会话；`canvas.update`、影响评估与对齐在读取时固定 page/canvas 目标，不得因切页改投。
10. v2/v3 `get()` 不写盘；旧档仅在首次成功结构、移动、资产或 viewState 变更时写为 v4。

## 8. D-037 现行归并约束：Canvas 命令与资产绑定（2026-11-19）

本节接收归档包 814 的 Canvas revision / receipt、命令幂等、原子 JSON、坏档保护、CanvasNode.assetIds 及资产绑定 UI。**现行形状以本包 v4“页—画布树”为唯一事实**；814 根级 nodes/edges 的 v3 只保留历史，不恢复为并行结构。

1. `CanvasNode.assetIds?: string[]` 是节点到真实资产索引的多选引用；image / video / music / workflow 均可绑定。绑定按 nodeId 去重，不自动修改坐标、连边、资产 meta 或 sourceSession。
2. `assets.bind` 校验节点、资产存在及数量上限后追加；`assets.unbind` 幂等移除。两条命令都携带完整 `{pageId, canvasId}` 目标，在不同页 / 画布存在同名 nodeId 时不得串写。
3. 结构、移动和资产命令继续使用 expectedRevision、commandId + 稳定内容 hash、receipts 和项目内单队列。重复提交同命令返回原 receipt，不重写、不广播；同 ID 不同内容明确冲突；revision 不符不写盘。
4. Canvas JSON 只在项目 canvas 目录内写同目录临时文件，归档既有档案后 rename；坏 JSON / 非法形状报 CANVAS_CORRUPT，ENOENT 才按缺文件处理，不得重建覆盖坏档。viewState 与命令共用队列和原子写，但不增加 revision / receipts。
5. AssetsPanel 与 CanvasBoard 通过 nodeId / canvasId 派生选中资产；绑定和解绑即时更新选中数、按钮 busy 与可访问状态。切节点只取消与该资产—节点对有关的旧请求，不影响其他节点选择；失败 / 冲突 / 广播后重新 get 当前页画布，按选择版本保留仍有效的其他勾选。
6. 历史消息中的安全资产 chip 可回放；缺索引记录、相对路径逃逸、真实文件缺失和来源补写失败均不阻断历史消息 / SSE。上传仍由 821 系统直做，不因导入成功自动绑定。
7. 可信来源由 821 负责，对话资产引用由 822 负责；本包只拥有 Canvas 节点绑定及其命令 / UI，不接 Agent 自报来源，不新增 MCP `canvas.write`。

**冲突裁决**：814 的 v3 文件布局、根级集合和以其为输入的旧示例均被本包 v2/v3 → v4 懒迁移与完整目标规则取代；可迁移的是命令语义、安全约束和交互行为，不是旧 JSON 形状。本次仅文档归并，不新增接口或真机验收声明。

## 9. Canvas 只读预检

本节接收归档包 825 中属于 CanvasStore 的只读预检约束。预检只回答“显式项目根目录下的 canvas 是否可按正式加载同一判据读取”，不代表完整项目打开已经提交成功。

### 9.1 与正式加载共用判据

1. CanvasStore 提供主进程内部能力 `assertReadable(projectDir)`，按调用方显式捕获的项目根目录检查画布；不得读取全局 currentDir 猜测目标，也不信任既有缓存。
2. 预检与正式 `getForRoot` 必须共用同一只读磁盘步骤：读取既有文件 → JSON 解析 → v2/v3 迁移及 v4 结构校验 → `projectId` 对目录身份校验。不得为预检复制一套较宽松或较严格的坏档判据。
3. 文件不存在（ENOENT）视为 Canvas 预检可打开，只读步骤返回空结果；正式加载才可在后续实际打开流程中创建空画布。坏 JSON、未知 / 非法结构、活动引用或事务字段损坏仍抛 `CANVAS_CORRUPT`，磁盘 `projectId` 与目标目录不符仍抛 `CANVAS_PROJECT_MISMATCH`，均 fail closed，不得返回假成功或以空画布覆盖。
4. 合法旧档只在内存中形成迁移投影；预检本身不得借“迁移”写入 v4。现有 v4 页—画布树仍是唯一现行结构，旧根级 nodes/edges 只作历史与懒迁移输入。

### 9.2 只读与零副作用

- 预检必须绕过缓存并直接检查磁盘，旧缓存不得掩盖坏档；有效返回值在预检完成后丢弃。
- 预检不得写盘、创建或补建 session、清理 / 恢复门、reset 或填充画布缓存、同步标题、广播 `canvas:changed`，也不得产生其他可观察写副作用。
- 文件缺失时预检不创建文件、不填缓存；只有正式 `getForRoot` 在缓存未命中且同一只读步骤返回空结果时，才按既有行为创建 emptyCanvas、原子写盘并填缓存。合法旧档仍遵循读取零写、首次成功变更才写 v4。
- 预检错误保持原错误码和可读原因向上传递，不吞错、不改写为成功；调用方必须将其视为不可继续提交的失败。

### 9.3 项目打开职责边界

827 负责路径和 manifest 校验后的 `openProject beforeCommit` guard、session / currentDir 提交与项目写队列；828 负责完整 `project:open` 编排、成功提交以及提交后的清门、reset / recover、标题与广播顺序。823 只负责 Canvas 文件解析、迁移 / 结构 / 项目身份校验及上述只读能力，不接管路径错误优先级或项目会话事务。

本包不因此扩展为跨文件事务、通用项目打开回滚或任意后置 I/O 故障保证，也不承诺预检成功后的任意并发文件替换均可被后续步骤发现。本次仅归并文档，不新增 IPC、DTO、共享类型或产品验收结论。
