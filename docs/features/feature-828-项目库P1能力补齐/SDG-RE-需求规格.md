# feature-828 · 项目库 P1 能力补齐 — 需求规格

> 版本：v1.0（2026-11-18 冻结）｜溯源：[自研新增·平台基础]
> 上游：P1 收口计划、D-035、feature-824/825/827。
> 授权：用户「没完成的继续完成」；K6/K8 方案已按推荐边界呈报并继续执行。

## 1. 问题

项目库已有新建、列表、搜索、打开、改名和删除，但最近使用仍按目录 mtime 排列，缺少详情与 Finder 定位，也没有跨目录静态项目包导入／导出。正式会话位于全局 opencode 数据目录，单纯复制项目目录会丢失过程留痕；直接复制还可能带入临时状态、错误 projectId 或覆盖现有项目。

## 2. 目标

1. 以项目 `.session.json.lastOpenedAt` 形成真实最近使用顺序，保留现有前缀搜索，并提供项目详情、Finder 定位入口。
2. 不新增压缩依赖，以目录作为静态项目包；导出包含业务文件、页/画布、资产、版本及当前绑定正式会话的只读快照，排除密钥、缩略图缓存、运行作业和临时状态。
3. 导入支持原生项目目录及本包导出的目录包，预检 manifest、canvas v4、projectId、符号链接和路径边界；重复项目始终分配新目录并重写项目身份，不覆盖当前或已有项目。
4. 导入和导出均使用目标同文件系统 staging→rename，取消零写盘，失败清理 staging；提交后目录才可被项目列表发现。
5. 导入会话仅以快照只读展示，活跃绑定置空；首次续聊由既有流程新建本地会话，并记录本地 sessionId 到来源 sessionId 的映射。

## 3. 验收标准

### AC-828-1 · 历史、搜索、详情与定位

`project:list` 返回 `lastOpenedAt` 并按其倒序排列；Welcome 最近项目使用该顺序而非目录 mtime。项目导航和 Welcome 可查看真实标题、目录、状态、创建/更新/最近打开时间，项目导航可在 Finder 中定位已校验的工作区项目。既有搜索、新建、打开、改名、删除不回归。

### AC-828-2 · 静态目录导出

用户显式选择不存在的新目录路径；拒绝已有路径及源/目标重叠。导出到目标同级 staging，复制允许的业务内容，写入 `project-package.json`、清理后的 `.session.json` 和 `session-snapshots.json` 后一次 rename 提交。当前绑定会话存在时必须从真实 runtime 读取消息；读取失败则导出失败，不得静默省略或伪造成功。无绑定会话时可不包含快照。导出包可由本包重新导入。

### AC-828-3 · 导入预检、副本与失败回滚

导入目录必须有合法 manifest；有 canvas 时必须通过现有 v4 读取校验，且 projectId 与包元数据或原生目录名一致。拒绝符号链接、非法包结构、源/目标重叠及任何越权目标写入。使用既有 `project-<时间戳>-<随机串>` 规则分配唯一副本目录，重写 `.session.dir`、`canvas.projectId/title`，保留页、画布、节点、资产和版本 ID。取消、预检失败、复制失败和 rename 失败均不产生可见项目或残留 staging；不得覆盖当前项目。

### AC-828-4 · 正式会话只读快照与来源

快照保存 sourceProjectId、sourceSessionId、exportedAt 及现有 `RuntimeSessionMessageRecord[]`，在项目详情中以既有消息呈现组件只读查看。导入不连接或冒充原 opencode 会话；`.session.activeSessionId=null`。首次发送仍走既有 createSession→activeSession→promptAsync 链路，并在 `session-sources.json` 追加去重来源映射。再导出时保留历史快照并追加当前本地会话快照。

### AC-828-5 · 自动化与真实 Electron 验收

覆盖列表历史、详情、坏 manifest/canvas、projectId 失配、符号链接、重复导入、导出后再导入、复制/rename 故障、取消零写盘、会话只读及来源映射。定向测试、全量 Vitest、typecheck、build 通过。隔离真实 Electron 覆盖导入→打开→完整重启、导出→重新导入、取消/失败不污染列表及 feature-824 F1—F10 回归，保存结构化证据；不宣称完整目录事务或完整 Parity 通过。

## 4. 非目标

- 不新增 ZIP、Dagre 或其他依赖，不修改 `shared/types.ts`，不新增 MCP 工具。
- 不复制 opencode 私有数据库，不恢复运行中 Agent/Comfy 作业，不让导入快照直接接受 prompt。
- 不实现跨文件事务、跨进程锁、目录 fsync、断电级一致性、项目级归档/模板或通用迁移入口。
- 不提前实施 feature-829—834，不提交、不推送、不发布，不覆盖工作树其他修改。

## D-037 现行归并约束：无项目入口、F1—F10 与打开提交事务（2026-11-19）

本节自包含接收 feature-812、feature-824 与 feature-825 的现行项目库需求；历史验收证据仍留原包。

### 1. 无项目入口（接收 feature-812）

- 无活动项目时进入项目库/首启选择态，提供新建、打开既有项目及最近项目入口；不得伪造示例项目、活动项目 ID 或空画布加载成功。
- 最近项目存在时可选择重开；记录失效、读取失败或用户尚未选择时停留在项目库并显示真实原因/未选择状态，不以 Stage 0 或空白工作台冒充项目已打开。首启不得自动创建项目。
- 无项目及项目首拉未完成时不得显示虚假工作进度/状态结论，也不得允许对话发送或创建孤儿会话；输入锁定与发送守卫均为零运行时副作用，模型选择和 AI 服务设置仍可用于首启配置。
- 只有项目打开事务完整提交后才建立活动项目会话并进入工作区。feature-820 原「未选择项目落 Stage 0」仅可解释为**已打开项目内部**的工作区导航，不再承担真正无活动项目入口；feature-812 不归 feature-820，feature-813 保持独立。

### 2. 项目库 F1—F10（接收 feature-824）

| 能力 | 现行需求 |
| --- | --- |
| F1 项目列表 | 展示真实项目记录及既有名称、标识、时间/状态字段；读取失败显示错误，不伪造示例卡 |
| F2 打开项目 | 从卡片/最近项目触发既有打开流程，成功提交后才进入工作区 |
| F3 新建项目 | 通过既有模板/立项入口创建唯一项目，失败不得留下伪活动项目 |
| F4 关闭项目 | 完成既有保存/待处理打开流程后清理活动会话并回项目库 |
| F5 重命名 | 校验名称，更新同一项目事实源与列表展示，不新建项目替代改名 |
| F6 复制项目 | 生成不同项目 ID 与独立目录/记录，源项目保持不变 |
| F7 删除项目 | 经既有确认后删除目标项目；不得误删当前其他项目或伪造删除成功 |
| F8 导入项目 | 预检结构、身份、符号链接和路径边界；重复项目始终分配新目录并重写身份，非法输入/失败清理不得产生可见污染或覆盖既有项目 |
| F9 导出项目 | 使用既有导出流程生成真实静态目录产物，取消零写盘，失败显示错误，不把选择目录当作导出成功 |
| F10 保存状态 | 沿用 D-025 四态；项目 JSON 修改使用 1 秒尾随自动保存，最后一次写入生效，关闭前冲刷待保存内容 |

以上仅为能力归属与有效需求归并，不新增产品验收声明。**feature-824 原始总体 FAIL、F10 FAIL 永久冻结**；F1—F9 的历史 PASS 与 F10 的历史 FAIL 不回写，后续 feature-825/828 修复不得倒写原始验收。任何后续通过只能作为独立新证据登记，本次归并不新增或改写此类结论。

### 3. 项目打开提交事务（接收 feature-825）

1. 打开先经 `assertProjectDir` 与 manifest access，再在同一单项目写队列内执行内部 `beforeCommit` guard；错误优先级和 session/currentDir 写安全由 feature-827 承接。
2. guard 调用 feature-823 的 Canvas 只读预检：canvas 不存在允许普通新项目打开；截断 JSON、非法结构或 projectId 不匹配必须 fail closed。预检不得自动修复/覆盖坏档，也不得创建默认 session、写盘、清门、广播或重建缓存。
3. 只有预检成功后才写目标 `.session.json` 并提交 `currentDir`，随后按既有顺序清脏门、reset、恢复会话/工作区、同步标题并广播。预检失败时原项目 session/currentDir、保存状态、门和广播均保持，不得留下半切换或把坏目标项目伪装成已打开。
4. 普通打开仍按既有 DTO 返回 `{ ok, activeSessionId }`，并刷新 `lastOpenedAt`；缺失 canvas 只在预检与提交成功后按既有路径创建，标题同步等非致命步骤不得把已提交打开伪报为失败。
5. 本事务只承诺上述真实预检—提交顺序，不扩为任意预检后 I/O、第三方并发替换或跨文件通用回滚。F10 的 D-025 保存状态、1 秒尾随保存和关闭前冲刷仍按本包既有项目保存契约独立执行。

### 4. 归并边界

本次只修改文档，不新增 IPC/DTO，不宣称 F1—F10、打开事务或真机验收通过；单文件原子写、同项目队列及真实 SIGKILL 范围仍由 feature-827 限定，不扩为跨文件事务、目录 `fsync` 或断电全保证。
