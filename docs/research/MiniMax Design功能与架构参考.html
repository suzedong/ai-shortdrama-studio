定位

§0 · 外部产品参考
产品本质
MiniMax Design = AI Agent 驱动的商业内容生产平台：用户表达创作目标 → Agent 规划任务、扩展 Prompt、选择 Skill 与工具、调用适配模型、组织素材、持续修改，把想法做到最终交付。
覆盖形态与优势场景
文本脚本、图文、视频、Motion Graphic、3D 建模、网页 UI/UX、专业设计与影视后期。优势场景：广告投放、电商素材、品牌宣传、KOC 内容、短视频、Motion Graphic、3D 资产、网页 UI/UX、影视后期。

0.1 需求基线变更：从“补缺口”转为“全面复刻”（2026-11-15） v1.4 新

用户本轮明确：目标由“只补 MiniMax Design 的局域网 ComfyUI 与生产闭环缺口”调整为全面复刻 MiniMax Design，其中图片和视频生成改走局域网 ComfyUI。本报告因此从“差异参考”升级为“复刻能力基线”，但它仍是研究文档，不自动替代《短剧Agent平台设计》、项目特化规则或决策台账。
  1. 复刻能力与体验，不复制专有实现：覆盖用户可见功能、交互、工作流、数据语义与可追溯机制，采用自研或开源等价实现；不复制闭源代码、商标、私有素材、账号权限或云端服务。
  2. 图片 / 视频明确改编：统一调用可配置的本地 / 局域网 ComfyUI，Renderer 不直连，媒体执行收敛到主进程 / MCP 引擎工具；原产品界面出现的云端模型条目不等于本项目可用通道。
  3. 未被明确变更的约束不擅自扩大解释：音乐、文本 Provider、纯 JSON 持久化、账号 / 社区 / 团队 / 积分等仍按现行规格执行或另立决策；“全面复刻”不授权 Agent 自行改模型、引入数据库或接入云端媒体 Key。
  4. 保留本项目八步闭环：MiniMax 短剧七阶段作为工作流机制参考，映射到现有 0 立项 → 1 故事 → 2 剧本分场 → 3 资产 → 4 分镜 → 5 镜头 → 6 后期 → 7 发布，不合并或裁剪立项与发布。

2.1.3 Agent 驱动工作流 v1.1 新

官方原文：

The Agent on the right side of MiniMax Design can fill workflow inputs from your conversation and start the current workflow for you. For example, choose a workflow and tell the Agent: "Use this workflow, use Picture 1 as the first frame, and generate a five-second video with a slow push-in." 即 Hub 的核心交互模式是 「Agent 通过对话填充工作流输入并启动」，高级操作支持 Agent 通过对话编辑节点 / 调整参数。

2.2.4 本地持久化、正文资产与 Agent 关联

静态结构：每个画布有 .hilo/canvas-v3/state.sqlite。document 表用单行完整 JSON 保存图文档，receipts 表用于命令去重与结果恢复：

CREATE TABLE document (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  json TEXT NOT NULL
);

只读实测样本：测试画布实际文档为 schemaVersion: 1、revision: 8，含两个节点和一条边：

节点 / 边实际数据要点结论
已写内容的文本节点kind: "composition"，含 compositionId: "cmp_e570ac46087c"；size: 350 × 500节点壳通过 compositionId 关联正文资产
空白文本节点kind: "placeholder"，expectedKind: "text"占位节点与已写内容节点在图文档中形态不同
节点间边source 为 placeholder，target 为 composition连线只保存节点引用，不内嵌正文

正文另存为 assets/Untitled.md，实测内容为「画布交互调研：第一段测试文本。」；store/ 下另有两个 ver_*.md 版本文件。因此可以确认节点壳、正文和正文版本分离，但不能仅凭这一组样本断言所有节点类型都沿同一路径转换。

Agent 与画布的静态关联字段包括：

  • 任务：canvasId、compositionId、taskIds、placements、origin、handoff.target = "canvas"。
