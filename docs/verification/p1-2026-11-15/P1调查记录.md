### ⑤ 真实 AI runtime 会话

**结论：阻塞，非环境缺 Key。** `arkConfigured: true`，但运行时启动失败：

```
runtime.status → { state: "error", healthy: false,
  error: { code: "INTERNAL",
    message: "showrunner.md 模板缺少 __MODEL_REF__ 占位符：
      D:\\Code\\ai-shortdrama-studio\\node_modules\\electron\\dist\\resources\\opencode\\agents\\showrunner.md" } }
```

- 运行时处于 error 态时，`runtime.listSessions()`、`runtime.listAgents()` 均返回 `RUNTIME_NOT_READY`；UI 输入框 `disabled`，占位文案「AI 服务不可用，恢复后可继续对话」——**降级是诚实的**，没有伪造可对话状态。
- 模板不一致事实：

| 文件 | 大小 | 修改时间 | `model` 行 |
| --- | ---: | --- | --- |
| 仓库 `resources/opencode/agents/showrunner.md` | 50,303 B | 2026-11-15 | `model: __MODEL_REF__`（第 4 行） |
| 报错副本 `node_modules/electron/dist/resources/opencode/agents/showrunner.md` | 43,413 B | 2026-10-28 | `model: ark/__ARK_MODEL_ID__`，**无 `__MODEL_REF__`** |

- 解析逻辑（[provider.ts](../../../electron/runtime/provider.ts#L153-L177)）在开发态应在仓库 `resources/` 命中现行模板，实际报错却指向 `process.resourcesPath` 下的旧副本。**本记录只登记该不一致与现象，不宣布唯一根因**；是解析分支、启动参数判定还是旧副本残留所致，须由修复包单独定位，不能以"清缓存即可"结论搪塞。
- 因此 SSE 流式、停止、工具轨迹、多会话等**全部无法现场验证**。

**补记（2026-11-15 同日，feature-819 修复后复验，不改写上方原始结论）**：

- 根因已实测确认：Electron 33.4.11 下 `electron <appdir>` 启动时 `app.isPackaged` 与 `process.defaultApp` 同时为 `true`，旧判据 `if (app.isPackaged)` 把开发态误判为打包态。修复见 [feature-819](../../features/feature-819-Agent运行时模板解析修复/SDG-AI-变更记录.md)。
- 复验结果（[p1-after-819-runtime.json](./p1-after-819-runtime.json)）：`runtime.status` = `{ state: "running", port: 4096, version: "1.18.34", healthy: true, error: null }`；`listAgents` 返回 showrunner（`ark/ark-code-latest`，23 个工具）；`listSessions` 返回 27 条历史会话；对话输入框恢复可用（占位 `描述创作目标，或 / 唤起 Skill…`）。主进程日志 [electron-after-819.err.log](./electron-after-819.err.log) 无 runtime 错误。
- 仍未验证：真实 prompt → SSE → 停止 → 工具轨迹的完整往返（需真实推理与项目写入，留待 P1 对话验收单独执行）。
