ai-shortdrama-studio · 技术方案

本地 UI 观察与测试结果压缩方案

将高频、只读、可复核的观察工作放到本地模型，将单次大上下文理解、诊断和修复保留给主模型。目标不是让本地模型替代程序员，而是建立一个本地「观测与信息压缩层」。

01 背景

开发、调试和 UI 测试过程中，主模型的 token 消耗往往不来自「写代码」本身，而来自反复读取：

  • 每一步操作后的界面截图；
  • DOM、无障碍树和控件状态；
  • 控制台、页面和测试日志；
  • 多轮成功但无需主模型关注的中间过程。

本方案将高频、只读、可复核的观察工作放到本地模型，将单次大上下文理解、诊断和修复保留给 Trae 主模型。目标不是让本地模型替代程序员，而是建立一个本地「观测与信息压缩层」。

02 目标与原则

2.1 目标

  1. 重复 UI 测试不消耗主模型的截图和完整日志上下文。
  2. 主模型默认只接收简短摘要，异常时才读取指定证据。
  3. 本地模型始终只读，不直接修改代码或操作生产数据。
  4. 本地模型不可用、超时或输出无效时，明确标记为待复核，绝不假报通过。

2.2 核心原则

工具负责动手，本地模型负责看，主模型负责想。
  • 能由 selector、日志规则或状态断言确定的结果，由确定性工具判断。
  • 截图主要用于页面状态与视觉异常观察，不作为唯一功能断言依据。
  • 本地模型不承担架构设计、代码修复、自动合并和最终发布判断。
  • 默认只让摘要进入主对话；截图和完整日志保留为本地产物。

03 模型与工具分工

角色建议运行位置职责
Playwright / 固定脚本开发机启动 Electron、执行固定操作、采集截图和日志
Qwen3.5-9B（Q4 量化）本机 8G GPU常规截图观察、日志压缩、结构化结果输出
Qwen3.8-27B局域网 24G GPU（可选）复核疑难、失败或低置信度观察结果；不纳入 MVP
Trae 主模型 / 火山方舟云端制定测试计划、诊断异常、修改代码、最终判断
上下文提示
Qwen3.5-9B 在 8G GPU 上建议从 Q4_K_M、8K 上下文起步。模型原生上下文能力不等于本地可用上下文，不为长日志盲目扩大上下文。

04 MVP 范围

4.1 首条固定流程

只实现一条低风险 Electron 流程：

  1. 启动应用；
  2. 等待主窗口和明确的工作台控件出现；
  3. 保存启动阶段与工作台阶段截图；
  4. 收集控制台错误和页面异常；
  5. 将每张截图及当前步骤检查清单发送给本地 9B；
  6. 汇总确定性断言与视觉观察；
  7. 向标准输出返回短摘要和本地产物路径。

首条流程不进入立项、生成、ComfyUI 等复杂业务，不修改业务数据。

4.2 明确不做

真机操作 自动修复代码 失败后自动重试 截图猜坐标点击 自由探索整个应用 自动提交 / 合并 / 推送 两级模型自动级联 视觉结果作为发布门禁

  • 执行一条 UI 观察命令

  • 异常时读取指定截图、相关日志和复现步骤

06 视觉检查清单

每一步使用明确、封闭的检查项，不询问「这个页面怎么样」。

启动阶段建议检查

  • 是否出现应用主窗口；
  • 是否白屏或只有无法识别的空白内容；
  • 是否出现错误弹窗或明显错误提示。

工作台阶段建议检查

  • 主窗口和核心工作区是否可见；
  • 是否存在明显遮挡、截断、重叠或大面积异常空白；
  • 是否出现与预期状态不符的错误提示；
  • 页面整体是否符合「工作台」预期。
断言边界
功能是否到达工作台仍由 selector 断言决定；视觉模型只提供辅助观察。

07 本地模型输出契约

每一步只返回一个 JSON 对象：

{"
  "step": "open-workbench",
  "status": "pass",
  "observations": [
    "主窗口已显示",
    "中央工作区可见"
  ],
  "evidence": [
    "左侧导航和中央内容区域可见"
  ],
  "confidence": 0.92
}

字段约束

字段类型规则
stepstring必须等于当前请求步骤 ID
statusenumpass fail uncertain 三选一
observationsstring[]只记录从截图中实际观察到的内容
evidencestring[]给出状态判断对应的可见依据
confidencenumber0–1；无法可靠判断时配合 uncertain

以下情况统一转换为 uncertain 并记录原因

  • HTTP 请求失败或超时；
  • 模型返回空内容；
  • 返回内容不是合法 JSON；
  • 字段缺失、类型错误或状态枚举越界；
  • 返回的步骤 ID 与请求不一致；
  • 本地服务不支持图片输入。
不做自动重试修复
不自动让模型重试修复格式；MVP 直接保留原始响应并标记待复核。

08 汇总规则

每个步骤同时保留两类结果：

  • functional：由 Playwright selector、页面异常等确定性规则产生；
  • visual：由本地视觉模型产生。

汇总时遵守

  1. 确定性功能失败不能被视觉 pass 覆盖；
  2. 视觉服务不可用不能被视为视觉通过；
  3. 任一关键环节失败，总体结果不得为 pass；
  4. 无明确失败但存在 uncertain，总体结果为 needs_review；
  5. MVP 的总体结果只供开发辅助，不作为发布门禁。

建议总体状态：pass fail needs_review

09 本地产物与主模型摘要

9.1 产物目录

artifacts/ui-observe/<run-id>/
├─ run.json
├─ summary.json
├─ steps/
│  ├─ 01-launch.png
│  ├─ 01-launch.json
│  ├─ 02-workbench.png
│  └─ 02-workbench.json
└─ logs/
   ├─ console.log
   └─ runner.log
版本库卫生
artifacts/ 应在实施时加入 .gitignore，避免截图、日志和运行数据进入版本库。

9.2 标准输出摘要

正常情况只输出：

UI 观察完成：2/2 步通过
功能断言：通过
视觉检查：通过
控制台错误：0
产物目录：artifacts/ui-observe/<run-id>

异常情况额外输出：

  • 失败或待复核步骤；
  • 一句话观察结果；
  • 对应截图路径；
  • 相关日志路径或首个有效错误；
  • 最小复现步骤。

摘要保持短小而固定，不把所有成功步骤的截图、日志和模型原始响应传入主对话。

10 配置与密钥管理

环境变量

变量用途
UI_OBSERVER_BASE_URL本地或局域网 OpenAI 兼容接口地址
UI_OBSERVER_MODEL模型名，MVP 默认 qwen3.5-9b
UI_OBSERVER_API_KEY接口密钥；本地无需认证时可留空
UI_OBSERVER_TIMEOUT_MS单次观察超时时间

安全要求

  • 不在源码、任务文档、配置样例或日志中写入真实密钥；
  • 不打印请求头和完整鉴权信息；
  • 截图优先使用本机或可信局域网服务；
  • 不通过公网明文 HTTP 发送截图和密钥；
  • 本地模型只接收脚本传入的图片和文本，不获得 shell、文件系统或应用控制工具；
  • 测试脚本只能写入规定的产物目录，不修改应用源码和业务项目数据。

11 建议实施结构

为控制依赖和改动范围，建议先采用独立脚本，不接入 Electron 主进程：

scripts/ui-observe/
├─ run.mjs
├─ observer.mjs
├─ checklist.json
└─ observer.test.mjs

并在 package.json 增加两个命令：

  • ui:observe：执行固定 UI 观察流程；
  • ui:observe:test：执行观察器单元测试。

预计新增开发依赖：playwright。它只用于测试采集，不进入应用运行代码。

边界约束
最终文件布局可在实施任务包中调整，但不得将观察器接入共享类型或修改现有业务契约。

12 单元测试与验收

12.1 单元测试（至少覆盖）

  1. 合法 pass、fail、uncertain JSON 的解析；
  2. 非 JSON、缺字段、错误类型和未知状态的处理；
  3. 步骤 ID 不匹配时转为 uncertain；
  4. 请求超时、服务不可用和空响应的处理；
  5. 功能失败不会被视觉通过覆盖；
  6. 存在 uncertain 时总体结果为 needs_review；
  7. 摘要不包含密钥、完整日志和无关截图数据。

12.2 MVP 验收标准

编号验收标准
AC-01一条命令能够启动应用、完成固定流程并保存两步截图和日志
AC-02正常流程下，主对话只收到短摘要，不接收全部截图和日志
AC-03预置异常截图能够被标记为 fail，并给出可见依据
AC-04本地模型不可用或输出无效时，结果为 needs_review，不会假报通过
AC-05观察器单元测试、项目现有类型检查和全量测试均通过
AC-06整个流程不修改业务源码、共享层和真实项目数据

13 实施顺序

  1. 治理准备按项目 AI-SDG 规范建立 Feature 任务包，补齐需求规格、契约、任务清单和变更记录；新增 Playwright 前完成 K9 依赖确认。
  2. 本地接口验证确认 Qwen3.5-9B 服务支持 OpenAI 兼容图片输入，验证 Q4 量化下的显存、响应时间和结构化输出能力。
  3. 只采集、不观察先跑通 Electron 启动、截图、日志和确定性断言。
  4. 接入本地观察器实现单图请求、固定提示词、JSON 校验和异常转换。
  5. 实现摘要与产物确保主模型默认只读取摘要，异常证据可按路径查看。
  6. 测试与试运行完成单元测试和真实启动流程，再用一批正常/异常截图评估误报和漏报。
  7. 决定是否扩展只有在 MVP 稳定后，才考虑更多 UI 流程、24G 复核或真机测试。

14 后续可选扩展

以下均不属于 MVP：

  • 24G 模型仅对 fail 和 uncertain 结果进行二次复核；
  • 将日志压缩独立为无图片请求，降低视觉调用成本；
  • 基于同一检查清单批量回归多个页面；
  • 使用 Playwright Trace 定位失败前后的状态；
  • Android 真机通过 ADB/UIAutomator 操作，截图仅用于观察；
  • 根据实际 diff 和测试结果生成文档初稿，主模型一次终审。
扩展不变式
扩展时仍保持同一边界：确定性工具执行操作，本地模型只读观察，主模型负责诊断与修改。

15 成效度量

试运行阶段记录：

  • 每次测试进入主模型的截图数量；
  • 每次测试进入主模型的日志字符数或 token 数；
  • 本地观察的 pass / fail / uncertain 分布；
  • 主模型复核后确认的误报和漏报数量；
  • 单次本地观察耗时及显存占用；
  • 因本地观察错误导致的额外复核成本。
判断标准
方案是否值得扩大，不取决于本地模型调用了多少次，而取决于它能否在低风险前提下稳定减少主模型上下文，同时不增加大量复核工作。
