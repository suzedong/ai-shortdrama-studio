# 立项阶段整体真机测试用例（STAGE 0）

> **版本**：v1.0（2026-10-28 建）
> **依据**：2026-10-28 全包真机目验覆盖盘点（feature-001~010、801/802/804/806~811 变更记录与任务清单）。
> **范围**：立项阶段（STAGE 0）当前功能全集的端到端真机走查（A）+ 单包真实链路补验（B）+ 环境受限与挂起项（C）。
> **定位**：手工真机测试用例矩阵，非自动化脚本；执行结果回填本文 §6 与各包变更记录。

## 1. 背景与缺口结论

立项阶段功能由 10+ 个任务包分别落地，各包目验通道不一：真实 Electron + ARK 链路（003/006/806/807/808/809/810/811）、仅 dev-mock 浏览器目验（004/005/007/008/009/010）、无本包真机目验（001/002/801/802）。2026-10-15 的 STAGE 0 走查早于 004/005/006/007-010/806 落地，**不构成当前功能全集的端到端验收**。本文补齐三类缺口：

- **A 整体层**：同一新项目、一次连续走查，证明各机制协同工作。
- **B 真实链路层**：主功能仅 dev-mock/单测覆盖的包，补真实 Electron 写盘与 Agent 链路证据。
- **C 环境/证据层**：环境受限项显式挂起、证据不充分项补强。

## 2. 执行约定

1. **通道**：A/B 用例一律 Electron 实机 + 真实 ARK 链路（`npm run dev`）；dev-mock/Playwright 仅可作辅助取证，不作通过依据。
2. **沙箱保护**：涉及回滚、漂移、构造 blocker 等破坏性操作用例，在 `Documents/ai-shortdrama-studio/project-<日期>-e2e` 沙箱项目执行（复制真实项目建沙箱）；目验毕沙箱整体删除，真实项目零污染。
3. **留证**：逐步截图存 `/tmp/e2e-*.png`（不入仓库）；每用例记录「执行日期 / 通道 / 结果 / 证据清单 / 异常」，回填 §6 矩阵状态列。
4. **状态口径**：⬜ 待执行 → ✅ 通过 / ❌ 不通过（登记缺陷并呈报）/ ⏸ 环境受限或依赖裁决。不通过项修复后须同用例复测。
5. **807 边界（既有职责，非缺陷）**：brief.publish 直发不推进 manifest.briefVersion、不生成影响清单；指针推进与影响清单为 impact.commit 专属职责。判据按此口径断言。
