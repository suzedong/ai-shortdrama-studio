# H3 Image 定妆生产规范（H3 单轨 · 9:16 单尺寸 4MP 版）

> **版本**：v2.1 · 全新方案（v2.0 的 9:16 收敛版）
> **模型**：MiniMax H3 Image（`image_minimax_h3_image_t2i.json` 子图链路）
> **适用**：STAGE3 角色定妆（人物图）
> **状态**：核心机制已真机验证（§12）；未验证项见 §11
> **作者**：AI-SDG 协作者 · 2026-11-14

---

## 0. 一句话

**一个角色、一个尺寸、一个 seed：全部定妆图统一 9:16 · 1440×2560（约 4MP），只改构图段，不换分辨率。**

四条铁律：

1. **只有一个尺寸。** 所有定妆图（含全身正面/背面）都用 1440×2560。没有横版，没有 16MP，没有第二档。
2. **只有一个 seed 链。** 主脸锚定版后，其余视角用同一 seed、只改 S4。**换尺寸就是换脸，所以尺寸不许动。**
3. **一个角色只有一个脸源。** 全剧所有镜头 `<Picture 1>` 指同一张主脸锚。
4. **生成 4MP、入库 1/2 缩。** 生成档唯一，入库档唯一（720×1280）。

**一条补充**：定妆只管"这个人长什么样"，不管"笑起来什么样"。表情视角会换脸（§6.5 实测），只能当表演参考。

## 1. 为什么 4MP 够（像素账）

| 环节 | 分辨率 | 像素 | 说明 |
| :-- | :-- | :-- | :-- |
| 视频成片 | 1344×768（16:9） | 1.03 MP | 既有镜头实例，20 步标准档 |
| 定妆入库 | 720×1280（9:16） | 0.92 MP | 与视频面积同量级，R2V 拿到的是等量级参考 |
| 定妆生成 | 1440×2560（9:16） | 3.69 MP | 4 倍超采样，缩下来才干净 |

**账很直白**：视频模型自己的输出预算只有 1.03 MP，喂给它的参考超过这个量级也变不出更多细节。生成端用 3.69 MP 是为了"缩得干净"——实测 1MP 直出会有块状结块，4MP 缩下来边缘干净。

同时 1440×2560 是 9:16 精确比例 + 32 对齐（1440/32=45、2560/32=80），不会掉进 H3 的低分辨率劣化区，也不需要对画幅做任何裁剪。

## 2. 尺寸与档位（各只有一档）

| 项目 | 取值 | 说明 |
| :-- | :-- | :-- |
| **生成尺寸** | **1440×2560** | 9:16 精确、32 对齐、3.69 MP |
| **入库尺寸** | **720×1280** | 精确 1/2 缩，整数倍重采样 |
| 画幅 | 竖版 9:16 | **全部视角统一，无例外** |

### 2.1 尺寸纪律

1. **不许出现第二种尺寸**，横版、16:9、4:7、1:1 一律不产出。全身也不例外。
2. **不得跨尺寸复跑**。实测同 seed 换宽高即换脸（§12 表 2）；跨尺寸用参考图派生也锁不住（§12 表 3）。
3. **缩放只在 SaveImage 之前做**，资产目录只留 720×1280 终态，不留 4MP 中间态。
4. 场景底图、道具底图**不受本条约束**（它们不是人物定妆，画幅另行定）。

## 3. 采样参数（唯一档）

| 参数 | 取值 | 说明 |
| :-- | :-- | :-- |
| 采样器 / 调度器 | **euler / simple** | 模板默认，实测可用 |
| 步数 | **6** | 少步模型，加步数只涨时间不涨细节 |
| CFG | **1.0** | 必须 1.0，见 §3.1 |
| denoise | **1.0** | 全幅重绘，不存在低 denoise 保脸这条路 |
| 批 | 1 | 抽卡靠换 seed，不靠 batch |

### 3.1 为什么 CFG 必须是 1.0

工作流里 `negative` 被 `ConditioningZeroOut` 清零，CFG>1 时模型仍按"负向 = 零张量"计算，负向不仅无效，还会把画面往过饱和推。所以：

- **CFG 恒为 1.0**，负向输入在本链路里是死输入，**任何负面词都不写**。
- 洁净度、无文字、无家具一律写成**正向陈述**（"背景为纯净浅米色无缝墙面，空景"）。

## 4. 提示词结构（五段式 · 单段中文流）

| 段 | 名称 | 内容 | 随视角变 |
| :-- | :-- | :-- | :-- |
| S1 | 风格与光 | 世界观锚 + 视觉风格 + 光线基调 | **逐字不变** |
| S2 | 人物 | 年龄 / 职业 / 气质 / 脸型 / 发型 | 同角色不变 |
| S3 | 服装 | 上衣段 / 全套（见 §4.4） | **按视角分档** |
| S4 | 构图 | 景别 + 朝向 + 占比 + 留白 | **逐视角改写** |
| S5 | 背景洁净 | 底色 + 空景 + 光线均匀 + 无文字水印边框 | 不变 |

提交给模型的是一段连续中文，按五段顺序拼，**不写结构标签**（标签会印进 PNG 元数据）。

### 4.1 S1 必须与视频侧风格句逐字同字（硬规则）

H3 图像与 H3 视频共用同一个 32B 文本编码器（`qwen3vl_32b_minimax_h3_int8_convrot` / `nvfp4_awq`）。S1 里那句风格描述，**必须与 STAGE5 镜头提示词的"风格："句完全一致，一个字都不改**：

> 拟真人仿真人动漫，贴近真人神态与微表情、立体感强、保留动漫美感。

这是图文两侧唯一的文本同源点。**S1 改一个字，一致性就断在文本层，画面上追不回来。**

### 4.2 S4 的三个硬约束（9:16 专用）

1. **占比**（全身卡）：写"人物占画面高度约 82%，头顶留白约 8%，鞋底可见"。实测 9:16 下这样写，全身从头到脚完整入画、脚不被裁（§12 表 8）。
2. **朝向**：正面 / 3-4 侧（转约 35°，露一侧耳）/ 纯侧（转约 90°）/ 背面。**只改这一句，其余四段不动**。
3. **画幅词**：竖版统一写"竖版构图"，不要再写横版词。

### 4.3 模板（陈默 · 正面平静，9:16 实测可用）

```
千禧年初北方省会城市，拟真人仿真人动漫，贴近真人神态与微表情、立体感强、保留动漫美感，
22岁男程序员，气质木讷真诚，鹅蛋脸、三七分、和善，
穿蓝色牛仔外套，内搭白色翻领衬衫，
竖版胸像特写，腰部以上构图，正面平视镜头，表情平静温和，脸居中占画面主要位置，
背景为纯净浅米色无缝墙面，空景，没有家具，没有道具，没有场景元素，柔和均匀的光线，画面没有文字，没有水印，没有标志，没有边框
```

### 4.4 S3 服装必须按视角分档（实测教训）

| 视角类型 | S3 写什么 |
| :-- | :-- |
| 胸像 / 正面表情 / 3-4 侧 / 纯侧脸 | **上衣段**（外套 + 内搭），下半身不入画，不写 |
| 全身正面 / 全身背面 | **全套**（外套 + 内搭 + 下装 + 鞋） |

**为什么**：实测用同一 seed、只把 S4 从胸像改成全身，但 S3 仍是上衣段，结果下装和鞋被自由发挥——黑色皮鞋变成棕色皮鞋、白衬衫变 Polo 领（§12 表 8）。**下半身不写就等于不约束**。

## 5. 视角清单（八视角 · 全 9:16）

| # | 视角码 | 生成尺寸 | 入库 | 身份等级 | 用途 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | **正面平静** | 1440×2560 | 720×1280 | **主脸锚（唯一）** | 所有镜头 `<Picture 1>` |
| 2 | 胸像特写_竖版 | 1440×2560 | 720×1280 | 派生锚（与主锚同人，实测几乎同图） | 大特写镜头 |
| 3 | 正面微笑 | 1440×2560 | 720×1280 | **表演参考（不作身份锚）** | 情绪参考，不入 `<Picture 1>` |
| 4 | 正面大笑 | 1440×2560 | 720×1280 | **表演参考（不作身份锚）** | 情绪参考，不入 `<Picture 1>` |
| 5 | 3-4侧 | 1440×2560 | 720×1280 | **次锚（实测保脸）** | 对话/侧身镜头的 `<Picture 1>` |
| 6 | 纯侧脸 | 1440×2560 | 720×1280 | **次锚（实测保脸）** | 侧向构图 |
| 7 | 全身正面 | 1440×2560 | 720×1280 | **体态锚** | 所有镜头 `<Picture 2>` |
| 8 | 全身背面 | 1440×2560 | 720×1280 | 体态锚（背面） | 背影镜头 |

> **表情视角为什么会掉级**：同一 seed、只改 S4 的条件下，微笑与大笑会换成一张更圆更软的脸（T 模式、R 模式都如此）。表情词在 H3 上是**主体属性**，不是表情层——模型会按表情重造脸型。详见 §6.5 与 §12 表 9。

### 5.1 身份等级的含义

- **主脸锚**：一个角色唯一一张，抽卡选定后全剧不变。它是"这个人"的定义。
- **派生锚**（胸像特写）：与主锚同 seed 同尺寸，实测几乎同图（只有裁得更紧），可放心用。
- **次锚**（3-4侧 / 纯侧脸）：必须与主脸锚同尺寸同 seed，人眼验收"同一人"才可进 `<Picture 1>`。实测这两个**能保住脸**。
- **表演参考**（正面微笑 / 正面大笑）：**只提供情绪表达方式，不作身份依据**。它们与主锚不是同一张脸（§6.5），拿去当 `<Picture 1>` 会把角色换掉。
- **体态锚**（全身正面 / 全身背面）：供衣服、身高比例、体型，**脸不作身份依据**——全身构图里脸被压小、五官趋平（§12 表 8）。

## 6. 一致性机制

### 6.1 三条锁定线

| 线 | 手段 | 断了会怎样 |
| :-- | :-- | :-- |
| **文本线** | S1 与视频侧风格句逐字同字 | 图文风格分家 |
| **身份线** | 单一尺寸（1440×2560）+ 单一 seed 链 | 每个视角一张新脸 |
| **尺度线** | 入库 720×1280 ≈ 视频面积量级 | 参考与成片细节密度不匹配 |

### 6.2 为什么"统一 9:16"是这套方案的关键

H3 Image 每次都是 denoise 1.0 全幅重绘，**宽高一变 latent 网格就变，采样轨迹不再对应**。实测同 seed 下 1MP / 4MP / 16MP 出三张不同的脸。所以"不换脸"不是靠提示词写得好，而是靠**结构上不给换脸的机会**：

- 尺寸唯一 → latent 网格唯一 → 同 seed 的采样轨迹可复现；
- 只改 S4 → 条件向量只在一个维度上变 → 主体结构跟着走，不重掷。

把全身也做成 9:16，正是为了消掉"竖版 ↔ 横版"这个必然换脸的断点。代价是横版全身不再有，但横版全身本来就不该当脸源（§5.1）。

### 6.3 承诺边界（诚实话）

- **承诺**：竖版八视角之间，同一 seed 只改 S4，可出同一人（已实测正面→3-4侧、正面→全身，§12 表 6/8）。
- **不承诺**：全身视角的脸与胸像逐像素一致。全身构图里脸只占几十像素，五官会趋平、脸略瘦，**这是信息量问题，不是身份问题**。所以全身只当体态锚。
- **不承诺**：换 seed 还同脸。seed 就是身份，换 seed 等于换人。

### 6.4 R 模式的用法

`MiniMaxH3ImageConditioning` 的 `vae` + `images` 接上后，参考图作为 reference latents 锚定（不接 vae 只走文本编码器）。API 格式里 `images` 必须写成**连接列表**：

```json
"5": {"class_type": "MiniMaxH3ImageConditioning",
      "inputs": {"clip": ["2",0], "prompt": "...", "width": 1440, "height": 2560,
                 "vae": ["3",0], "images": [["10",0]]}}
"10": {"class_type": "LoadImage", "inputs": {"image": "ref_正面平静_720x1280.png"}}
```

- `"image_0": ["10",0]` → 报 `unexpected keyword argument 'image_0'`
- `"images": ["10",0]` → 报 `Boolean value of Tensor ... ambiguous`
- `"images": [["10",0]]` → **跑通**

**用途**：氛围、服装、光位、画风靠拢（实测能把写实倾向拉回参考图的插画质感）。
**限制**：**不是保脸工具**。跨尺寸时脸仍会变；同尺寸下也不比"同 seed T 模式"更稳。身份由 seed + 人眼验收兜。

---

### 6.5 表情视角一定会换脸（实测，重要）

同尺寸、同 seed、只把 S4 的表情词从"表情平静温和"改成"嘴角自然上扬的微笑"或"张口大笑"，出来的是一张**更圆、更软的脸**：眉形变细、眼睛变大、下颌变钝、脸变宽。判为另一个更年轻的人（§12 表 9）。

- **T 模式和 R 模式都这样**。R 模式喂主锚作参考重跑微笑，结果与 T 模式几乎同图——再次证明 R 模式是氛围锚不是身份锚。
- **根因**：denoise 1.0 全幅重绘，模型没有"只动嘴角"的层；表情词在 H3 里被当作**主体属性**，改动它会连带重造脸型。
- **所以定妆不承担表情**。表情交给视频侧：`<Picture 1>` 用主锚，表情写在视频提示词文字里，H3 会从这张脸自己演出表情——擦头那一镜（§12 表 7）就是这么成的。
- **表情卡不得进参考槽**，尤其不得当 `<Picture 1>`；它只作导演/人眼参考，或用作该镜头"想要什么情绪"的沟通样本。

**一句话**：定妆回答"这个人长什么样"，不回答"这个人笑起来什么样"。后者是镜头的事——实测在视频侧用文字驱动就能演出来，且不换人（§12 表 10）。

## 8. 与 H3 视频 R2V 的对接

### 8.1 参考槽位

| 槽位 | 内容 | 取图 |
| :-- | :-- | :-- |
| `<Picture 1>` | 面部锚 | **主脸锚（正面平静）** 或已验收次锚（3-4侧） |
| `<Picture 2>` | 体态锚 | 全身正面（衣服、身形、站姿） |
| `<Picture 3>` | 场景/道具 | 场景底图 / 道具底图 |
| `<Audio 1>` | 音色 | `音色_{角色}.wav` |

### 8.1.1 参考图比例不必与画幅一致（已验证）

`MiniMaxH3ReferenceToVideo` 的 `ref_image_size`：

- **`match`（默认）**：*"scales each ref (down only, keeping aspect) to the generation's pixel area"* —— 等比缩放到生成像素面积，**只缩不放大，不裁剪不拉伸**。
- **`max`**：*"uses the reference pipeline's 2048px short edge for best identity fidelity"*，参考 token 参与每一步采样，**慢数倍**。

**实测**：720×1280 / 768×1344 竖版定妆喂 1344×768 横画幅，`match`，正常出片——无黑边、无裁切、构图未带歪、脸与主锚一致（§12 表 7）。参考图不是帧，是全程参与采样的条件，**比例不一致不构成障碍**。

| 场景 | 参考图 | `ref_image_size` |
| :-- | :-- | :-- |
| 常规镜头（多、要快） | 入库 720×1280 | `match` |
| 关键镜头（特写、脸要像） | **4MP 原图** 1440×2560 | `max`（短边 1440 < 2048，不会被缩，保真最高） |

### 8.1.2 双锚必须都喂，但双锚也不够（实测教训，两次）

- **第一次（只喂 Picture 1）**：省掉 `<Picture 2>` 全身正面，成片里陈默穿白色圆领 T 恤——定妆卡明明是蓝色牛仔外套。服装不从胸像继承。
- **第二次（双锚都喂）**：Picture 1 + Picture 2 + 场景全部给齐，**开头 0.2 秒有外套，抬头笑的瞬间外套消失变白 T**，一直穿到片尾（§12 表 10）。

所以：`<Picture 1>` 管脸、`<Picture 2>` 管身形，**服装不能被参考图兜住**，必须在提示词文字里复述（§8.2.1）。双锚是必要条件，不是充分条件。

### 8.2 视频参数（既有，不改）

`1344×768 · 20 步 · 5 秒档`。

### 8.2.1 服装必须在视频提示词里复述（实测，硬规则）

双锚都喂齐了（Picture 1 胸像 + Picture 2 全身正面），**只要文字里没写衣服，模型就会自己换装**。实测那条擦头接笑的镜头：0.2 秒还穿着蓝色牛仔外套，抬头笑的瞬间外套就没了，身上只剩白圆领 T 恤，一直穿到片尾（§12 表 10）。参考图没能拦住。

所以 `<Picture 1>/<Picture 2>` 之后，**必须紧跟一句服装复述**：

```
陈默，穿蓝色牛仔外套，内搭白色翻领衬衫，下穿深色长裤，脚穿黑色皮鞋。
```

规律一句话：**参考图管"长相对不对得上"，文字管"身上到底穿什么"。** 可变量（服装、发型干湿、配饰、道具在不在手上）都要用文字钉一遍；参考图是软约束，文字是硬约束。

### 8.3 提示词写法

```
<Picture 1> 为{角色}定妆照（正面平静），<Picture 2> 为{角色}定妆照（全身正面），<Picture 3> 为{场景}参考，<Audio 1> 为{角色}音色参考。
{角色}，{服装复述：外套 + 内搭 + 下装 + 鞋}。          ← 必写，见 §8.2.1
{内容层：动作 + 景别 + 运镜 + 神情}
{对白 + 语气}
声音：{声音描述}
风格：拟真人仿真人动漫，贴近真人神态与微表情、立体感强、保留动漫美感。
```

风格句照抄定妆 S1，一个字不改（§4.1 的反向约束）。

## 12. 实测记录（2026-11-14 · 陈默）

**环境**：局域网 RTX 4090 24G · ComfyUI 0.45.3 · `minimax_h3_image_pruned_int8_convrot` + `qwen3vl_32b_minimax_h3_int8_convrot`。

### 表 1 · 分辨率与入库锐度（缩到 768×1368 后测边缘能量）

| 生成档 | 生成尺寸 | 耗时 | 入库边缘能量 | 判定 |
| :-- | :-- | :-- | :-- | :-- |
| 16MP | 3072×5472 | 33 s | 5071 | 最锐，但超出视频消费能力 |
| 4MP | 1536×2720 | 10 s | 2229 | 采用（够用、边缘干净） |
| 1MP | 768×1344 | 8 s | 2503 | 数值不低但块状结块 |

### 表 2 · 跨尺寸是否同脸（同 seed 594535360）

| 样本 | 尺寸 | 结果 |
| :-- | :-- | :-- |
| 胸像 1MP | 768×1344 | 脸 A |
| 胸像 4MP | 1536×2720 | 脸 B |
| 胸像 16MP | 3072×5472 | 脸 C |

结论：**换分辨率就是换脸**。这条直接决定了"统一 9:16"的必要性。

### 表 3 · R 模式锁脸能力

| 组 | 参考 | 目标 | 结果 |
| :-- | :-- | :-- | :-- |
| 竖 → 横全身 | 768×1344 | 2688×1536 | **失败**，脸型/眉形/发型全变 |
| 竖 → 竖同尺寸 | 768×1344 | 1536×2688 | 氛围与服装靠拢，脸仍偏柔 |

结论：R 模式是"氛围锚"不是"身份锚"。

### 表 4 · 节点接法（踩坑）

| 写法 | 报错 |
| :-- | :-- |
| `"image_0": ["10",0]` | `unexpected keyword argument 'image_0'` |
| `"images": ["10",0]` | `Boolean value of Tensor ... ambiguous` |
| `"images": [["10",0]]` | 跑通 |

### 表 5 · 4MP 样张（4:7 旧口径，已被 9:16 取代）

`_h3测试\定妆_陈默_正面平静_h3v2_00001_.png`（768×1344，源 1536×2688）等，仅留档。

### 表 6 · 同尺寸同 seed 只改构图（保脸验证）

| 项 | 设定 |
| :-- | :-- |
| 尺寸 / seed | 1536×2688 · seed 2026111410 |
| 改动 | 仅 S4：`正面平视镜头` → `3-4侧脸，面部朝画面左侧转约35度，露出右耳` |
| 结果 | 脸成立：发型分缝、眉形、眼型、耳廓一致，视角成功转换 |

结论：**同尺寸 + 同 seed + 只改 S4 = 可复现的保脸手段**。

### 表 7 · 竖版定妆喂横画幅 R2V（端到端）

| 项 | 设定 |
| :-- | :-- |
| 模型 | `minimax_h3_ref2va_pruned_int8_convrot` + `qwen3vl_32b_minimax_h3_nvfp4_awq` |
| 输出 | 1344×768 · 124 帧（5.17 s）· 20 步 |
| 参考 | Picture 1 = 竖版定妆 768×1344，Picture 2 = 宿舍场景，`ref_image_size=match` |
| 结果 | 正常出片：无黑边、无裁切、构图未带歪；末帧脸（三七分发、眉形、脸长）与主锚一致 |
| 失败点 | **服装漂**：成片白 T 恤（定妆是牛仔外套）——因为省掉了 Picture 2 |

结论：① 比例不一致不构成障碍；② 双锚缺一必漂。

### 表 8 · 9:16 单尺寸八视角验证（核心）

| 项 | 设定 |
| :-- | :-- |
| 尺寸 | **1440×2560**（9:16 精确、32 对齐、3.69 MP） |
| seed | 2026111430（两图相同） |
| 图 E | 正面平静（S4 = 竖版胸像特写，腰部以上） |
| 图 F | 全身正面（仅改 S4 = 竖版全身，占画高 82%，头顶留白 8%，鞋底可见） |

结论：① 9:16 能做全身，旧"竖版画不全腿脚"的顾虑在 H3 上不成立；② 同尺寸同 seed 只改构图能保脸；③ S3 必须按视角分档。

### 表 9 · 9:16 八视角全链同 seed 实跑（1440×2560 · seed 2026111430 · 只改 S4）

| :-- | :-- | :-- | :-- |

### 表 10 · 主锚 + 文字表情演笑（双锚三参考，端到端）

| 项 | 设定 |
