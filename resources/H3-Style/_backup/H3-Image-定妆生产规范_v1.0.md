# H3 Image 定妆生产规范 v1.0

> **适用通道**：MiniMax H3 Image 文生图（工作流 `image_minimax_h3_image_t2i.json` 及本文 §10 定义的 ref 变体）
> **取代关系**：本文**取代**原 qwen-image 口径下的定妆参数规范（1344×768 / 768×1344、euler/normal/20 步/CFG 2.5、负面抑制词），**仅对 H3 通道生效**。已产出的 qwen 定妆资产不回炉、不追溯重出，继续有效（且可作为 §6 的 R 模式基准图）。
> **状态**：v1.1（2026-11-14 真机实测后修订，实测记录见 §13；未验证项见 §12）。
> **作者**：AI-SDG 协作者 · 2026-11-14

---

## 0. 一句话口径

**H3 定妆 = 16MP 单一档（不设 4MP 抽卡档）/ 6 步 CFG 1.0 / 入库统一 1368×768 或 768×1368 / 五段式自然语言 / 洁净度正向化 / 同分辨率同 seed 或基准图锁人。**

四条与旧规范最不一样的地方，先记住：

1. **分辨率就是身份**：实测同 seed 下 4MP 与 16MP 出的是两张不同的脸（§13），所以**全流程只用 16MP**，不存在「小图抽卡、大图复跑」的省时路径。
2. **没有负面词这回事**：negative 分支被 `ConditioningZeroOut` 清零，CFG 又固定 1.0，负向在数学上不参与计算。所有抑制必须写进正向描述。
3. **不写画幅词**：宽高由节点决定，扩写链产出的 `aspect_ratio` 也没有接到宽高。prompt 里写 "16:9" 只会制造冲突。
4. **入库尺寸唯一**：生成侧允许多种尺寸，**入库只有两种**。一切缩放裁剪在 `SaveImage` 之前完成。

## 1. 模型事实（本规范的物理基础）

| 项 | 事实 | 来源 |
| :-- | :-- | :-- |
| 模型 | `minimax_h3_image_pruned_int8_convrot` + `qwen3vl_32b_minimax_h3` 文本编码 + `minimax_h3_image_vae_fp16` | 工作流节点 1/2/3 |
| 有效分辨率区间 | 约 **4 MP – 20 MP** | 工作流内嵌说明 |
| 最佳分辨率 | 约 **16 MP** | 同上 |
| 低分辨率表现 | 官方明示「doesn't work well in low resolution」，模板默认 4MP 已属降级起步 | 同上 |
| 采样 | `euler` / `simple` / **6 步** / **CFG 1.0** / denoise 1.0 | `KSampler` 节点默认 |
| 负向 | 无负向文本编码节点，negative 由 `ConditioningZeroOut` 清零 | 节点 6 |
| 文本编码器性质 | qwen3vl-32B，吃自然语言 caption，**不是 SD 的 CLIP 权重语法** | 模型链 |
| 参考图 | `MiniMaxH3ImageConditioning` 保留 `images.image_0 / image_1` 两个接口，**模板未接线** | 节点 5 |
| 出图 | 单次单图，`SaveImage` 前缀 `minimax_h3_image_t2i` | 节点 9 |

**三条推论**（后面所有规则的源头）：

- 推论 A：定妆不可能是小图。旧规范的 1344×768 只有 1.03MP，**低于 H3 下限**，必须「大图出、再缩到入库尺寸」。
- 推论 B：既然画质由分辨率给，就别在步数/CFG 上折腾。任何「调到 20 步 CFG 2.5」的做法在这条通道上属于参数错配。
- 推论 C：负向失效 → 背景纯净度只能靠正向描述与构图约束达成，**这是 H3 定妆最大的工艺难点**。

## 2. 画幅规范

### 2.1 两种形态、两种比例

| 形态 | 视角 | 生成比例 | **生成尺寸（唯一档）** | **入库尺寸（唯一）** |
| :-- | :-- | :-- | :-- | :-- |
| 全身卡（横版） | 全身正面 / 全身背面 | **16:9** | **5472×3072** | **1368×768**（1/4） |
| 人像卡（竖版） | 胸像 / 正面表情 / 3-4 侧 / 纯侧 | **9:16** | **3072×5472** | **768×1368**（1/4） |

**为什么是 16:9 与 9:16**：

- 全身在横版宽幅里容得下手脚与站姿留白，裁切风险最低；
- 人像在竖版里更贴脸，胸上构图的头部占比自然更高；
- 两者与主流成片画幅一致，定妆图可直接被 R2V 当参考整图送入，不需要二次构图；
- **下采样是整除关系**：5472×3072 → 1368×768、3072×5472 → 768×1368，都是精确 1/4，无插值尺寸差、无裁切动作。

### 2.2 三条画幅纪律

1. **入库尺寸唯一**：不论生成侧是 4MP 还是 16MP、节点实际吐出多少像素，入库前一律缩到 1368×768 或 768×1368。记录页/索引/参考图只认这两个尺寸。
2. **生成侧锁死 16MP 标称尺寸**：5472×3072 / 3072×5472，节点按 32 对齐，允许 ±1% 像素偏差。**不得用 4MP 出图再缩**——实测 4MP 缩到入库尺寸后的边缘能量与 1MP 基本持平（§13），这一步等于白跑。
3. **禁用比例**：1:1（定妆无用途）、21:9（无用途）、4:3 / 3:2（同面积下人物更小，只剩更多墙面，等于浪费像素）。若某项目确需方形物料，走发布物料通道另做，**不进定妆库**。

### 2.3 高精档（可选，不入默认流程）

特写镜或发布物料需要更大底图时，允许额外保留一份 **2736×1536 / 1536×2736**（1/2）作为「高精副本」，命名加 `_hi` 后缀，**不参与定妆清单计数、不参与一致性 QC 抽检**，避免污染主库。

## 3. 采样与参数

### 3.1 唯一档（抽卡、定稿共用）

```
euler | simple | 6 步 | CFG 1.0 | denoise 1.0
```

| 参数 | 取值 | 说明 |
| :-- | :-- | :-- |
| 采样器 | `euler` | 模板默认，H3 原生 |
| 调度器 | `simple` | 同上 |
| 步数 | **6** | 官方模板默认值，不调 |
| CFG | **1.0** | 负向已清零，提高 CFG 无引导收益、只有失控风险 |
| denoise | 1.0 | 纯生成，无重绘 |
| 分辨率 | **16MP**（5472×3072 / 3072×5472） | 唯一档；4MP 档已实测淘汰（§13） |

### 3.2 禁止项

- ❌ 套用 qwen 的 `normal` 调度器、20 步、CFG 2.5 —— 参数体系不同，混用只会糊或过曝。
- ❌ 提高 CFG「加强提示词服从」—— H3 没有可用负向，提高 CFG 实际是在拿零条件做对比，结果不可控。
- ❌ 用 `euler_ancestral` 等 SDXL 采样器。
- ❌ 抽卡用 Lightning / 蒸馏 LoRA —— H3 本身已是少步，没有加速档概念。

### 3.3 seed 规则

| 阶段 | seed | 记录要求 |
| :-- | :-- | :-- |
| 抽卡 | `randomize` | 每张候选的实际 seed 必须落进 `资产候选.json` 与 PNG 元数据 |
| 定稿 | **固化**（沿用选定候选的 seed） | 16MP 复跑**必须用同一 seed**，否则等于换人 |
| 跨角色 | **禁止复用** | 同 seed 跨角色会撞脸，是 H3 上最隐蔽的串脸原因 |
| 同角色跨视角 | 允许复用（R 模式下无意义） | T 模式下可复用，但优先靠 prompt 差异拉开 |

## 4. 提示词规范：五段式

### 4.1 结构

H3 只认**一整段自然语言**。定妆 prompt 固定由五段顺序拼接，段间用逗号或句号，**不换行、不加标题、不加编号**。

| 段 | 名称 | 内容 | 是否可变 |
| :-- | :-- | :-- | :-- |
| **S1** | 风格与光 | 形态 / 画风 / 质感 / 光影方向。来自立项视觉风格设定，**全剧一处定义** | 全剧固定 |
| **S2** | 人物本体 | 年龄、性别、职业气质、脸型、发型、眉眼、肤色、体态 | 角色固定 |
| **S3** | 服装与配饰 | 上衣 / 下装 / 鞋 / 配饰 / 面料与颜色 | 角色固定（换装走变体） |
| **S4** | 姿态与构图 | 视角（正面/背面/3-4侧/纯侧）、景别（全身/胸像）、表情、站姿、入画完整性 | **逐卡可变** |
| **S5** | 背景与洁净 | 背景材质、光质、排除项（正向表达） | 全剧固定 |

**组装公式**：

```
S1 ＋ S2 ＋ S3 ＋ S4 ＋ S5
```

五段**全部必填**，缺 S5 是定妆最常见的翻车点（背景会自己长东西）。

### 4.2 禁写项

| 禁写 | 原因 |
| :-- | :-- |
| `(word:1.2)` / `[[word]]` 权重括号 | H3 是 caption 模型，语法会被当正文读进画面或直接忽略 |
| `16:9` / `portrait` / `square` 等画幅词 | 宽高由节点决定，写了制造冲突 |
| `masterpiece, best quality, 8k, ultra detailed` | SD 时代咒语，H3 无收益，只会拉高细节噪声、让皮肤变塑料 |
| `Base:` / `组合N` / `特征N` 等结构标签 | 标签会被印进 PNG 元数据，污染出生证明（历史已实证） |
| 具体场景词（卧室、教室、街景、窗、床、桌） | 定妆带场景 → R2V 串台，场景背景一律由场景概念图承担 |
| 负面词（`no bad hands` 之类） | 无负向通道，写了无效，只会占 token |

### 4.3 S5 洁净度标准句（强制）

每张定妆的 S5 **必须包含**下面这组语义（英文原样拼入，可微调语序，不得删项）：

```
plain seamless light-beige wall, empty background, no furniture, no props, no scenery,
soft even diffused light, no text, no watermark, no logo, no border, no frame
```

- 背景色**默认浅米色**；项目若要换底色（纯白 / 浅灰），在立项视觉设定里一次性定，**全剧统一**，不允许逐卡改。
- 禁止写 `studio backdrop`、`gradient`、`vignette`、`bokeh background` —— 都会引入渐变或虚化，破坏「纯色墙面」这一硬约束。

## 5. 视角清单与产出包

### 5.1 基础包（6 张／角色，必出）

| # | 视角码 | 景别 / 朝向 | 比例 | 表情 | 下游用途（R2V 映射） |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | `bust` | 胸像，正面 | 9:16 | 平静 | 竖屏镜、脸锚 |
| 2 | `front_calm` | 正面，近景 | 9:16 | 平静 | 横屏近景默认 |
| 3 | `three_quarter` | 3-4 侧，近景 | 9:16 | 平静 | 3/4 视角镜 |
| 4 | `profile` | 纯侧脸 | 9:16 | 平静 | 侧脸镜 |
| 5 | `full_front` | 全身，正面，含脚 | 16:9 | 平静 | 中/全景、服装体型锚 |
| 6 | `full_back` | 全身，背面，含脚 | 16:9 | — | 背影镜、走位镜 |

### 5.2 表情扩展包（2 张／角色，按需）

| # | 视角码 | 景别 / 朝向 | 比例 | 表情 |
| :-- | :-- | :-- | :-- | :-- |
| 7 | `front_smile` | 正面，近景 | 9:16 | 微笑 |
| 8 | `front_laugh` | 正面，近景 | 9:16 | 大笑 |

**合计 8 张／角色**。表情只在近景/胸像出，**全身卡永远平静**，不单独出全身表情版（全身表情在下游 R2V 里没有用，纯浪费）。

### 5.3 出卡顺序（强制）

```
基准卡（#2 front_calm 或 #1 bust，二者择一，人拍板）
        ↓
其余 5 张基础包（以基准卡为锚）
        ↓
表情扩展包 2 张（以 #2 为锚）
```

**先出基准卡、人确认、再派生**，不许八张并行乱抽。基准卡定的是这张脸，后面七张是「同一个人换视角」，顺序错了就是八个不同的人。

## 6. 一致性机制

### 6.1 两种模式

| 模式 | 机制 | 适用 | 现状 |
| :-- | :-- | :-- | :-- |
| **T 模式**（纯文生） | 五段式 prompt ＋ seed 锚定 ＋ 逐层对照 QC | 基准卡、无参考资产时 | 模板原生可用 |
| **R 模式**（基准图锁定） | 把基准卡（或已选定概念图）接 `images.image_0`，其余视角以图生图方式派生 | 其余 5–7 张派生，**推荐** | 需 §10 的 ref 变体工作流 |

### 6.2 R 模式要点

- **参考图只接一张**（`image_0`），不要 `image_0 + image_1` 双图，双图会让模型在两张脸之间做平均。
- 参考图**必须是同角色同服装的基准卡**，不能跨服装、不能跨年龄段。
- R 模式下 S2/S3 仍需完整写（图给的是身份，文给的是指令，缺一不可）。
- R 模式的 seed **不重要**（身份来自图），但仍要记录，便于复现。

### 6.3 QC

- 每角色入库前跑 `role_consistency.py`（register 建档 → check-images 比对）。
- 记录页逐卡展示「设计层 vs PNG 实际」对照，**漂移标红即重抽依据**。
- 一致性不达标时，优先改 R 模式参考图，**不要靠加形容词往回拉** —— H3 上形容词救不了脸。

## 7. 抽卡与定稿 SOP

| 步 | 动作 | 参数 | 产出 |
| :-- | :-- | :-- | :-- |
| 1 | 起草五段式 prompt（S1–S3 从角色设定取，S4 按视角表，S5 用标准句） | — | prompt 记录 |
| 2 | 出**基准卡**：4 张候选，**16MP**，seed randomize | 5472×3072 或 3072×5472 | 4 张候选 |
| 3 | 人选 1 张 → 记下 seed → 其余候选归档 `_backup/` | — | 基准卡确定 |
| 4 | 派生其余 5 张基础包（R 模式优先；T 模式则各自抽卡） | **16MP** | 5 张候选 |
| 5 | 全部视角定稿：**同分辨率 + 固化 seed**（R 模式用同参考图）。**禁止跨分辨率复跑** | 同为 5472×3072 / 3072×5472 | 定稿原图 |
| 6 | 节点内 ImageScale → ImageCrop → **SaveImage**，直接落 1368×768 / 768×1368 | — | **入库图（元数据完整）** |
| 7 | 记录：命名、清单、PNG 元数据、`record STAGE3_资产 --version vN+1` | — | 记录页 |
| 8 | QC：一致性 + 画幅 + 数量 → 人确认 | — | 放行 |

**为什么第 5 步必须复跑 16MP**：4MP 只用于选脸选构图，4MP 图直接入库会踩官方「低分辨率出不好」的坑，皮肤、发丝、布料纹理都撑不住 R2V 参考。

## 8. 文件、元数据与版本

### 8.1 命名与目录

- 文件名沿用现状骨架 `定妆_{角色}_{视角}_v{N}_{序号}_.png`（**不改骨架**，避免下游 glob 断链）；视角码已在文件名中，清单表只需再记 seed 与模式。
- 视角码、seed、分辨率、模式（T/R）**写进 PNG 元数据与定妆清单 CSV**，不塞文件名。
- 目录：`STAGE3_资产/定妆/`；旧版一律归档 `_backup/`，记录页只展示最新版。

### 8.2 元数据（出生证明）

每张入库 PNG 必须自带：`prompt`（五段完整拼接文本）、`seed`、`steps`、`cfg`、`sampler`、`scheduler`、`width`、`height`、`workflow`。

**唯一保证方式**：`SaveImage` 之前完成缩放与裁剪（`VAEDecode → ImageScale → ImageCrop → SaveImage`）。
一旦用外部工具二次转存（PS / ffmpeg / 批量改名脚本重编码），元数据即被冲掉，后续悬停提示词、逐层对照、复现全部失效。**这是硬红线，没有豁免。**

### 8.3 版本纪律

- 改图必升版（`_vN+1` 或加版本后缀），旧图归档不删。
- 重抽只换 **S5 背景段或 S4 构图段**，S1–S3 一字不动；动了 S1–S3 等于换人，必须重新走基准卡。
- 每次变更 → `record` 重生成记录页 → `check` → `advance`。

## 9. 验收清单（可机检）

| # | 项 | 规则 | 机检方式 |
| :-- | :-- | :-- | :-- |
| 1 | 入库画幅 | 全身卡 **1368×768**；人像卡 **768×1368**；不接受其他尺寸 | `glob_pil_size` |
| 2 | 数量 | 每角色 ≥8 张（6 基础 + 2 表情），全剧 6 角色 ≥48 | `glob_count_min` |
| 3 | 视角齐全 | 8 个视角码全覆盖，缺一即 FAIL | 清单比对 |
| 4 | 元数据 | prompt/seed/steps/cfg/宽高齐全，缺项 FAIL | PNG 元数据解析 |
| 5 | 背景纯净 | 元数据 prompt 含 S5 标准句全部排除项 | `text_contains` |
| 6 | 无标签污染 | prompt 中不含 `Base:`/`组合N`/`特征N` | `text_not_contains` |
| 7 | 索引一致 | 索引「已选定底图文件」 ↔ 资产候选.json ↔ 文件真实存在 | `picks_consistent` |
| 8 | 一致性 | `role_consistency.py` 全部达标 | QC 库比对 |
| 9 | 记录页 | 悬停覆盖完整、非过期快照 | `record_pmap_cover` |

> 验收规则落到 `验收规则.json`，**改规则不动 proj.py**（沿用既有纪律）。

## 10. 平台接入规格

### 10.1 两个工作流变体

| id | 用途 | 说明 |
| :-- | :-- | :-- |
| `minimax-h3-image-t2i` | T 模式定妆 / 场景 / 道具 | 由 `image_minimax_h3_image_t2i.json` 导出 API 格式 |
| `minimax-h3-image-ref` | R 模式定妆派生 | 在上者基础上，接 `LoadImage → images.image_0` |

### 10.2 manifest 条目（`resources/comfyui/workflows/manifest.json`）

```json
{
  "id": "minimax-h3-image-t2i",
  "version": "h3-image-pruned-int8-v1.0",
  "kind": "image",
  "model": "minimax-h3-image",
  "file": "minimax-h3-image-t2i.json",
  "inputs": {
    "prompt": { "node": "5", "field": "prompt", "type": "string", "required": true, "minLength": 1, "maxLength": 8000 },
    "width":  { "node": "5", "field": "width",  "type": "integer", "required": true, "min": 1024, "max": 8192 },
    "height": { "node": "5", "field": "height", "type": "integer", "required": true, "min": 1024, "max": 8192 },
    "seed":   { "node": "7", "field": "seed",   "type": "integer", "required": true }
  }
}
```

> 节点 ID 以**实际导出**的 API JSON 为准（子图会被扁平化，可能形如 `23:5`）。

### 10.3 导出前必做

1. **断开 `ResolutionSelector → MiniMaxH3ImageConditioning` 的 width/height 连线**。有连线时 API JSON 里那两位是 `["14", 0]`，清单写 width/height 会被直接忽略——这是最容易踩的坑。
2. 或干脆删除 `ResolutionSelector`，把宽高变成纯 widget 字段。
3. `ComfySwitchNode` 保持 `false`（走原始 prompt，不走 caption 扩写），并从清单里**不暴露**该开关，防止误开。
4. 保存前缀改为 `h3_定妆`，便于收片识别。

## 11. 与旧规范差异与迁移

| 维度 | 旧（qwen-image 口径） | 新（H3 口径） |
| :-- | :-- | :-- |
| 画幅 | 1344×768 / 768×1344（7:4 / 4:7） | **1368×768 / 768×1368**（16:9 / 9:16） |
| 生成分辨率 | 单档 ≈1MP | **4MP 抽卡 / 16MP 定稿** |
| 采样 | euler/normal/20 步/CFG 2.5 | **euler/simple/6 步/CFG 1.0** |
| 质感档 | 双档（标准 / Lightning 4 步预览） | **单档**，无加速档概念 |
| 负面抑制 | 负面词表 | **取消**，全部正向化进 S5 |
| 提示词 | 六层（L1–L6） | **五段（S1–S5）**，段职责重排 |
| 一致性 | seed + 六层锚词 | **seed ＋ R 模式基准图锁定** |
| 定妆背景 | 浅米色纯色墙面（写在 L6） | 同左，但固化进 **S5 标准句**，逐卡强制 |

**迁移原则**：

1. **新图走新规、旧图不回炉**。已入库的 qwen 定妆继续有效；只有新角色、重抽、换装的资产按本文执行。
2. 旧图在 R 模式下可直接当基准参考图使用——它们本身就是「浅米色墙面 + 全正面」的标准形态，迁移成本低。
3. 一个角色**不允许新旧混库**：若某角色重抽，则该角色 8 张整体按新规重出，避免同一角色两种画幅。

## 13. 实测记录（2026-11-14 · 陈默胸像）

**环境**：局域网 RTX 4090 24G · ComfyUI 0.45.3 · `minimax_h3_image_pruned_int8_convrot`（21 GB）+ `qwen3vl_32b_minimax_h3_int8_convrot`（25 GB）。
**样本**：五段式中文 prompt（陈默 · 22 岁男程序员 · 牛仔外套），T 模式，三档分辨率共用 seed `594535360`。
**样张位置**：`D:\Dufs\AI短剧工作流\安妮的夏天\STAGE3_资产\_h3测试\`

| 档位 | 生成尺寸 | 耗时 | 入库后边缘能量 | 判定 |
| :-- | :-- | :-- | :-- | :-- |
| 16MP | 3072×5472 | **33 s** | **5071** | 可用，定稿档 |
| 4MP | 1536×2720 | 10 s | 2229 | 与 1MP 无差异，淘汰 |
| 1MP（旧口径） | 768×1344 | 8 s | 2503 | 不可用 |
| 16MP 全身 | 5472×3072 | **58 s** | — | 可用，构图需加占比约束 |

**五条实测结论**：

1. **换分辨率就是换脸**。三张同 seed、同 prompt，1MP / 4MP / 16MP 得到三张明显不同的脸（发型分缝、眉形、脸长都变）。原因：宽高一变，latent 网格全变，采样轨迹不再对应。→ 原 v1.0 的「4MP 抽卡 + 16MP 同 seed 复跑」**不成立**，已删档。
2. **4MP 不解决问题**。缩到 768×1368 后，4MP 与 1MP 的边缘能量几乎相同（2229 / 2503），16MP 是它们的 2.3 倍。低分辨率不是「略软」，是细节根本没生成。
3. **16MP 成本可以接受**。4090 上 33–58 秒/张，8 张/角色 ≈ 5–8 分钟，不需要为省时间降档。
4. **风格被写实化**。L2 锚词写了「2D动漫质感、二次元插画质感」，但 H3 的先验是摄影/真人，输出接近真人写真，看不到 2D 渲染痕迹。**这是与现有 qwen 定妆最大的不一致**：两套图放同一部剧会像两个世界。→ 需拍板：接受 H3 的写实基调（则全剧视觉风格要重新定），或在 S1 前段强化 2D/插画权重词后重测。
5. **全身 16:9 人物偏小**。人物约只占画高 60%，两侧空墙过多，作为 R2V 服装锚分辨率利用率低。→ S4 需加「人物占画面高度约 70–80%」的占比约束；或在允许范围内改用 3:2（5024×3360）并接受入库 1256×840。
6. **背景仍有地板与投影**。S5 写了「无缝墙面」，全身卡仍出现地平过渡与脚下轻投影。若要求绝对纯净，S5 需加 `no floor line, no cast shadow`；若可接受（仅作参考图），维持现状并在验收里说明。
