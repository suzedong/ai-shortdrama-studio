# H3 Image 定妆生产规范（H3 单轨 · 4MP 版）

> **版本**：v2.0 · 全新方案
> **模型**：MiniMax H3 Image（`image_minimax_h3_image_t2i.json` 子图链路）
> **适用**：STAGE3 角色定妆、场景底图、道具底图
> **状态**：核心机制已真机验证（见 §12）；未验证项见 §11
> **作者**：AI-SDG 协作者 · 2026-11-14

---

## 0. 一句话

**定妆图的唯一验收标准，是它能不能当 H3 视频 R2V 的锚、并且成片里长得一样；画质只为这件事服务，4MP 刚好够。**

三条铁律：

1. **一个角色只有一个脸源。** 全剧所有镜头的 `<Picture 1>` 都指同一张"主脸锚"（默认 `正面平静`）。谁都可以换，这张不能换。
2. **同尺寸 + 同 seed 才可复现。** 换宽高就是换一张脸，跨尺寸复跑拿不到同一个人。
3. **生成 4MP、入库 1/2 缩。** 生成档唯一，入库档唯一，下游尺寸零改动。

---

## 1. 为什么 4MP 就够（像素账）

| 环节 | 分辨率 | 像素 | 说明 |
| :-- | :-- | :-- | :-- |
| 视频成片 | 1344×768 | 1.03 MP | 既有镜头实例，20 步标准档 |
| 定妆入库（横） | 1344×768 | 1.03 MP | 与视频**同尺度**，R2V 拿到的是等像素参考 |
| 定妆入库（竖） | 768×1344 | 1.03 MP | 同上，旋转 90° |
| 定妆生成 | 2688×1536 | 4.13 MP | 4 倍超采样，缩下来才干净 |
| 定妆生成（竖） | 1536×2688 | 4.13 MP | 同上 |

**账算得很直白**：视频模型自己只有 1.03 MP 的输出预算，喂给它的参考图超过 1 MP 也不会变成更多细节。生成端用 4MP 是为了"缩得干净"——实测 4MP 缩到入库尺寸后边缘干净、无 1MP 直出的块状结块（§12 表 1）。再往上（16MP）确实更锐（边缘能量 2.3 倍），但那部分锐度在 1.03 MP 的成片里直接被丢掉，只换来 4 倍耗时和 4 倍显存。**所以 4MP 是"刚好够"，不是"妥协"。**

同时 4.13 MP 卡在 H3 的 4 MP 下限之上，不会掉进低分辨率出不好的区间。

## 2. 尺寸与档位（各只有一档）

### 2.1 生成尺寸

| 形态 | 视角 | 生成尺寸 | 比例 | 像素 |
| :-- | :-- | :-- | :-- | :-- |
| 竖版 | 胸像特写_竖版 / 正面平静 / 正面微笑 / 正面大笑 / 3-4侧 / 纯侧脸 | **1536×2688** | 4:7（0.5714） | 4.13 MP |
| 横版 | 全身正面 / 全身背面 | **2688×1536** | 7:4（1.75） | 4.13 MP |

### 2.2 入库尺寸（与下游、与视频完全对齐）

| 形态 | 入库尺寸 | 缩放关系 |
| :-- | :-- | :-- |
| 竖版 | **768×1344** | 精确 1/2，整数倍 |
| 横版 | **1344×768** | 精确 1/2，整数倍 |

**这两组数字是刻意选的**：比例与既有资产、与视频画幅完全一致（4:7 ↔ 768×1344，7:4 ↔ 1344×768），缩放是整数 1/2，不产生半像素重采样，下游 glob、索引、记录页、R2V 全部零改动。

### 2.3 尺寸纪律

1. **只准用 1536×2688 / 2688×1536**。32 对齐已满足（1536/32=48、2688/32=84），不要再让 ResolutionSelector 改画幅。
2. **不得跨尺寸复跑**。竖版抽出的脸，横版用同 seed 复跑会得到另一个人（§12 表 2）。全身卡如果需要脸完全一致，只能同尺寸派生后裁切，或接受"脸不参与身份判定"（见 §6.2）。
3. **缩放只在 SaveImage 之前做**，入库文件必须是缩好的终态，不留 4MP 中间态混进资产目录。

## 3. 采样参数（唯一档）

| 参数 | 取值 | 说明 |
| :-- | :-- | :-- |
| 采样器 / 调度器 | **euler / simple** | 模板默认，实测可用 |
| 步数 | **6** | 少步模型，加步数只涨时间不涨细节 |
| CFG | **1.0** | 必须为 1.0，见 §3.1 |
| denoise | **1.0** | 全幅重绘，不存在低 denoise 保脸这条路 |
| 帧数 / 批 | 1 | 抽卡靠换 seed，不靠 batch |
| 参考图 | 见 §6.3 | 仅主锚派生时用 |

### 3.1 为什么 CFG 必须是 1.0

工作流里 `negative` 被 `ConditioningZeroOut` 清零，CFG>1 时模型仍会按"负向 = 零张量"计算，结果是**负向不仅无效，还会把画面往过饱和方向推**。所以：

- **CFG 恒为 1.0**，负向提示词在本链路里是死输入，**任何负面词都不写**。
- 洁净度、无文字、无家具这类要求，一律写成**正向陈述**（"背景为纯净浅米色无缝墙面，空景"），不写"不要 XX"。

## 4. 提示词结构（五段式 · 单段中文流）

提交给模型的是一段连续中文，按五段顺序拼，**不写结构标签**（标签会印进 PNG 元数据）：

| 段 | 名称 | 内容 | 是否随视角变 |
| :-- | :-- | :-- | :-- |
| S1 | 风格与光 | 世界观锚 + 视觉风格 + 光线基调 | **全角色全视角逐字不变** |
| S2 | 人物 | 年龄 / 职业 / 气质 / 脸型 / 发型 / 表情倾向 | 同角色不变 |
| S3 | 服装 | 外套 + 内搭 + 下装 + 鞋，按当集服装卡 | 同集不变 |
| S4 | 构图 | 景别 + 朝向 + 视线 + 占比 + 画幅 | **逐视角改写** |
| S5 | 背景洁净 | 底色 + 空景 + 光线均匀 + 无文字水印边框 | 不变 |

### 4.1 S1 必须与视频侧风格句逐字同字（硬规则）

H3 图像和 H3 视频共用一个 32B 文本编码器（`qwen3vl_32b_minimax_h3_int8_convrot`）。S1 里那句风格描述，**必须与 STAGE5 镜头提示词里的"风格："句完全一致，一个字都不许改**：

> 拟真人仿真人动漫，贴近真人神态与微表情、立体感强、保留动漫美感。

这是图文两侧唯一的文本同源点：同一句话编码出的条件向量一致，定妆图与视频才会落在同一个风格邻域。**S1 改一个字，一致性就断在文本层，画面上追不回来。**

### 4.2 S4 构图段的三个硬约束

1. **占比**：全身卡写"人物占画面高度约 75%，头顶留空约 5%，鞋底留空约 5%"。实测不写占比时，横版全身人物只占画高 60%，两侧大量空墙，作参考图利用率低。
2. **朝向**：正面 / 3-4 侧（转约 35°，露一侧耳）/ 纯侧（转约 90°）/ 背面。**只改这一句，其余四段不动**。
3. **画幅词**：竖版写"竖版胸像特写，腰部以上构图"，横版写"全身正面站姿，从头到脚完整，腿部完整可见，全身入镜看到鞋子"。

### 4.3 模板（陈默 · 正面平静 · 竖版，实测可用）

```
千禧年初北方省会城市，拟真人仿真人动漫，贴近真人神态与微表情、立体感强、保留动漫美感，
22岁男程序员，气质木讷真诚，鹅蛋脸、三七分、和善，
穿蓝色牛仔外套，内搭白色翻领衬衫，
竖版胸像特写，腰部以上构图，正面平视镜头，表情平静温和，脸居中占画面主要位置，
背景为纯净浅米色无缝墙面，空景，没有家具，没有道具，没有场景元素，柔和均匀的光线，画面没有文字，没有水印，没有标志，没有边框
```

## 5. 视角清单与身份等级

### 5.1 八个视角（名称固定，不可改）

| # | 视角码 | 画幅 | 身份等级 | 用途 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | **正面平静** | 竖 1536×2688 | **主脸锚（唯一）** | 所有镜头 `<Picture 1>` |
| 2 | 胸像特写_竖版 | 竖 | 派生锚 | 大特写镜头 |
| 3 | 正面微笑 | 竖 | 辅助 | 情绪镜头 |
| 4 | 正面大笑 | 竖 | 辅助 | 情绪镜头 |
| 5 | 3-4侧 | 竖 | **次锚** | `<Picture 1>` 的第二选择（对话/侧身镜头） |
| 6 | 纯侧脸 | 竖 | 辅助 | 侧向构图 |
| 7 | 全身正面 | 横 2688×1536 | **体态锚** | 所有镜头 `<Picture 2>` |
| 8 | 全身背面 | 横 | 辅助 | 背影镜头 |

### 5.2 身份等级的含义

- **主脸锚**：一个角色只有一张，抽卡选定后**全剧不再变**。它是"这个人"的定义。
- **次锚**（3-4侧）：允许存在，但**必须与主脸锚同尺寸、同 seed 派生**，且必须人眼验收"是同一个人"，否则降级为辅助，不得进 `<Picture 1>`。
- **辅助**：只提供表情/角度信息，**不作身份依据**，漂了不算事故。
- **体态锚**（全身正面）：只提供身高比例、体型、服装。**脸不参与身份判定**——视频里脸由 `<Picture 1>` 主导，全身卡的职责是把衣服和身形说清楚。

## 6. 一致性机制（本规范的核心）

### 6.1 三条锁定线

| 线 | 手段 | 断了会怎样 |
| :-- | :-- | :-- |
| **文本线** | S1 风格句与视频侧逐字同字 | 图文风格分家，一个像写真一个像插画 |
| **身份线** | 单一主脸锚 + 同尺寸同 seed | 每个镜头一张新脸，观众认不出是同一个人 |
| **尺度线** | 入库尺寸 = 视频画幅像素 | 参考图与成片细节密度不匹配，R2V 抓不住五官特征 |

### 6.2 跨尺寸的真实结论（重要）

实测（§12 表 2）：**同一 seed 只换宽高，出的是不同的人**；跨尺寸用参考图派生（R 模式）也**锁不住脸**。原因是 H3 Image 每次都是 denoise 1.0 全幅重绘，宽高一变 latent 网格就变，采样轨迹不再对应；参考图只以 reference latent 形式参与，是"靠拢"不是"复制"。

**所以本规范不承诺"八个视角同一张脸"，只承诺"全剧一个脸源"。** 具体落地：

- 竖版六视角之间：同尺寸同 seed，只改 S4 → 一致性最好，可复现。
- 竖版 → 横版全身：必然换脸，**接受**。全身卡不带身份职责（§5.2）。
- 若某镜头必须用横版全身当 `<Picture 1>`：禁止。改走"用竖版 3-4侧 当 Picture 1 + 横版全身当 Picture 2"。

### 6.3 R 模式的正确用法与限制

节点 `MiniMaxH3ImageConditioning` 的 `vae` + `images` 接上后，参考图会作为 reference latents 锚定（不接 vae 则只走文本编码器，锚定更弱）。API 格式里 `images` 必须写成**连接列表**：

```json
"5": {"class_type": "MiniMaxH3ImageConditioning",
      "inputs": {"clip": ["2",0], "prompt": "...", "width": 1536, "height": 2688,
                 "vae": ["3",0], "images": [["10",0]]}}
"10": {"class_type": "LoadImage", "inputs": {"image": "ref_正面平静_768x1344.png"}}
```

- 写成 `"image_0": ["10",0]` 会报 `unexpected keyword argument 'image_0'`；
- 写成 `"images": ["10",0]` 会报 `Boolean value of Tensor ... ambiguous`；
- **只有 `"images": [["10",0]]` 能跑通**（实测，§12）。

**用途**：让派生视角的服装、发型、光位、氛围贴近主锚；**以及把画风拉回参考图**——实测 R 模式下画面明显回落到参考图的插画质感，比同 prompt 的 T 模式更"不写真"。
**限制**：**它不是保脸工具**。实测跨尺寸时脸仍会变成另一个人；同尺寸下与"同 seed T 模式"相比也不更稳。所以 R 模式只用于"氛围与画风靠拢"，身份由 seed + 人眼验收兜。

## 7. 生产 SOP（一次成型，不设小图抽卡）

| 步 | 动作 | 参数 | 产出 |
| :-- | :-- | :-- | :-- |
| 1 | 写五段式提示词：S1 抄视频风格句、S2/S3 抄角色卡 | — | prompt 草稿 |
| 2 | 主脸锚抽卡：4 张，只改 seed | 1536×2688 · 4.13MP | 4 张候选 |
| 3 | 人选 1 张 → 记下 seed → 其余归档 `_backup/` | — | **主脸锚定版** |
| 4 | 竖版其余 5 视角：**同 seed + 只改 S4** | 1536×2688 | 5 张 |
| 5 | 验收：与主脸锚并排看，脸不对就换 seed 重抽该视角，不改主锚 | — | 竖版 6 张通过 |
| 6 | 横版 2 视角（全身正/背）：单独抽卡，**允许换脸** | 2688×1536 | 2 张 |
| 7 | 全部缩到入库尺寸，命名归档 | 1/2 缩 | 8 张入库 |

**不设"小图抽卡、大图复跑"档**。因为跨尺寸必然换脸，省下的时间会变成"复跑后发现不是同一个人"，返工成本远高于 33 秒。

**成本**：单张 4MP 约 10–21 秒（4090），一个角色 8 视角含重抽约 3–6 分钟。

## 8. 与 H3 视频 R2V 的对接规格

### 8.1 参考槽位

| 槽位 | 内容 | 取图 |
| :-- | :-- | :-- |
| `<Picture 1>` | 面部锚 | **主脸锚（正面平静）** 或已验收的次锚（3-4侧） |
| `<Picture 2>` | 体态锚 | 全身正面（衣服、身形、站姿） |
| `<Picture 3>` | 场景/道具参考 | 场景底图 / 道具底图 |
| `<Audio 1>` | 音色参考 | `音色_{角色}.wav` |

### 8.1.1 参考图比例不必与画幅一致（已验证）

`MiniMaxH3ReferenceToVideo` 的 `ref_image_size` 决定参考图怎么进模型（工具提示原文）：

- **`match`（默认）**：*"scales each ref (down only, keeping aspect) to the generation's pixel area"* —— **等比缩放到生成像素面积，只缩不放大，不裁剪不拉伸**。
- **`max`**：*"uses the reference pipeline's 2048px short edge for best identity fidelity"*，代价是参考 token 参与每一步采样，**慢数倍**。

**实测（§12 表 7）**：768×1344 竖版定妆喂 1344×768 横画幅，`match`，成片正常出——无黑边、无裁切、竖构图没有把横画幅带歪，脸部与主锚一致。结论：**横画幅可以直接吃竖版定妆，比例不一致不是问题**，因为参考图不是帧，是全程参与采样的条件。

三档建议：

| 场景 | 参考图 | `ref_image_size` |
| :-- | :-- | :-- |
| 常规镜头（多、要快） | 入库图 768×1344 / 1344×768 | `match` |
| 关键镜头（特写、脸要像） | **4MP 原图** 1536×2688 | `max`（短边 1536 < 2048，不会被缩，保真最高） |
| 长片批量 | 入库图 | `match` |

### 8.1.2 双锚必须都喂（实测教训）

表 7 那一条只喂了 `<Picture 1>`（胸像）+ 场景，**省掉了 `<Picture 2>` 全身正面**，结果成片里陈默穿的是白色圆领 T 恤——定妆卡上明明是蓝色牛仔外套。**服装不会从胸像自动继承**，只会从全身卡来。所以：

- `<Picture 1>` 管脸，`<Picture 2>` 管衣服和身形，**两个都得给**，缺一个就漂。
- 胸像卡的上下边界之外（腰以下、鞋）在视频里全靠 `<Picture 2>`；只给胸像时模型会自由发挥成"白 T + 休闲"。


### 8.2 视频参数（既有，不改）

`1344×768 · 20 步 · 5 秒档`，与定妆入库尺寸同尺度（§1）。

### 8.3 提示词写法

```
<Picture 1> 为{角色}定妆照（正面平静），<Picture 2> 为{角色}定妆照（全身正面），<Picture 3> 为{场景}参考，<Audio 1> 为{角色}音色参考。
{内容层：动作 + 景别 + 运镜 + 神情}
{对白 + 语气}
声音：{声音描述}
风格：拟真人仿真人动漫，贴近真人神态与微表情、立体感强、保留动漫美感。
```

**风格句照抄定妆 S1，一个字不改**（§4.1 的反向约束）。

### 8.4 景别 ↔ 锚点对应

| 景别 | 首选 `<Picture 1>` |
| :-- | :-- |
| 大特写 / 特写 | 胸像特写_竖版 |

## 12. 实测记录（2026-11-14 · 陈默）

**环境**：局域网 RTX 4090 24G · ComfyUI 0.45.3 · `minimax_h3_image_pruned_int8_convrot` + `qwen3vl_32b_minimax_h3_int8_convrot`。
**条件**：五段式中文 prompt，T 模式，除注明外 seed 相同。

### 表 1 · 分辨率与入库锐度（缩到 768×1368 后测边缘能量）

| 生成档 | 生成尺寸 | 耗时 | 入库边缘能量 | 判定 |
| :-- | :-- | :-- | :-- | :-- |
| 16MP | 3072×5472 | 33 s | **5071** | 最锐，但超出视频消费能力 |
| 4MP | 1536×2720 | 10 s | 2229 | **采用**（够用，边缘干净） |
| 1MP | 768×1344 | 8 s | 2503 | 数值不低但块状结块、发丝粘连 |

结论：16MP 的锐是真实的，但成片只有 1.03 MP；4MP 缩到入库尺寸已无可见结块，故选 4MP。

### 表 2 · 跨尺寸是否同脸（同 seed 594535360）

| 样本 | 尺寸 | 结果 |
| :-- | :-- | :-- |
| 胸像 1MP | 768×1344 | 脸 A |
| 胸像 4MP | 1536×2720 | 脸 B（发型分缝、眉形、脸长均不同） |
| 胸像 16MP | 3072×5472 | 脸 C |

结论：**换分辨率就是换脸**。同 seed 不足以保证跨尺寸一致。

### 表 3 · R 模式锁脸能力

| 组 | 参考图 | 目标尺寸 | 结果 |
| :-- | :-- | :-- | :-- |
| A → B | 竖版正面 768×1344 | 横版全身 2688×1536 | **失败**，脸型/眉形/发型全变，换了个人 |
| A → C | 竖版正面 768×1344 | 竖版同尺寸 1536×2688 | 氛围与服装靠拢，脸仍偏柔、不等同 |

结论：R 模式是"氛围锚"不是"身份锚"。本规范因此把身份锁在"单一主脸锚 + 同尺寸同 seed"，不把 R 模式写进身份承诺。

### 表 4 · 节点接法（踩坑记录）

| 写法 | 报错 |
| :-- | :-- |
| `"image_0": ["10",0]` | `execute() got an unexpected keyword argument 'image_0'` |
| `"images": ["10",0]` | `Boolean value of Tensor with more than one value is ambiguous` |
| `"images": [["10",0]]` | **跑通** |

### 表 5 · 4MP 新方案样张

| 文件 | 尺寸 | 用途 |
| :-- | :-- | :-- |
| `_h3测试\定妆_陈默_正面平静_h3v2_00001_.png` | 768×1344（源 1536×2688） | **主脸锚**样张 |
| `_h3测试\定妆_陈默_3-4侧_h3v2_00001_.png` | 768×1344（源 1536×2688） | 次锚样张（同 seed 只改 S4） |
| `_h3测试\定妆_陈默_全身正面_h3v2_00001_.png` | 1344×768（源 2688×1536） | 体态锚样张（R 模式，含换脸） |

### 表 6 · 同尺寸同 seed 只改构图（核心规则验证）

| 项 | 设定 |
| :-- | :-- |
| 尺寸 / seed | 1536×2688 · seed 2026111410（与正面锚完全一致） |
| 改动 | **仅** S4 段：`正面平视镜头，表情平静温和` → `3-4侧脸，面部朝画面左侧转约35度，露出右耳，视线略偏离镜头` |
| 结果 | 脸部成立：三七分发量、眉形、眼型、耳廓与正面锚一致，视角成功转到 3-4 侧 |

结论：**同尺寸 + 同 seed + 只改 S4，是可复现的保脸手段**。这是本规范唯一写进身份承诺的机制。反过来说，只要动了尺寸或 seed，就必须重新认定身份。

### 表 7 · 竖版定妆喂横画幅 R2V（端到端）

| 项 | 设定 |
| :-- | :-- |
| 模型 | `minimax_h3_ref2va_pruned_int8_convrot` + `qwen3vl_32b_minimax_h3_nvfp4_awq` |
| 输出 | 1344×768 · 124 帧（5.17 s）· 20 步 · res_multistep / simple |
| 参考 | `<Picture 1>` = 定妆_陈默_正面平静_h3v2**（768×1344 竖版）**，`<Picture 2>` = 宿舍场景，`ref_image_size = match` |
| 结果 | 正常出片：无黑边、无裁切、横画幅构图未被竖图带偏；末帧脸部（三七分发、眉形、脸长）与主锚一致 |
| 失败点 | **服装漂了**：定妆卡是蓝色牛仔外套，成片穿白色圆领 T 恤——因为**这次只喂了 Picture 1，省掉了全身正面**。服装不从胸像继承 |

结论：① 比例不一致不构成障碍；② 双锚缺一必漂，`<Picture 2>` 不是可选项。
