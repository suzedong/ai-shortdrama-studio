## 一、现行结论与边界

### 1.1 一句话方案

**图像全部由 MiniMax H3 Image 承担，视频全部由 MiniMax H3 承担，配乐继续由独立的 MiniMax Music3 承担。Qwen-Image 及其专用编辑、ControlNet、分层、多角度、透明底能力全部停用，其 27 份专用参考 JSON 已从本参考库删除；P-H3、FastH3/FastVideo、Pika H3 的 8 份参考 JSON 亦已删除。上述文件均不作主用、备选、成本档、组合链或故障回退。**

音乐不是“H3 音乐”；Music3 是独立模型与独立音频工作流。本文也不把 H3 编辑、视频或 Music3 的参考模板写成已经接入平台生产的能力。

### 1.2 三种状态

| 状态 | 含义 | 当前范围 |
| --- | --- | --- |
| **生产已启用** | 已由生产 manifest 显式注册，经受控 loader 与主进程引擎执行 | 仅 MiniMax H3 Image 文生图兼容图 |
| **参考保留 / 生产未接入** | 原始模板继续用于接法、权重与参数参考；投入生产前必须另有 Feature、实例核验与真机验收 | H3 Image 编辑、H3 T2V/I2V/R2V、多帧参考、视频控制、Music3 |
| **删除禁用** | 已删除参考文件不得进入任何现行方案与生产回退；Qwen 生产 graph 已由 C3 删除，历史资产和生成元数据仍只读保留 | 全部 Qwen-Image 及其专用能力链；P-H3、FastH3/FastVideo、Pika H3 参考件 |

### 1.3 三类目录与格式

| 位置 | 格式与用途 | 能否直接生产执行 |
| --- | --- | --- |
| `resources/_ref_官方模板/H3/UI/`、`resources/_ref_官方模板/Music3/UI/` | 10 份 **UI Format**，顶层含 `nodes` / `links` / `definitions.subgraphs`；H3 按 6 个用途域细分，Music3 单独归档 | **不能**直接提交 `/prompt` |

生产 loader 只读 manifest，不扫描本参考库或工作流目录；唯一 Qwen 生产归档及空 `_archive/` 已由 C3 删除。UI JSON 不得改名冒充 API graph；API 参考件也不得绕过 manifest 手工提交来冒充平台验收。

## 二、八阶段选型

八阶段是业务产物与验收边界，7 类工作流用途域是可复用媒体能力，二者是多对多关系。阶段定义以《短剧Agent平台设计》为准，不合并、不裁剪。

| 阶段 | 现行主用 | 按需参考 | 状态与边界 |
| --- | --- | --- | --- |
| 0 立项 | H3 Image 文生图 | — | 风格样片可辅助拍板；生产只走已注册 H3 Image。 |
| 1 故事 | — | — | 大纲、人物小传由文本链完成。 |
| 2 剧本分场 | — | — | 分场与资产需求由文本链和系统完成。 |
| 3 资产 | H3 Image 文生图 | H3 Image 编辑 | 文生图已接入；编辑仅参考。多角度、拆层、透明底不再路由到 Qwen。 |
| 4 分镜 | H3 Image 文生图 | H3 Image 编辑 | 文生图探索分镜；需要参考图修改时可评估 H3 编辑，但未接入前不得提交生产。 |
| 5 镜头 | — | H3 I2V / T2V / R2V / 多帧参考 / 视频控制 | 全部是参考保留、生产未接入；不得因文件存在而宣称镜头生产已跑通。 |
| 6 后期 | — | Music3；H3 Image 编辑 | 配乐与图像编辑均未接入；剪辑、字幕、合流、混音由后期系统负责。 |
| 7 发布 | H3 Image 文生图 | H3 Image 编辑 | 系统负责成片与渠道交付；封面仅复用现行图像通道。 |

### 2.1 决策树

```text
① 需要的是图像、视频还是配乐？
│
├─ 图像 ──→ 有已批准参考图、必须照图修改吗？
│          ├─ 是 ─→ H3 Image 编辑（参考保留 / 生产未接入）
│          └─ 否 ─→ H3 Image 文生图（生产已启用）
│
├─ 视频 ──→ 有批准首帧 / 末帧吗？
│          ├─ 有 ─→ H3 I2V；需要接下一段时用 I2V continuation
│          └─ 无 ─→ 有独立人物 / 物体 / 音频参考吗？
│                     ├─ 有 ─→ H3 R2V；按秒锚定多参考时用多帧参考
│                     └─ 无 ─→ 必须由真人动作驱动吗？
│                                ├─ 是 ─→ H3 + Fun-ControlNet-Union
│                                └─ 否 ─→ H3 T2V
│          以上视频路由全部为参考保留 / 生产未接入。
│
└─ 配乐 ─→ MiniMax Music3（参考保留 / 生产未接入）
```

**不再进入决策树的能力**：Qwen ControlNet、Qwen Layered、Qwen 多角度、Qwen 生成式抠图、Relight、光迁移、转写实和 Qwen 各代专用编辑。命中这些需求时记录“当前 H3 方案未覆盖”，由人工/系统处理或另行立项，不自动回退旧模型。

### 2.2 推荐基准流程 v1.0

> 本版是 H3 统一通道后的起始方案，不是“全部已生产验证”。只有 A/B 的 H3 Image 文生图进入本次生产迁移，其余步骤是后续制作参考路由。

```text
0–2 文本创作、资产清单、分场与镜头需求
  ↓
A 风格锚点：H3 Image 文生图，锁定画幅、材质、光线与色彩锚词
  ↓
B 资产母版：角色 / 场景 / 关键道具统一走 H3 Image 文生图
  ↓
C 首帧：无参考修改走 H3 Image 文生图；确有参考修改需求才评估 H3 Image 编辑
  ↓
D 首帧批准（身份 / 构图 / 场景 / 光线）
  ↓
E 镜头参考路由：优先 H3 I2V；无首帧用 T2V；独立多主体参考用 R2V
  ↓                         ├─ 超过单段时长 → I2V continuation
                            ├─ 按秒锚定多参考 → 多帧参考
                            └─ 真人动作控制 → H3 视频控制
F 系统粗剪确认时长与情绪 → Music3 配乐 → 配音 / 字幕 / 混音 / 合流
  ↓
G 系统导出与发布；封面复用 H3 Image
```

| 顺序 | 默认动作 | 工作流 | 当前生产状态 |
| --- | --- | --- | --- |
| A | 用同一中文风格 prompt 出样片，选定后保留 prompt、seed、画幅与 MP | `H3/UI/01_文生图/image_minimax_h3_image_t2i.json` | **生产已启用**，使用生产兼容图而非直接执行 UI 件 |
| B | 一名主角先出一张正式母版，再扩其他角色；场景与关键道具同链 | 同上 | **生产已启用** |
| C | 无参考修改时继续文生图；必须照批准图修改时才进入编辑评估 | `H3/UI/02_图像编辑/image_minimax_h3_image_edit.json` | 参考保留 / 生产未接入 |
| D | 人工验收首帧；失败先修 prompt / 参考，不换 Qwen | 对应 H3 Image 路由 | 按实际路由 |
| E | 有首帧优先 I2V；无首帧、独立参考或动作控制时按决策树选择 | `H3/UI/03_文生视频` / `04_图生视频` / `05_参考生视频` / `06_视频控制` | 参考保留 / 生产未接入 |
| F | 粗剪后按实际时长与情绪生成配乐 | `Music3/UI/audio_minimax_music_3.json` | 参考保留 / 生产未接入 |
| G | 封面与宣传图复用 H3 Image；精准排版、裁切与封装由系统完成 | H3 Image 文生图 / 编辑 | 仅文生图已接入 |

### 2.3 质量与返修原则

- 图像草案与正式件都使用 H3 Image；通过 prompt、seed、画幅和 MP 管理迭代，不再设置 Qwen Wuli、Lightning 或 Turbo 成本档。
- H3 Image 生产采样固定官方参考的 6 步 / CFG 1；本次不新增采样参数面板。
- 视频预览与定稿应在同一路由内比较，具体档位待对应视频 Feature 冻结，不能套用旧 Qwen 或未验收经验。
- 人设漂移先回批准 prompt / 参考与首帧；构图失败先修首帧；接片跳变回最近合格末帧。任何失败都不得触发 Qwen 回退。
- 需要透明底、分层、多角度或严格控制网时，标记为未覆盖需求并走人工/系统处理或新 Feature，不重新引入旧模板或启用旧模型。

## 五、H3 Image 生产兼容图

### 5.1 注册与输入

| 项 | 生产契约 |
| --- | --- |
| `workflowId` | `minimax-h3-image-t2i` |
| `kind / model` | `image / MiniMax-H3` |
| 执行文件 | `resources/comfyui/workflows/minimax-h3-image-t2i.json` |
| 必填输入 | `prompt` |
| 可选输入 | `seed`、`aspectRatio`、`megapixels` |
| 默认 | seed 0、16:9、4 MP |
| 固定采样 | `KSampler`、6 steps、CFG 1、euler、simple、denoise 1 |
| 画幅 | 1:1、2:3、3:2、3:4、4:3、9:16、16:9、21:9 |
| MP 范围 | 0.1–16，`multiple=32` |

旧 `qwen-image-2512-text` 与旧字段 `width / height / negativePrompt / lightning4Steps` 不再接受；不设置旧 ID 到 H3 的别名，不自动换算旧尺寸，不把负提示词错接到 `ConditioningZeroOut`。

### 5.2 固定权重与核心链

```text
UNETLoader  minimax_h3_image_pruned_int8_convrot.safetensors
CLIPLoader  qwen3vl_32b_minimax_h3_int8_convrot.safetensors / type=minimax
VAELoader   minimax_h3_image_vae_fp16.safetensors
                    ↓
ResolutionSelector → MiniMaxH3ImageConditioning → KSampler → VAEDecode → SaveImage
                                      └→ ConditioningZeroOut → KSampler.negative
```

`qwen3vl_32b_minimax_h3_int8_convrot.safetensors` 是 H3 官方工作流指定的文本编码器，不是 Qwen-Image 生成权重，不构成旧通道回退。

### 5.3 与官方 API 参考件的差异

- 保留 H3 Image 核心加载、条件、采样、解码和保存链，以及官方 6 步 / CFG 1。
- 用户 prompt 直接进入 `MiniMaxH3ImageConditioning`，移除自动提示词扩写支路，避免依赖当前实例未注册的 LLM/JSON 节点和额外文本服务。
- 生产只接受 manifest 声明的四项输入；其余参数固定在 graph 内。
- 不使用带 Comfy Cloud 认证 / API Key 输入的 `MinimaxH3ImageNode`，不使用 H3 视频 UNet/VAE，不混入 Qwen-Image 权重或 LoRA。

## 七、删除禁用能力的处理口径

| 原需求 | 原 Qwen 专用能力 | 现行处理 |
| --- | --- | --- |
| 线稿 / 深度 / 姿态严格锁图 | 图像 ControlNet / Inpainting / Union | 参考件已删除、能力禁用；先用 H3 prompt / 参考迭代，仍不满足则记录未覆盖，不回退 |
| 独立编辑前景、背景、道具 | 图像分层与点名抽层 | 参考件已删除、能力禁用；由人工/系统图层工具处理或另立新 Feature |
| 角色 / 场景多角度批量 | 角色与场景多角度专用链 | 参考件已删除、能力禁用；可用 H3 分别生成并人工选版，但不冒称身份等价或批量角度已验证 |
| alpha PNG / 透明底 | 生成式背景移除 | 参考件已删除、能力禁用；由确定性的系统/人工抠图工具处理，不调用 Qwen |
